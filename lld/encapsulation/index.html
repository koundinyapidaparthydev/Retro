The problem they give you

They will not say “Encapsulation.” They describe this:

Given: ParkingSpot has public occupied and vehicle. Callers set them separately and the two fields disagree.

Find: Hide the fields. One verb must keep occupied iff a vehicle is present.

Tiny example: occupy(car) succeeds; setOccupied(true) does not exist. A later thread-safety ask locks that one method.

Name of the tool

Hide how an object stores and changes data; expose a small, intention-revealing API so invariants stay true no matter who calls you.

Why this tool

Most LLD bugs are not missing classes — they are leaked fields that any caller can corrupt.

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • This spot can be occupied and empty. Fix the API.
  • Now a handicap-only rule — who enforces it?
  • Make occupy safe when two cars arrive at once.

You say this first

I wouldn't name the pattern first. I'd say the problem encapsulation solves, then the three types. Hide how an object stores and changes data; expose a small, intention-revealing API so invariants stay true no matter who calls you.

Shape: List the invariants the object must always satisfy (e.g. capacity ≥ occupied, status matches assigned vehicle).. Don't: Pure data transfer objects that cross a process or network boundary — those are schemas, not domain objects. Say the invariant out loud, then show the method that protects it. Interviewers listen for that pairing.

More notes if you want them

Most LLD bugs are not missing classes — they are leaked fields that any caller can corrupt. Encapsulation is how you keep a ParkingSpot from going occupied-and-empty at once, and how you keep interview designs from collapsing when the interviewer adds a rule.

Use when: Any type that has rules: money, inventory, bookings, machine state, permissions.

Skip when: Pure data transfer objects that cross a process or network boundary — those are schemas, not domain objects.

Trap: Public fields or getters that return mutable lists — callers mutate around your methods.
