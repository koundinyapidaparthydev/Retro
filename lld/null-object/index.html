LLD/Behavioral Patterns

Null Object

NEXT

Definition

Provide a do-nothing implementer of an interface so callers do not sprinkle null checks through the design.

Why it exists

Optional loggers, missing discounts, empty customers, and absent strategies produce `if (x != null)` in six places.

Approach

  1. Identify an optional collaborator with a clear neutral behavior.
  2. Implement the interface as no-ops / zeros / empty.
  3. Always inject either the real or the null object — never null.

You say this first

I wouldn't name the pattern first. I'd say the problem null object solves, then the three types. Provide a do-nothing implementer of an interface so callers do not sprinkle null checks through the design.

Shape: Identify an optional collaborator with a clear neutral behavior.. Don't: Required dependencies — crash at wiring time. If they say 'logging is optional', inject NullLogger. Cleaner than if (logger != null).

More notes if you want them

Optional loggers, missing discounts, empty customers, and absent strategies produce `if (x != null)` in six places. A NullLogger or NoDiscount that implements the same interface keeps the path linear.

Use when: Optional logging, metrics, discounts, notifications, default strategies.

Skip when: Required dependencies — crash at wiring time.

Trap: Null object that throws 'not implemented'.
