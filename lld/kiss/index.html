KISS — Keep It Simple

CORE

Definition

Choose the simplest design that meets the stated requirements and a realistic next variant — not a framework for an imaginary product.

Why it exists

Candidates lose LLD rounds by drawing Kafka, a plugin bus, and six design patterns for a vending machine.

Approach

  1. Restate the requirements in four bullets.
  2. Prefer a list and a loop over a pattern until a second family of objects appears.
  3. Prefer a function or a strategy over a framework.

KISS — Keep It Simple

Restate the requirements in four bullets. Design only those plus one named extension.

They ask it like this

  • "When would you use KISS — Keep It Simple?"
  • "Our class is growing a switch — what do you do?"
  • "Draw it. Then tell me when you would not."

You say this first

I wouldn't name the pattern first. I'd say the problem kiss — keep it simple solves, then the three types. Choose the simplest design that meets the stated requirements and a realistic next variant — not a framework for an imaginary product.

Shape: Restate the requirements in four bullets. Design only those plus one named extension.. Don't: Do not use KISS as an excuse to skip invariants, validation, or a needed interface. Say 'I'll keep this in-memory and extract a repository if we persist.' That is KISS with a growth path.

Candidates lose LLD rounds by drawing Kafka, a plugin bus, and six design patterns for a vending machine. Simple, correct classes beat an architecture astronaut diagram you cannot code in 35 minutes.

Use when: The first five minutes of every LLD interview.

Skip when: Do not use KISS as an excuse to skip invariants, validation, or a needed interface.

Trap: Pattern shopping: Adapter + Facade + Proxy on one gateway.
