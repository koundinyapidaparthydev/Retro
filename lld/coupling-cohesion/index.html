Coupling and cohesion

CORE

Definition

Keep each class about one idea (high cohesion) and keep classes from knowing each other's guts (low coupling).

Why it exists

Every 'this design is messy' interview note is a coupling or cohesion complaint.

Approach

  1. Write a one-sentence responsibility for each class.
  2. List outgoing dependencies.
  3. Replace fat parameter objects with the values the method actually uses, or with a dedicated command type.

You say this first

I wouldn't name the pattern first. I'd say the problem coupling and cohesion solves, then the three types. Keep each class about one idea (high cohesion) and keep classes from knowing each other's guts (low coupling).

Shape: Write a one-sentence responsibility for each class. If you need 'and', split.. Don't: Do not split a 30-line class just to improve a cohesion score — wait for a second reason. If they ask 'why another class?', answer with cohesion: 'Order should not know GST slabs.'

More notes if you want them

Every 'this design is messy' interview note is a coupling or cohesion complaint. God classes are low cohesion. A use case that new-s a SQL repository, formats HTML, and charges Stripe is high coupling. You cannot extend either.

Use when: Reviewing any whiteboard design before you code.

Skip when: Do not split a 30-line class just to improve a cohesion score — wait for a second reason.

Trap: Utils and Helpers that import the world — coupling hubs.
