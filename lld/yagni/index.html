YAGNI — You Aren't Gonna Need It

CORE

The problem they give you

They will not say “YAGNI — You Aren't Gonna Need It.” They describe this:

Given: Tic-tac-toe has an SPI, a connection pool, and four unused payment rails. The board still allows X to play twice.

Find: Build the starred requirements. A seam for the likely follow-up; not a framework for an imaginary product.

Tiny example: One concrete FeePolicy and a spoken 'I would extract here.' Auth, disk, multi-region stay on a not-today list.

Name of the tool

Do not build the distributed cache, the plugin SPI, or the fourth payment rail until the problem asks for it.

Why this tool

YAGNI protects interview time.

Approach

  1. Star the requirements that are in scope.
  2. Implement the starred items with the fewest types that keep invariants.
  3. Leave a named hook only for the follow-up you actually expect (second payment, second scheduler).

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • List what you will not build in the first two minutes.
  • They add a second scheduler — now extract, not before.
  • Connection pool for a library catalog they never asked for.

You say this first

I wouldn't name the pattern first. I'd say the problem yagni — you aren't gonna need it solves, then the three types. Do not build the distributed cache, the plugin SPI, or the fourth payment rail until the problem asks for it.
