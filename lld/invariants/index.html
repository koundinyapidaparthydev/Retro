Invariants

CORE

The problem they give you

They will not say “Invariants.” They describe this:

Given: You drew tables and setters. A spot is occupied with no vehicle. Order.total disagrees with lines after removeItem.

Find: Rules that stay true after every constructor and mutator. Name the owner and the failure.

Tiny example: occupiedCount == occupied spots. DateRange.start ≤ end. Write two sentences on the board before methods.

Name of the tool

An invariant is a rule that must be true for every instance, every moment after construction — the heart of encapsulation.

Why this tool

If you cannot name the invariants, you are drawing a database, not a design.

Approach

  1. Write invariants in one-line English on the class or aggregate.
  2. Enforce them in constructors and every mutator.
  3. Choose the owner: the smallest type that contains all mentioned fields.

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • A spot is never occupied without a vehicle. Which method?
  • They add a rule — invariant first, then a method.
  • Which invariant does the lot lock protect?

You say this first

I wouldn't name the pattern first. I'd say the problem invariants solves, then the three types. An invariant is a rule that must be true for every instance, every moment after construction — the heart of encapsulation.

Shape: Write invariants in one-line English on the class or aggregate.. Don't: Do not encode UI copy or transient display rules as invariants. Write two invariants on the board before methods. It looks like you know what 'design' means.

More notes if you want them

If you cannot name the invariants, you are drawing a database, not a design. Interviewers listen for 'a spot is never occupied without a vehicle' and then look for the method that protects it.

Use when: Every entity and value you create.

Skip when: Do not encode UI copy or transient display rules as invariants.

Trap: Invariants only in comments.
