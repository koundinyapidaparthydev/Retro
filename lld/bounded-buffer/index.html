Bounded buffer

CORE

The problem they give you

They will not say “Bounded buffer.” They describe this:

Given: Implement a fixed-size buffer. Producers and consumers are threads. They will watch for if (full) wait and a single condition.

Find: Monitor: array, count, mutex, notFull, notEmpty. Signal the opposite side. Capacity-1 test.

Tiny example: put/take plus close() that unblocks waiters. notify vs notifyAll — defend it. Lock-free only if they push.

Approach

  2. while (predicate) wait.
  3. Signal the opposite condition after mutate.

Seam for the variant: Test with many threads and capacity 1 (tightest race).. notify vs notifyAll — with two conditions, notify is enough if one waiter kind per condition; notifyAll is safer if mixed.

More notes if you want them

If they say 'implement a bounded buffer', they want the monitor pattern: mutex, two conditions, while-loops. It is the exam version of producer-consumer-queue.

Use when: Teaching monitors, implementing a queue without using the library.

Skip when: Production Java — use ArrayBlockingQueue unless the point is the exercise.
