LLD/Principles

DRY — Don't Repeat Yourself

CORE

Definition

Every piece of knowledge should have a single representation. Duplicate code is only a smell when it is the same knowledge copied.

Why it exists

Interview designs rot when the same fee rule lives in park(), unpark(), and report().

Approach

  1. When you paste a rule, stop and name the knowledge.
  2. Put it in a type (Money, FeeSchedule, LoanPolicy) or a single function.
  3. Call that type from every use case that needs the rule.

More notes if you want them

Interview designs rot when the same fee rule lives in park(), unpark(), and report(). DRY is how a variant updates one place. Blind copy-extraction, though, couples things that only looked alike.

Use when: Business numbers, state machines, validation, and parsers that appear twice.

Skip when: Accidental similarity — two UIs that both have a submit button.

Trap: Utils.Common.doStuff used by unrelated features.
