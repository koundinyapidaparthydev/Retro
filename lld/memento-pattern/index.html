The problem they give you

They will not say “Memento.” They describe this:

Given: Undo pokes editor.privateChars from the history stack. Snapshots alias the live buffer. History is unbounded.

Find: Originator exports an opaque snapshot. Caretaker stores tokens it cannot read. Restore rebuilds invariants.

Tiny example: createMemento / restore. Caretaker is two stacks. Cap history. Store a copy, not a reference.

Name of the tool

Capture an object's internal state in an opaque snapshot so you can restore it later without breaking encapsulation.

Why this tool

Undo that pokes private fields from the outside is not undo — it is a leak.

Approach

  1. Add originator.createMemento() and restore(memento).
  2. Store only what you need to rebuild invariants.
  3. Caretaker pushes/pops mementos; it does not inspect them.

More notes if you want them

Undo that pokes private fields from the outside is not undo — it is a leak. Memento lets the originator export a snapshot and import it, while caretakers (history stacks) only store the token.

Use when: Editors, games (checkpoints), wizards, interactive machines, transactional in-memory rollback.

Skip when: You can invert with a simple command (add 5 / subtract 5).

Trap: Memento with public fields the UI edits.
