Class diagrams

CORE

The problem they give you

They will not say “Class diagrams.” They describe this:

Given: The board is 30 Manager boxes, no methods, no multiplicity. Controllers occupy Spot. Every DTO is drawn.

Find: A dozen implementable types: verbs with types, ownership, and 1 / 0..1 / *.

Tiny example: Lot → Floor → Spot; park(Vehicle): Ticket. FeePolicy as an interface with space for a second box.

Name of the tool

A class diagram is the map of types, fields, methods, and relationships you will actually code — not a poster of every noun in the problem.

Why this tool

Interviewers read your class diagram to judge whether you understand ownership, multiplicity, and APIs.

Approach

  1. List candidate types from nouns, then drop the ones that are just fields or synonyms.
  2. For each keeper, write 2–5 methods that are verbs, not setX.
  3. Draw has-a / is-a / uses-a with multiplicity.
