Aggregates (DDD-lite)

ADV

Definition

An aggregate is a cluster of entities with one root. Outsiders change the cluster only through the root so invariants that span parts stay true.

Why it exists

Without aggregates, every class is public and every service pokes LineItems and Spots directly.

Approach

  1. List invariants that mention two objects.
  2. Place those objects under one root, or accept a cross-aggregate workflow with explicit steps.
  3. Hide inner constructors.

You say this first

I wouldn't name the pattern first. I'd say the problem aggregates (ddd-lite) solves, then the three types. An aggregate is a cluster of entities with one root. Outsiders change the cluster only through the root so invariants that span parts stay true.

Shape: List invariants that mention two objects.. Don't: A single entity with no children — it is already a root. Say 'ParkingLot is the aggregate root; spots are internal.' Then do not let the controller call spot.occupy.

More notes if you want them

Without aggregates, every class is public and every service pokes LineItems and Spots directly. That is how you oversell a room or double-book a seat. The root is the transaction and consistency boundary in an LLD.

Use when: Orders, lots, boards, carts, reservations — any cluster with a count or total.

Skip when: A single entity with no children — it is already a root.

Trap: Repositories for every inner entity — outsiders will mutate them.
