The problem they give you

They will not say “Mediator.” They describe this:

Given: Every widget calls every other widget. Landing planes hold Runway references. Adding a colleague edits eight classes.

Find: Colleagues talk only to a hub that routes. Domain rules stay on the colleagues.

Tiny example: FormMediator enables OK when checkbox and field agree. ChatRoom routes between Users. Tower assigns runways.

Name of the tool

Route communication through a hub so colleagues do not each know every other colleague — air traffic control for objects.

Why this tool

Chat rooms, dialog boxes, and game boards become spaghetti when every widget calls every other.

Approach

  1. List the pairwise calls you want to delete.
  2. Introduce a mediator interface those colleagues call.
  3. Implement routing in one concrete mediator.

More notes if you want them

Chat rooms, dialog boxes, and game boards become spaghetti when every widget calls every other. A mediator restores SRP: widgets emit events, the mediator decides who to tell.

Use when: UI forms with interdependent fields, chat rooms, air-traffic / tower, game piece interactions that would otherwise be N².

Skip when: Two objects that naturally talk — a mediator is ceremony.

Trap: Mediator that owns all state of all colleagues.
