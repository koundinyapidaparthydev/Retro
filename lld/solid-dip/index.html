LLD/Principles

SOLID — Dependency Inversion Principle

CORE

Definition

High-level policy should depend on abstractions; details (SQL, HTTP, SMTP) should implement those abstractions and be injected.

Why it exists

If BookingService constructs a MySqlBookingDao, you cannot test booking rules without a database and you cannot swap storage.

Approach

  1. Find an import from domain/application into a framework or vendor package.
  2. Define a port in the inner layer: an interface named for the capability.
  3. Implement the port in the outer layer.

If BookingService constructs a MySqlBookingDao, you cannot test booking rules without a database and you cannot swap storage. DIP is what makes hexagonal/clean architecture more than a slide.

Use when: Persistence, payments, notifications, clocks, feature flags, HTTP clients.

Skip when: Stable in-process helpers with no IO — an interface per class is noise.

Trap: Interface sitting in the same file as the SQL class — the domain still depends on SQL if it imports that package.
