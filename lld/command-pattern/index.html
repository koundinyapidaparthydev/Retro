The problem they give you

They will not say “Command.” They describe this:

Given: The editor undoes with boolean flags. Job 'send report' is a string in a switch. Remote buttons call Light.on() directly and cannot macro.

Find: The request is an object: receiver plus args, execute, optional undo. Invoker stores history.

Tiny example: InsertCommand / DeleteCommand on a buffer. Queue the same object for retries. Party-mode is a composite command.

Name of the tool

Turn a request into an object so you can queue it, log it, undo it, or send it to someone else later.

Why this tool

Text editors, remote controls, job queues, and macros are Command.

Approach

  1. Define Command with execute() and, if needed, undo().
  2. Each concrete command holds a receiver + parameters.
  3. Invoker stores history (stack) for undo/redo.

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Text editor undo. What does the command remember?
  • Macro 'party mode' — one execute, one undo.
  • Queued charges without ids — what double-fires?

You say this first

I wouldn't name the pattern first. I'd say the problem command solves, then the three types. Turn a request into an object so you can queue it, log it, undo it, or send it to someone else later.

Shape: Define Command with execute() and, if needed, undo().. Don't: A direct method call with no queue, undo, or logging need. Text editor and remote control are the textbook prompts. Draw Command, Invoker, Receiver.

More notes if you want them

Text editors, remote controls, job queues, and macros are Command. If they ask for undo, you almost always want commands (or events) that can invert, not a pile of boolean flags.

Use when: Undo/redo, macros, wizard steps, job queues, GUI buttons, transactional scripts.

Skip when: A direct method call with no queue, undo, or logging need.

Trap: Commands that contain all the business logic instead of telling the receiver.
