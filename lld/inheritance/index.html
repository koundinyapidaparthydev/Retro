Inheritance

CORE

The problem they give you

They will not say “Inheritance.” They describe this:

Given: Someone drew Penguin extends Bird with fly() that throws. Payroll has Manager extends Employee just to reuse name.

Find: Which relationships are really is-a? Where does a collaborator belong instead?

Tiny example: FlyingBehavior on birds that fly. Manager has a Role, not a parent class.

Name of the tool

Reuse and specialize a type when the child truly is a kind of the parent — not when you just want to share a helper method.

Why this tool

Inheritance is the first tool juniors reach for and the first one interviewers punish.

Approach

  1. Write the parent contract first: methods and their guarantees, not the shared fields.
  2. Ask whether every imagined subtype can honor those guarantees.
  3. Put only shared, stable algorithm steps in the parent.

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Is ElectricCar a Car? What must Car still guarantee?
  • They push Square extends Rectangle. What breaks?
  • Rewrite the bird tree so fly is not on the base type.

You say this first

I wouldn't name the pattern first. I'd say the problem inheritance solves, then the three types. Reuse and specialize a type when the child truly is a kind of the parent — not when you just want to share a helper method.

Shape: Write the parent contract first: methods and their guarantees, not the shared fields.. Don't: You only want to reuse a utility — extract a helper or compose a collaborator. Default to composition in the interview. Use inheritance only when you can defend the is-a sentence.

More notes if you want them

Inheritance is the first tool juniors reach for and the first one interviewers punish. Used for true is-a taxonomies it is clean; used for reuse it produces fragile base classes and LSP violations.

Use when: A genuine is-a taxonomy with a stable contract: Exception types, AST nodes with accept(), UI widgets in a framework you control.

Skip when: You only want to reuse a utility — extract a helper or compose a collaborator.

Trap: Inheriting just to get a logger or a database handle.
