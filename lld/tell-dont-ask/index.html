Tell, don't ask

NEXT

Definition

Command objects to do work instead of pulling their data out and deciding for them.

Why it exists

Ask-style code is how invariants leak: `if (spot.isFree()) spot.setVehicle(v)`.

Approach

  1. Find if/get/set triplets.
  2. Name the method as a domain verb.
  3. Return a result or throw; do not require the caller to re-check the same invariant.

You say this first

I wouldn't name the pattern first. I'd say the problem tell, don't ask solves, then the three types. Command objects to do work instead of pulling their data out and deciding for them.

Shape: Find if/get/set triplets. Fold them into a method on the data owner.. Don't: Reporting, DTOs, and views — those ask. Replace setStatus with domain verbs on the whiteboard: confirm, cancel, expire.

More notes if you want them

Ask-style code is how invariants leak: `if (spot.isFree()) spot.setVehicle(v)`. The spot did not get a chance to refuse. Tell-style `spot.park(v)` keeps the rule inside the object.

Use when: Any mutation that has a rule.

Skip when: Reporting, DTOs, and views — those ask.

Trap: Public setters 'and also' a park() method. Callers will use the setters.
