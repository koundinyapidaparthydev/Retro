Composite

CORE

Definition

Treat a single object and a tree of objects uniformly: folders, UI widgets, org charts, and menu items all answer the same operation.

Why it exists

File systems, UI trees, and company hierarchies are composite problems.

Approach

  1. Define Component with the shared operations.
  2. Implement Leaf with no children.
  3. Implement Composite with a list of Component and recursive methods.
Time O(n) to walk a tree of n nodes for a full-tree operationSpace O(h) recursion depth, or O(n) if you queue a traversal

You say this first

I wouldn't name the pattern first. I'd say the problem composite solves, then the three types. Treat a single object and a tree of objects uniformly: folders, UI widgets, org charts, and menu items all answer the same operation.

Shape: Define Component with the shared operations.. Don't: A flat list — Composite is overhead. For in-memory file system or org chart, Composite is the expected answer. Draw Leaf/Composite/Component.

More notes if you want them

File systems, UI trees, and company hierarchies are composite problems. If you write `if (isFolder)` everywhere, you missed the pattern. One `size()` or `draw()` on the component interface is the design.

Use when: File trees, UI widget trees, menus, org charts, BOM (parts made of parts), nested comments.

Skip when: A flat list — Composite is overhead.

Trap: Leaves that silently ignore add().
