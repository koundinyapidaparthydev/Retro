Flyweight

ADV

Definition

Share the immutable, intrinsic parts of many similar objects so you can afford millions of them.

Why it exists

Text editors (a glyph per character), game maps (a tree type vs tree instances), and boards with repeated pieces hit memory walls.

Approach

  1. Split fields into intrinsic vs extrinsic.
  2. Put intrinsic fields on an immutable flyweight.
  3. Key the factory (char → Glyph, type → PieceStyle).
Time O(1) factory lookup after intern; first miss pays constructionSpace O(unique types) instead of O(instances) for the heavy data

You say this first

I wouldn't name the pattern first. I'd say the problem flyweight solves, then the three types. Share the immutable, intrinsic parts of many similar objects so you can afford millions of them.

Shape: Split fields into intrinsic vs extrinsic.. Don't: Hundreds of objects — the factory is not worth it. For a text editor or a huge forest, mention Flyweight. For chess (32 pieces), skip it unless they ask about a game with thousands of units.

More notes if you want them

Text editors (a glyph per character), game maps (a tree type vs tree instances), and boards with repeated pieces hit memory walls. Flyweight splits shared data from per-instance data.

Use when: Huge numbers of similar objects that share most data.

Skip when: Hundreds of objects — the factory is not worth it.

Trap: Mutable flyweights — one tree turning autumn turns all trees.
