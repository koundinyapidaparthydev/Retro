URL shortener (classes)

CORE

The problem they give you

They will not say “URL shortener (classes).” They describe this:

Given: Product wants short links, optional alias, expiry, and click counts. Someone started drawing Dynamo and a CDN.

Find: ShortUrl entity, code generator, uniqueness retry, URL validation, repository. Stay in classes.

Tiny example: Custom alias conflict. FakeClock expiry → resolve fails. Bounded regenerate on collision. Reject javascript: URLs.

Name of the tool

Turn a long link into a short code, save the pair, and when someone opens the short link, send them to the long one — fast, with a cache.

Why this tool

As HLD this is hash + cache.

Approach

  1. base62 encode of a random or monotonic id.
  2. Retry on collision; bound the loop.
  3. Validate scheme/host; reject javascript: URLs.

More notes if you want them

As HLD this is hash + cache. As LLD it is: CodeGenerator, uniqueness retry, validation of URLs, and a click counter that is optionally async. Keep it a class design.

Use when: Identity generation, uniqueness, a tiny domain.

Skip when: Spending the hour on cache tiers — that is HLD.

Trap: Using the long URL's hash only — collisions and non-randomness.
