Elevator

CORE
AmazonoftenMicrosoftoftenState machine LLD.

Definition

Cars are state machines; a scheduler assigns hall calls; each car owns a direction and a set of stops. The extension is always the scheduling policy.

Why it exists

Elevator tests state, strategy, and concurrency.

Approach

  1. Draw the car state machine first.
  2. Implement one car + a naive scheduler (nearest idle).
  3. Add SCAN: keep moving until no stops in that direction.

You say this first

Each car is a state machine (idle, moving, door). A scheduler picks a car for a hall call. I would not hard-code SCAN in the car.

A car has one direction or idle. Door open only when stopped. Code Car.step and one scheduler. Tick with a fake clock. Express / peak hours = new Scheduler. Don't edit Car. If they ask “Three cars, how do you pick?”: Closest idle, or SCAN that will pass the floor. Interface, two impls.

More notes if you want them

Elevator tests state, strategy, and concurrency. Interviewers add destination-dispatch or peak-hour mode to see if you left a scheduler interface.

Use when: State + strategy interviews, concurrency follow-ups, control systems.

Skip when: Do not simulate physics or cable wear unless they are joking.

Trap: Car that both moves and assigns all hall calls (god car).
