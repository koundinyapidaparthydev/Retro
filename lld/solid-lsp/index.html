SOLID — Liskov Substitution Principle

CORE

The problem they give you

They will not say “SOLID — Liskov Substitution Principle.” They describe this:

Given: Callers write if (bird instanceof Penguin). Square overrides setWidth and silently changes height. ReadOnlyFile extends File and write() throws.

Find: Every child must honor the parent contract. If it cannot, the parent is wrong.

Tiny example: Shape.area() on immutable values. fly() is not on Bird. No UnsupportedOperationException overrides.

Name of the tool

Every subtype must honor the parent's contract: callers should not need to know which child they have.

Why this tool

LSP failures show up as `if (obj instanceof Penguin)` and as Squares that break Rectangle setters.

Approach

  1. Write the parent guarantees in words: inputs allowed, outputs promised, exceptions, invariants.
  2. For each subtype, check those four.
  3. Move the disputed method off the parent or split the parent (FlyingBird vs Bird).

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Square extends Rectangle — what does a setter caller assume?
  • The caller should not branch on subtype. Remove the branch.
  • A List.add that throws on an immutable list — what broke?

You say this first

I wouldn't name the pattern first. I'd say the problem solid — liskov substitution principle solves, then the three types. Every subtype must honor the parent's contract: callers should not need to know which child they have.

Shape: Write the parent guarantees in words: inputs allowed, outputs promised, exceptions, invariants.. Don't: Do not force a hierarchy just to apply LSP. No inheritance, no LSP issue. If they propose Square extends Rectangle, correct it and name LSP. That is a known softball.

More notes if you want them

LSP failures show up as `if (obj instanceof Penguin)` and as Squares that break Rectangle setters. Interviewers use these to see if you treat inheritance as a real contract.

Use when: Any time you draw extends / implements.

Skip when: Do not force a hierarchy just to apply LSP. No inheritance, no LSP issue.

Trap: Overrides that ignore the argument or return null 'for now'.
