The problem they give you

They will not say “Observer.” They describe this:

Given: ParkingLot.sendSms() sits next to occupy. They want analytics and email too. A slow send blocks park.

Find: Subject notifies subscribers it does not import. Keep listeners tiny or hand them a queue.

Tiny example: orderPlaced → Emailer and Analytics. Copy the listener list. Unsubscribe on teardown.

Name of the tool

One object yells “I changed.” Anyone who subscribed gets a ping. The yeller does not know their names.

Why this tool

Notifications, UI updates, in-process pub/sub, and 'on order placed' side effects are Observer.

Approach

  1. Define an Event type or a small set of notify methods.
  2. Subject: subscribe, unsubscribe, notify (iterate a copy of the list).
  3. Keep subject business methods calling notify at the end of a successful change.

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Also send SMS. Do you open ParkingLot?
  • A listener mutates the subject and you loop forever.
  • They want reliable delivery — queue behind the same subscribe idea.

You say this first

I wouldn't name the pattern first. I'd say the problem observer solves, then the three types. Let dependents subscribe to events so the subject can notify many listeners without knowing who they are.

Shape: Define an Event type or a small set of notify methods.. Don't: One caller that should just invoke a method — a function parameter is enough. For 'also send SMS', add an observer/listener rather than stuffing ParkingLot.

More notes if you want them

Notifications, UI updates, in-process pub/sub, and 'on order placed' side effects are Observer. It keeps the subject closed while new listeners appear — and it is how you accidentally create loops and god event buses.

Use when: Multiple independent reactions to one change: email, analytics, inventory projection.

Skip when: One caller that should just invoke a method — a function parameter is enough.

Trap: Observer updates the subject and retriggers forever.
