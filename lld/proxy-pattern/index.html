Definition

Stand in for another object to control access: lazy load, protect, remote, or cache — same interface, different reason than Decorator.

Why it exists

Proxies appear as virtual images, security wrappers, remote stubs, and smart references.

Approach

  1. Match the Subject interface exactly.
  2. Decide the control: lazy create, auth check, remote RPC, cache lookup.
  3. On each call, run the control, then forward.

You say this first

I wouldn't name the pattern first. I'd say the problem proxy solves, then the three types. Stand in for another object to control access: lazy load, protect, remote, or cache — same interface, different reason than Decorator.

Shape: Match the Subject interface exactly.. Don't: You only wanted to add logging — Decorator is the clearer name. If they mention lazy image loading or access control, say Proxy and the flavor (virtual/protection).

More notes if you want them

Proxies appear as virtual images, security wrappers, remote stubs, and smart references. Interviewers want you to distinguish them from decorators: proxy controls access to the same core; decorator adds responsibilities.

Use when: Lazy-loading expensive objects (images, big documents).

Skip when: You only wanted to add logging — Decorator is the clearer name.

Trap: Proxy that is not substitutable (leaks extra methods you must cast to).
