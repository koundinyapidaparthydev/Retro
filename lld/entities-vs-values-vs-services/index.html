Entities vs values vs services

NEXT

The problem they give you

They will not say “Entities vs values vs services.” They describe this:

Given: Email has a surrogate id. User.charge() is static. PaymentGateway got a fake primary key so it could 'be an entity'.

Find: Identity over time, data equality, or behavior with no id. Repositories only for the first.

Tiny example: Order #1001 stays itself after items change. Money is interchangeable. FareCalculator has no table.

Name of the tool

Split the model into things with identity, values defined by data, and stateless (or injected) services that perform work.

Why this tool

This DDD-lite split keeps you from giving Email an id and from stuffing charge() onto User as a static.

Approach

  1. For each type, apply the copy test and the verb test.
  2. Put ids and repositories only on entities (and aggregate roots).
  3. Put format/range checks on values.

This DDD-lite split keeps you from giving Email an id and from stuffing charge() onto User as a static. Interviewers may not say 'DDD', but they notice when ids and equals are sane.

Use when: Any domain model with both data and operations.

Skip when: Tiny katas with one struct — do not force three stereotypes.

Trap: Anemic entities and a 1000-line XxxService.
