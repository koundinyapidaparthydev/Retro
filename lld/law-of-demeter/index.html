The problem they give you

They will not say “Law of Demeter.” They describe this:

Given: Checkout does order.getCustomer().getWallet().debit(x). A zip change breaks three services.

Find: Talk only to immediate friends. Put the verb on the object that owns the data.

Tiny example: customer.charge(order) or wallet.debit(order.total()). Hotel rooms only via Reservation.

Name of the tool

Talk only to your immediate friends: do not reach through getters to poke a neighbor's neighbor.

Why this tool

Chains like `order.getCustomer().getWallet().debit(x)` couple you to the whole object graph.

Approach

  1. Find getter chains in the domain.
  2. Ask which object should own the action.
  3. Pass the values that method needs instead of the whole graph when possible.

More notes if you want them

Chains like `order.getCustomer().getWallet().debit(x)` couple you to the whole object graph. When Wallet moves, half the app breaks. Demeter keeps knowledge next to the data.

Use when: Domain services that wander through entities.

Skip when: Fluent builders (`builder.withX().withY()`) — those return this, not a stranger.

Trap: Train-wreck getters in the core use case.
