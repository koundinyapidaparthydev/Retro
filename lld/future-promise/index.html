Future and promise

NEXT

Definition

A Future is a read-only handle to a result that is not here yet; a Promise is the writable side that completes it.

Why it exists

Once you have a pool, callers need a way to wait, compose, and timeout.

Approach

  1. Create a pending promise/future pair when you submit work.
  2. Run the work on a worker; complete with value or error.
  3. Let callers wait with timeout or register a continuation.

You say this first

I wouldn't name the pattern first. I'd say the problem future and promise solves, then the three types. A Future is a read-only handle to a result that is not here yet; a Promise is the writable side that completes it.

Shape: Create a pending promise/future pair when you submit work.. Don't: A local computation that is already done — return the value. Signature: `Future<Receipt> charge(card)` plus a timeout in the use case.

More notes if you want them

Once you have a pool, callers need a way to wait, compose, and timeout. Futures are that API. Without them you invent boolean flags and missed signals.

Use when: Any async API: pay, geocode, download, schedule.

Skip when: A local computation that is already done — return the value.

Trap: Calling get() with no timeout in a request thread.
