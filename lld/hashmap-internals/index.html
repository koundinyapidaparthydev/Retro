HashMap internals

CORE

The problem they give you

They will not say “HashMap internals.” They describe this:

Given: Design a map. Keys can be mutated after put. == used instead of equals. Resize forgot to rehash. They may ask about threads.

Find: Buckets, hash & mask, chain, load-factor resize. State the equals/hashCode contract. This impl is not concurrent.

Tiny example: Tiny chained map with resize tests. Broken mutable-key demo. ConcurrentHashMap or a lock if they add threads.

Name of the tool

An array of buckets, hash + mask, collision lists or trees, load-factor resize. equals/hashCode on keys is part of the contract you must state.

Why this tool

Almost every LLD uses a map.

Approach

  1. State equals/hashCode contract.
  2. Implement put/get/remove with chaining.
  3. Resize at load factor.

More notes if you want them

Almost every LLD uses a map. Knowing how it fails (mutable keys, bad hash, load factor) is how you debug and how you answer 'design a hashmap'.

Use when: The 'design a hashmap' prompt; explaining caches and intern pools.

Skip when: Using HashMap from many threads without a story.

Trap: Using == instead of equals for keys.
