SOLID — Open/Closed Principle

CORE

The problem they give you

They will not say “SOLID — Open/Closed Principle.” They describe this:

Given: Adding ElectricVehicle means editing FeeCalculator, Ticket, and the nightly report — each has the same switch.

Find: Keep the park path closed. A new type or wrapper extends behavior.

Tiny example: FeePolicy interface. Weekend rates are a class. Lot.park is untouched.

Name of the tool

Keep working code closed to modification and open to extension: add a type or a plugin, do not keep editing the same switch.

Why this tool

The interviewer's favorite move is 'now support X'.

Approach

  1. Name the variation (vehicle type, payment rail, elevator policy, notification channel).
  2. Put a common interface on that variation.
  3. Keep the use case talking only to the interface.

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • If you add another vehicle I will add a class, not edit the lot.
  • Point at the extension point.
  • The same switch still lives in three classes — is that open/closed?

You say this first

I wouldn't name the pattern first. I'd say the problem solid — open/closed principle solves, then the three types. Keep working code closed to modification and open to extension: add a type or a plugin, do not keep editing the same switch.

Shape: Name the variation (vehicle type, payment rail, elevator policy, notification channel).. Don't: A one-off flag that will not grow — do not invent a strategy hierarchy for `isWeekend`. After the first design, say 'if you add another vehicle I will add a class, not edit the lot.' Then do it when they ask.

More notes if you want them

The interviewer's favorite move is 'now support X'. OCP is the difference between adding ElectricVehicle and rewriting FeeCalculator, Ticket, and Report.

Use when: Any axis the interviewer is likely to grow.

Skip when: A one-off flag that will not grow — do not invent a strategy hierarchy for `isWeekend`.

Trap: Interfaces that change every time you add a variant — not closed, just renamed.
