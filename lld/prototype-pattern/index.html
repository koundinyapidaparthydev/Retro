The problem they give you

They will not say “Prototype.” They describe this:

Given: Duplicate document re-runs a 40-step setup. Clone() copies the list field by reference. Two 'copies' share listeners.

Find: Clone a template, then tweak. Say deep vs shallow, and give entities a new id.

Tiny example: Chess board deep-copies pieces for lookahead. Resume templates issue a new id. Do not clone a singleton.

Name of the tool

Create new objects by cloning a prototype instead of reconstructing from scratch — useful when setup is expensive or the exact class is unknown.

Why this tool

Prototype is the right story for document templates, game unit presets, and 'duplicate this row'.

Approach

  1. Add a clone method that documents deep vs shallow.
  2. Copy mutable children in a deep clone; share immutables.
  3. Assign a new id if the object is an entity.

More notes if you want them

Prototype is the right story for document templates, game unit presets, and 'duplicate this row'. It is also a reminder that clone is hard: deep vs shallow, identity, and mutable children.

Use when: Templates: resume, dungeon room, email campaign, enemy loadout.

Skip when: Cheap immutable values — just construct them.

Trap: Shallow copy of a list field.
