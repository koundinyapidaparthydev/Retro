Factory Method

CORE

The problem they give you

They will not say “Factory Method.” They describe this:

Given: DealHand, exportReport, and park each contain new Car() / new Bike() / new Truck(). The workflow is otherwise stable.

Find: The algorithm talks to a product role. Creation is a method or small object you can stub.

Tiny example: Notification.create(channel) returns Email or Sms. Adding boat is a product plus a factory branch, not a new park().

Name of the tool

Let a creator type defer which product to instantiate so subclasses or injected policies pick the concrete class.

Why this tool

Factory Method is the smallest 'I do not hard-code new' pattern.

Approach

  1. Identify the product interface (`Vehicle`, `Button`, `Handler`).
  2. Write the workflow against that interface.
  3. Extract the `new Concrete()` into a method or collaborator the workflow calls.

More notes if you want them

Factory Method is the smallest 'I do not hard-code new' pattern. You will use it for vehicles, pieces, notifications, and parsers — anywhere the rest of the algorithm is stable and the type varies.

Use when: Frameworks that let users plug in their product type.

Skip when: A single concrete product with no variation.

Trap: Factory that also contains domain logic (fees, parking).
