The problem they give you

They will not say “In-memory autocomplete.” They describe this:

Given: Typeahead scans the whole dictionary each keystroke. N will grow. They want top-k and later live updates.

Find: Trie or an honest list if N is tiny. suggest(prefix, k). Optional node-level top-k cache.

Tiny example: Insert a corpus; suggest('ca', 3). Clamp k. Concurrent add is a later lock or writer thread.

Name of the tool

A Trie (or prefix map) of terms with frequencies; suggest(prefix, k) returns top-k. Updates increment counts; the trie is the index, not a list scan.

Why this tool

Autocomplete is the 'design a DS + API' LLD.

Approach

  1. TrieNode map char → child.
  2. add updates freq.
  3. suggest uses a heap if no cache.

More notes if you want them

Autocomplete is the 'design a DS + API' LLD. The class design is TrieNode, Dictionary, Ranker. Pagination/k and thread safety are variants.

Use when: Typeahead, command palettes, in-memory dictionaries.

Skip when: Three hardcoded commands — a list is enough.

Trap: Scanning the whole dictionary every keystroke without saying N is small.
