Facade

CORE

Definition

Give clients a short, intention-revealing API in front of a noisy subsystem so they do not need to know the moving parts.

Why it exists

A checkout that must talk to inventory, pricing, tax, payment, and email is a facade (or an application service).

Approach

  1. Identify the subsystem types a typical client must touch.
  2. Write one method per use case on the facade.
  3. Sequence the tells inside: validate, reserve, charge, record.

You say this first

I wouldn't name the pattern first. I'd say the problem facade solves, then the three types. Give clients a short, intention-revealing API in front of a noisy subsystem so they do not need to know the moving parts.

Shape: Identify the subsystem types a typical client must touch.. Don't: A subsystem of one class — just use the class. Name your application service a clear verb facade: `ParkingService`, `BookingService`. That is the facade.

More notes if you want them

A checkout that must talk to inventory, pricing, tax, payment, and email is a facade (or an application service). Facades keep controllers thin and hide order-of-operations so callers cannot call step 3 before step 1.

Use when: Entry points: controllers calling many services, SDKs wrapping internals, 'start game' buttons.

Skip when: A subsystem of one class — just use the class.

Trap: Facade that duplicates all internal methods (no simplification).
