Composition over inheritance

CORE

The problem they give you

They will not say “Composition over inheritance.” They describe this:

Given: They want LoggedRetryUpiGateway extends UpiGateway, then PeakHourDestinationElevator.

Find: Assemble pricing, locking, and retry as fields you inject. Do not subclass each mix.

Tiny example: CoffeeMachine has Recipe, Inventory, Payment. Add logging by wrapping the gateway, not a new child.

Name of the tool

Build objects by assembling collaborators you own, instead of stretching a parent class to cover every variation.

Why this tool

Interview variants are mix-and-match: an elevator that is both destination-dispatch and peak-hour, a payment that is both retrying and logged.

Approach

  1. List behaviors that vary independently (pricing, locking, scheduling, persistence).
  2. Give each behavior its own type with a small interface.
  3. Hold those types as fields.

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Elevator has a SchedulingPolicy — it is not PeakHourElevator.
  • Retry plus metrics plus the real rail. How many new types?
  • Admin is a User with a Role, not a subclass.

You say this first

I wouldn't name the pattern first. I'd say the problem composition over inheritance solves, then the three types. Build objects by assembling collaborators you own, instead of stretching a parent class to cover every variation.

Shape: List behaviors that vary independently (pricing, locking, scheduling, persistence).. Don't: A true subtype with a stable contract and shared algorithm — inheritance or Template Method can be smaller. Say the phrase once, then show it: 'Elevator has a SchedulingPolicy, it does not subclass PeakHourElevator.'

More notes if you want them

Interview variants are mix-and-match: an elevator that is both destination-dispatch and peak-hour, a payment that is both retrying and logged. Inheritance forces a class per combination. Composition lets you plug policies together.

Use when: Almost always as the default structure in an LLD interview.

Skip when: A true subtype with a stable contract and shared algorithm — inheritance or Template Method can be smaller.

Trap: God objects that compose twelve collaborators and still contain all the logic.
