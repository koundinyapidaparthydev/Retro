Thread-safe logger

CORE

The problem they give you

They will not say “Thread-safe logger.” They describe this:

Given: 200 threads synchronized on one file. Callers stall. Events are reused. The queue of lines has no bound.

Find: Immutable LogEvent, bounded queue, one writer, pluggable appenders. Level check before format.

Tiny example: Async logger, FileAppender, drop-on-full. MetricsAppender added without editing Logger. Inject, do not require getInstance.

Name of the tool

A Logger facade enqueues immutable LogEvents; a single writer (or a small pool) writes to Appenders. Do not lock the whole app on System.out.

Why this tool

The naive synchronized log() serializes callers.

Approach

  1. LogEvent immutable.
  2. Sync logger for tests; async for prod.
  3. Bounded queue + one writer.

More notes if you want them

The naive synchronized log() serializes callers. The better LLD is async producer-consumer with a bound, a level filter, and pluggable appenders.

Use when: Any app; as a standalone concurrency design.

Skip when: println in a 20-line kata — do not overbuild.

Trap: synchronized on every log to a file from 200 threads.
