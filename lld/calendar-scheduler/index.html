The problem they give you

They will not say “Calendar and meeting scheduler.” They describe this:

Given: Find a 30-minute slot for three people in a window. Working hours exist. Two books can race the same gap. Recurrence is a trap.

Find: Busy ranges merge, invert inside working hours, book re-checks. Store UTC. One Event or per-calendar copies — pick.

Tiny example: Three users, propose a 30m slot. Concurrent books of that slot — one fails. Skip RRULE in v1.

Name of the tool

Users have Calendars of Events with DateRanges; a Scheduler finds overlapping free slots across invitees and books an Event if no conflict (or with a policy).

Why this tool

Meetings combine value-object ranges, per-user aggregates, and a use case that reads many calendars.

Approach

  1. DateRange with overlaps/merge.
  2. Pure function freeSlots(busy[], window, duration).
  3. book re-validates before commit.

More notes if you want them

Meetings combine value-object ranges, per-user aggregates, and a use case that reads many calendars. It is the 'two aggregates' coordination problem.

Use when: Calendars, room booking, interview-loop scheduling.

Skip when: A single reminder — a Job scheduler is enough.

Trap: String times without timezone.
