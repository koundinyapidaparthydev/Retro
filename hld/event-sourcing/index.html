Event sourcing

ADV

Definition

The write-side source of truth is an append-only log of facts; current state is a fold over those events. Powerful, easy to overuse.

Why it exists

Ledgers, collaborative editing, and audit-heavy domains sometimes want the history as the data.

Approach

  1. One stream per aggregate (account_id); append with expected version.
  2. Snapshot every N events; load snapshot + tail to serve commands.
  3. Project to read models asynchronously; rebuild when projections change.

More notes if you want them

Ledgers, collaborative editing, and audit-heavy domains sometimes want the history as the data. Event sourcing is not 'we have Kafka.' It is a persistence choice with replay, versioning, and snapshotting. Interviews reward using it only where history is the product.

Use when: Wallets, booking histories, collaborative documents, workflows you must replay.

Skip when: Simple CRUD profiles and CMS pages.

Trap: Mutable 'events' — then it is not a log.
