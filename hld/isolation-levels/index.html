Isolation levels

NEXT

Definition

Read uncommitted through serializable — which write/read anomalies you accept inside a database, and why distributed SQL still makes you choose.

Why it exists

HLD candidates jump to shards and forget that a single primary still has isolation.

Approach

  1. Name the engine default (Postgres: read committed; MySQL InnoDB: repeatable read).
  2. For money and inventory, use row locks, SELECT FOR UPDATE, or optimistic version checks.
  3. Raise to serializable/SSI only on the few transactions that have write-skew risk.

More notes if you want them

HLD candidates jump to shards and forget that a single primary still has isolation. Lost updates on inventory, non-repeatable reads on a transfer, and write skew on 'only two admins' are isolation bugs. You should know what Postgres default actually gives you.

Use when: Inventory, wallets, booking, unique constraints, 'exactly one winner.'

Skip when: Do not wrap a whole checkout HTTP workflow in one open transaction.

Trap: Read-modify-write on a counter without atomic increment or version.
