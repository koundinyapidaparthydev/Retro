HLD/Security

Encryption at rest and in transit

CORE

Definition

TLS on the wire, KMS-backed encryption on disks and objects, and application-level encryption when the platform admin should not see the bytes.

Why it exists

Compliance checklists ask this; so do interviewers.

Approach

  1. Enable platform encryption on disks, buckets, and warehouses.
  2. KMS CMKs per environment/tenant class; IAM on kms:Decrypt.
  3. TLS to Redis/Kafka/Postgres, not only to the browser.

You say this first

TLS on the wire, KMS-backed encryption on disks and objects, and application-level encryption when the platform admin should not see the bytes. I'd only add it if a requirement we wrote down actually needs it. Platform at-rest + TLS: all production.

Tradeoff: Platform encryption: easy, coarse, trusts the cloud IAM.. Failure mode: Keys in the same repo as ciphertext. Say 'TLS everywhere + KMS-encrypted S3/DB + field encrypt PAN' as a stack.

More notes if you want them

Compliance checklists ask this; so do interviewers. The design questions are who holds keys, what is covered (backups, replicas, logs), and whether you need envelope encryption for specific fields (SSN, card PAN).

Use when: Platform at-rest + TLS: all production.

Skip when: Do not roll your own block cipher mode in the app for fun.

Trap: Keys in the same repo as ciphertext.
