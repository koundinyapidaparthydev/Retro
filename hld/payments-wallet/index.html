I'd treat this as a 45-minute HLD. First I lock v1 of payments wallet / ledger: who uses it, read vs write, latency, what is v2. A system of record for money: double-entry ledger, idempotent credits/debits, and sagas with processors — correctness first.

Then API, data, one write path and one read path. Deep dive: Idempotency lock/row → insert two entries → update balances/versions → outbox → commit.. Stored balance vs fold of entries: speed vs rebuild purity (use both: snapshot + tail).

More notes if you want them

This is the ACID/idempotency exam. Fancy scale is secondary until you can not double-spend, not drop a credit, and explain reconciliation.

Use when: Wallets, gift cards, marketplace escrow, in-app credits.

Skip when: Do not put the ledger in Mongo without single-document ACID and a careful model.

Trap: DELETE a ledger row to 'undo.'
