Definition

A log of partitions, a managed competing-consumer queue, and a flexible broker — when each is the boring correct choice.

Why it exists

Name-dropping without a mental model is a reject.

Approach

  1. Need replay, many independent apps, or CDC-scale ingest → Kafka/Kinesis.
  2. Need a dumb durable job list with almost no ops → SQS (+ SNS).
  3. Need sophisticated routing and work queues you already run → Rabbit.

You say this first

A log of partitions, a managed competing-consumer queue, and a flexible broker — when each is the boring correct choice. I'd only add it if a requirement we wrote down actually needs it. Kafka: activity, logs, event bus, stream processing.

Tradeoff: Kafka: powerful and heavy; ops and partition planning.. Failure mode: Kafka consumers in the same group accidentally sharing work you wanted duplicated. If the company is AWS-heavy, SQS+SNS is a credible default; mention Kafka when replay/fan-in exists.
