The problem they give you

They will not say “Failure modes: crash, partition, split-brain, clock skew.” They describe this:

Given: The box did not crash. It paused. The network lied. Clocks jumped. Two primaries exist.

Find: Name the failure you are designing for — crash, partition, split-brain, or skew — and the client-visible result.

Tiny example: GC pause 12s, clocks 400ms apart, a fencing token ignored.

Name of the tool

The failures your protocol must survive — not 'the server goes down,' but the messy ones that duplicate leaders and reorder time.

Why this tool

Designs that only handle clean process death look fine on a whiteboard and lie in production.

Approach

  1. Assume every RPC can timeout with unknown result — design idempotent writes.
  2. Use majority quorum or an external lock service for exclusive roles.
  3. Issue monotonic epochs/fencing tokens on failover; storage rejects old epochs.

Whiteboard prompts

  • The node is slow, not dead. What does the caller do?
  • How do you notice split-brain?

You say this first

The failures your protocol must survive — not 'the server goes down,' but the messy ones that duplicate leaders and reorder time. I'd only add it if a requirement we wrote down actually needs it. Any leader election, unique resource, multi-AZ database, or LWW store.

Tradeoff: Aggressive timeouts: faster failover, more false partitions and duplicate work.. Failure mode: Even-sized clusters and two-node 'HA.' Walk one story: primary isolated, still accepting writes, then the new primary — and show fencing.

More notes if you want them

Designs that only handle clean process death look fine on a whiteboard and lie in production. Partitions create two realities. Split-brain double-applies money. Clock skew breaks TTLs, tokens, and last-writer-wins. Name these modes and the fence that stops them.

Use when: Any leader election, unique resource, multi-AZ database, or LWW store.

Skip when: Do not hand-wave 'we'll use NTP' as a consistency protocol.

Trap: Even-sized clusters and two-node 'HA.'
