The problem they give you

They will not say “Design live comments.” They describe this:

Given: A World Cup goal drops and 200k people comment on the same video at once.

Find: v1: append-only comments that other viewers see within a second or two.

Tiny example: One video is 90% of write QPS. History is a cursor, not a refresh.

Name of the tool

A high-churn comment stream on a live video or launch: recent window + subscribe, not a full Instagram comment system on every tick.

Why this tool

The Super Bowl stream has a write QPS that would melt a naive comments table plus a fan-out to millions of viewers.

Approach

  1. Client posts; API writes Kafka + optional sync persist.
  2. Sampler/aggregator publishes a human-speed stream per event.
  3. Viewers SSE/WS the display topic; catch-up last N from Redis.

More notes if you want them

The Super Bowl stream has a write QPS that would melt a naive comments table plus a fan-out to millions of viewers. You need sampling, windows, and a pubsub, plus a durable subset for later VOD.

Use when: Live sports, product launches, live commerce, Twitch-like chat on a video.

Skip when: Do not use the full Instagram comment schema and fan-out-on-write to all viewers.

Trap: One Kafka partition for the Super Bowl.
