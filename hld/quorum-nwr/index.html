Quorum reads and writes (N, W, R)

NEXT

Definition

With N replicas, a write waits for W acks and a read waits for R responses. If R+W > N you overlap and can read the latest write — with caveats.

Why it exists

Dynamo, Cassandra, and Riak made NWR famous.

Approach

  1. Pick N from failure model (3 for 1 failure, 5 for 2) and storage cost.
  2. Pick W/R from the API: money W=N or majority; feed W=1; profile R=1 with cache.
  3. On read, merge R responses; if siblings, resolve or return conflict to the app.

You say this first

With N replicas, a write waits for W acks and a read waits for R responses. If R+W > N you overlap and can read the latest write — with caveats. I'd only add it if a requirement we wrote down actually needs it. Leaderless or multi-master KV/wide-column stores.

Tradeoff: Higher W/R: stronger overlap, worse latency and availability (need more live nodes).. Failure mode: R+W>N with last-writer-wins and skewed clocks. Default N=3, W=2, R=2 and say what concurrent writes do.

More notes if you want them

Dynamo, Cassandra, and Riak made NWR famous. It is the concrete knob behind CAP/PACELC for leaderless stores. Interviews expect you to pick N=3, W=2, R=2 for 'pretty strong' and to know when it still fails (concurrent writes, sloppy quorums, clocks).

Use when: Leaderless or multi-master KV/wide-column stores.

Skip when: Do not use W=1 for a unique inventory decrement and call it quorum-safe.

Trap: R+W>N with last-writer-wins and skewed clocks.
