API gateway and reverse proxy

CORE

Definition

The HTTP front door: routing, authn, rate limits, TLS, and request shaping so every microservice does not reinvent the edge.

Why it exists

Gateways are how you present one public API over many services.

Approach

  1. Terminate TLS, attach request_id, authenticate, then route by path or host.
  2. Apply consumer quotas and IP/WAF rules before hitting app CPU.
  3. Use a BFF or aggregation layer when mobile would otherwise chat 15 APIs.

More notes if you want them

Gateways are how you present one public API over many services. They are also a bottleneck and a single place to get auth wrong. Know what belongs at the edge versus in the service, and how a reverse proxy differs from a full API management product.

Use when: Public APIs, partner integrations, and many microservices behind one hostname.

Skip when: A single small app — a load balancer plus the service is enough.

Trap: JWT validation without issuer/audience/clock-skew checks.
