Design a newsfeed (Twitter-like)

CORE

The problem they give you

They will not say “Design a newsfeed (Twitter-like).” They describe this:

Given: I follow 200 people. I open the app and want new posts now.

Find: v1: deliver a home timeline. Ranking models are later.

Tiny example: Reads dwarf writes. One celebrity has 50M followers.

Name of the tool

Post once, read a ranked timeline — hybrid fan-out, caches, and a celebrity exception. The classic social HLD.

Why this tool

If you can explain push vs pull and a 10M-follower tweet, you can do Instagram, notifications, and live comments.

Approach

  1. Post: write tweet → enqueue fan-out → 202/200 with tweet id.
  2. Workers push id into follower inboxes except celebrities.
  3. Home read: LRANGE inbox + pull recent celebrity tweets + hydrate objects from cache/DB + rank.

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Design Twitter / Facebook home feed.
  • Fan-out on write or on read — who gets which?
  • I follow someone and the feed looks empty.

You say this first

The hard part is fan-out, not the tweet table. I'd pick fan-out-on-write for normal users and fan-out-on-read for celebrities.

posts by id. follow graph. precomputed feed lists in Redis/Cassandra per user. Write: API → post DB → fan-out workers → follower feed caches. Read: API → my feed cache. Hybrid: push to normal followers, pull celebrities at read time and merge. If they ask ranking, add a lightweight score on merge — don't start with ML. If they ask “Someone has 50M followers.”: Do not write 50M feed entries. Pull at read. Cache their recent posts.
