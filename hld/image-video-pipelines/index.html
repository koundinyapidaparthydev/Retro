Image and video processing pipelines

NEXT

Definition

Async workers that transcode, thumbnail, and package media into CDN-ready variants — never on the upload request thread.

Why it exists

Instagram and YouTube are upload + pipeline + serve.

Approach

  1. Upload complete → message {object_key, user, type}.
  2. Workers write variants to a deterministic prefix; update DB status.
  3. CDN serves variants; API returns the manifest when ready.

You say this first

Async workers that transcode, thumbnail, and package media into CDN-ready variants — never on the upload request thread. I'd only add it if a requirement we wrote down actually needs it. Any UGC photo/video product.

Tradeoff: More variants: better UX and device coverage, storage/CPU cost.. Failure mode: Unbounded user-supplied resolution/duration as a DoS. State machine: uploaded → processing → ready/failed; user can see progress.

More notes if you want them

Instagram and YouTube are upload + pipeline + serve. The pipeline is a queue of CPU/GPU jobs with idempotent outputs, priority, and poison videos. If you transcode in the API process you fail the interview and the p99.

Use when: Any UGC photo/video product.

Skip when: Do not transcode synchronously in the upload HTTP handler.

Trap: Unbounded user-supplied resolution/duration as a DoS.
