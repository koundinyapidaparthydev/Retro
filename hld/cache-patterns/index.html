Where the cache sits on the read/write path, how it goes stale, and how you stop a TTL expiry from becoming a database outage. I'd only add it if a requirement we wrote down actually needs it. Read-heavy objects, sessions, rendered feeds, CDN assets.

Tradeoff: Aside: simple, stampede and stale-if-you-forget-delete.. Failure mode: Inconsistent key hashing so you cannot delete what you wrote. Name aside vs through and say 'delete the key on write, TTL 5m as backup.'
