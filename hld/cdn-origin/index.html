The problem they give you

They will not say “CDN and origin design.” They describe this:

Given: Viewers worldwide request the same MP4. The origin is in one region and the NIC is melting.

Find: Design the edge cache and what still has to hit origin.

Tiny example: 80% cacheable, 20% personalized manifests, a bad deploy cached for 24h.

Name of the tool

How the edge talks to object storage or an origin fleet: cache keys, shields, signed URLs, and range requests for media.

Why this tool

A CDN without an origin plan still melts S3 or your app.

Approach

  1. Put CloudFront/Fastly/etc.
  2. Version objects; long TTL; purge by key only when you must.
  3. Sign URLs for private media; keep listing disabled.

You say this first

How the edge talks to object storage or an origin fleet: cache keys, shields, signed URLs, and range requests for media. I'd only add it if a requirement we wrote down actually needs it. Any public or private media at consumer scale.

Tradeoff: Bucket as origin: simple, limited logic.. Failure mode: Cache key includes a unique token so hit rate is 0. Do the miss-bandwidth math once — it justifies the CDN more than adjectives.

More notes if you want them

A CDN without an origin plan still melts S3 or your app. File/video designs live or die on cache hit ratio, range requests, and whether the origin is the bucket or a compute layer (image resize, auth).

Use when: Any public or private media at consumer scale.

Skip when: Tiny, unique, authenticated JSON at low QPS — extra hop may not pay.

Trap: Cache key includes a unique token so hit rate is 0.
