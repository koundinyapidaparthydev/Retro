You say this first

I'd treat this as a 45-minute HLD. First I lock v1 of key-value store: who uses it, read vs write, latency, what is v2. A Dynamo-style distributed KV: partition, replicate, put/get, and handle failures without a single primary for all keys.

Then API, data, one write path and one read path. Deep dive: Hash key to ring; coordinator sends to N replicas; wait for W/R.. Leaderless + W=1: available, conflicts.

More notes if you want them

This is the 'build Dynamo/Cassandra' interview. It pulls together consistent hashing, NWR, hinted handoff, and compaction. It is how you prove you understand data systems, not only boxes.

Use when: Sessions, inboxes, huge sparse objects, interview 'design Dynamo.'

Skip when: Ad-hoc query, multi-key SQL joins, or a 10 GB dataset.

Trap: hash % N with no plan to add nodes.
