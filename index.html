Start here · CORE first

The interviews ask these early

DSA listings put must-haves on top. These six are the usual first stop.

Binary Search

CORE

If the list is sorted, keep asking “is the middle too small or too big?” and throw away half each time.

Two Pointers

CORE

Put one finger on the left and one on the right, then move them toward each other instead of using two nested loops.

Breadth-First Search

CORE

Explore a graph like ripples in a pond: everything 1 step away, then 2 steps, then 3. Closest things first.

0/1 Knapsack

CORE

A backpack that can take each item at most once. For every item you ask: take it, or skip it, and remember the best leftover capacity.

Design a URL shortener

CORE

Turn a long link into a short code, save the pair, and when someone opens the short link, send them to the long one — fast, with a cache.

Parking lot

CORE

A lot owns floors and spots. A car asks for a matching free spot, gets a ticket, and pays a fee policy when it leaves.

How to read a topic

  1. Definition, why, approach — three short cards.
  2. Play the picture for that problem. Company chips say who asks it.
  3. They ask / you say. Extra notes stay collapsed.

On /dsa, categories run Arrays → Hashing → two pointers → binary search → … → advanced, with CORE cards first.
