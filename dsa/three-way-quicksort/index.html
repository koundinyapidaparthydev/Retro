The problem they give you

They will not say “3-Way Quicksort.” They describe this:

Given: An array whose values are only 0, 1, and 2 — or many duplicates of a few keys.

Find: The same values grouped in order: all 0s, then 1s, then 2s. One pass, in place. Do not re-process the equals.

Tiny example: [2, 0, 2, 1, 1, 0] → [0, 0, 1, 1, 2, 2].

Name of the tool

Dijkstra's Dutch-national-flag partition: split into < pivot, == pivot, > pivot so duplicate keys are finished in one pass.

Why this tool

Approach

  1. Choose a pivot (random index is still wise).
  2. While i <= gt: if A[i] < pivot, swap(i, lt), i++, lt++.
  3. Recurse on [lo, lt) and (gt, hi].

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Rearrange 0/1/2 in one pass with constant extra space.
  • Ten million records, but the key is a status enum with three values. How do you sort?
  • Keys are all distinct. Is the extra third bucket still worth it?

You say this first

Dijkstra's Dutch-national-flag partition: split into < pivot, == pivot, > pivot so duplicate keys are finished in one pass. I'd dry-run a tiny case first, then say the invariant and the complexity (O(n log n) typical; O(n) when all keys equal time, O(log n) stack space).

Offer the next notch: While i <= gt: if A[i] < pivot, swap(i, lt), i++, lt++. If A[i] > pivot, swap(i, gt), gt--. Else i++.. Tradeoff: Keys are unique — extra pointers buy nothing over Hoare/Lomuto. If they give you an array of 0/1/2, they want Dutch flag, not a full sort. Do it in one pass.

More notes if you want them

Classic two-way quicksort degrades when the array has few distinct keys — think 'sort 10 million records with a boolean or a status enum.' Every equal key still gets re-partitioned. 3-way quicksort (Bentley–McIlroy / Dijkstra) puts all equals in the middle and does not recurse there. It is the same idea as the Dutch national flag problem, which is itself a common interview.

Use when: Arrays with many duplicate keys.

Skip when: Keys are unique — extra pointers buy nothing over Hoare/Lomuto.

Trap: Advancing i after a swap with gt — the new A[i] has not been classified.
