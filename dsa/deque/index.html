Deque (Double-Ended Queue)

NEXT

The problem they give you

They will not say “Deque (Double-Ended Queue).” They describe this:

Given: A sequence that must accept inserts and deletes at both the front and the back.

Find: All four end operations in O(1). Popping the front of a plain dynamic array is not O(1).

Tiny example: pushBack 1, pushFront 2, popBack → 1, popFront → 2. The sequence is empty.

Name of the tool

Push and pop at both ends in O(1). The structure behind monotonic queues, 0-1 BFS, and sliding-window algorithms.

Why this tool

A deque is the data structure people mean when they say 'queue' and then pop from the back.

Approach

  1. Circular-array deque: head/tail indices modulo cap, grow by allocating 2× and laying out elements linearly when full.
  2. Linked-list deque: dummy head/tail like the LRU list; add/remove at either dummy.
  3. Use it: sliding-window max (pop back losers, pop front stale); 0-1 BFS (push front if dist shrinks by 0, push back if +1).

dq.push(2);        // back
dq.unshift(1);     // front

console.log("popBack", dq.pop(), "left", dq.slice());

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Implement a double-ended queue.
  • Edges weigh only 0 or 1. Where do you insert the 0-weight neighbor?
  • Check a palindrome by eating both ends.

You say this first

Push and pop at both ends in O(1). The structure behind monotonic queues, 0-1 BFS, and sliding-window algorithms. I'd dry-run a tiny case first, then say the invariant and the complexity (O(1) end operations (amortized if growing) time, O(n) space).

Offer the next notch: Linked-list deque: dummy head/tail like the LRU list; add/remove at either dummy.. Tradeoff: Only one end — a stack or queue is a clearer type. If you write `shift()` on a JS array as your queue, mention it is O(n) and you would use a deque in production.

More notes if you want them

A deque is the data structure people mean when they say 'queue' and then pop from the back. Monotonic window maxima, 0-1 BFS (push front on weight-0 edges), and palindrome checks (pop both ends) all need it. If you only have a stack and a queue, you will fake a deque with a list and accidentally make an O(n) front pop.

Use when: Need both-end access in O(1).

Skip when: Only one end — a stack or queue is a clearer type.

Trap: Using an array front-delete in a tight loop — hidden O(n²).
