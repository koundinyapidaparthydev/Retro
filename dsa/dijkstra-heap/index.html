The problem they give you

They will not say “Dijkstra as a Heap Algorithm.” They describe this:

Given: A map of cities and roads. Each road has a positive travel time. You start at city S.

Find: The cheapest travel time from S to every other city. A plain hop-count walk is wrong because roads cost different amounts.

Tiny example: S→A=1, S→B=4, A→B=1. Best to B is 2 via A, not the direct 4.

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Shortest time on a weighted map. All edges are positive.
  • You push a new (time, city) pair whenever a city improves. A later pop is stale — what do you do?
  • Some roads cost 0 or 1 only. Do you still want a priority bag?

You say this first

Dijkstra is BFS with a min-heap of (distance, node) instead of a queue. The heap always expands the closest unsettled node. This topic is the heap view; the graph topic covers the full algorithm. I'd dry-run a tiny case first, then say the invariant and the complexity (O((V + E) log V) lazy binary heap time, O(V + E) space).

Offer the next notch: While heap: pop {d, u}. if d !== dist[u] continue. for each edge u→v, if dist[u]+w < dist[v], update and push {dist[v], v}.. Tradeoff: Unweighted — BFS. 0-1 weights — deque. Negative weights — Bellman-Ford. If they ask you to implement Dijkstra, this loop is the answer. Talk about stale heap entries.

More notes if you want them

Interviewers ask 'why a heap?' because the next-closest node is a priority-queue extract-min. If you use a linear scan for the closest node, Dijkstra is O(V²), which is fine on dense graphs and bad on sparse ones. The heap makes it O((V+E) log V) with binary heaps (lazy version). Seeing Dijkstra as 'heap + relaxation' ties this chapter to graphs.

Use when: Non-negative weighted shortest paths; the implementation vehicle is a min-heap.

Skip when: Unweighted — BFS. 0-1 weights — deque. Negative weights — Bellman-Ford.

Trap: Using a max-heap. Using BFS on weighted edges.
