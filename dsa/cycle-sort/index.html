Cycle Sort

ADV

The problem they give you

They will not say “Cycle Sort.” They describe this:

Given: An array of n integers. Each value is supposed to sit in 1..n, but one number is missing, one is duplicated — or you need the first missing positive.

Find: The missing number (or every duplicate). Use the array itself as seats: value v belongs at index v-1. No extra set.

Tiny example: [3, 1, 3, 4] for range 1..4 → 3 sits twice, 2 is missing. Return 2.

Name of the tool

Write each element directly to its final index by walking cycles of the permutation. Minimizes writes; useful when memory writes are costly.

Why this tool

Cycle sort is the rare sort whose headline is writes, not comparisons.

Approach

  1. General cycle sort: for start in 0..n-2, compute the rank of A[start] among all items; skip if it is already home; otherwise rotate the cycle, writing…
  2. Permutation-of-1..n variant: while A[i] is in 1..n and A[A[i]-1] !== A[i], swap A[i] with A[A[i]-1].
  3. After every cycle is placed, a linear scan finds missing / duplicate / first-missing-positive answers from positions where A[i] !== i+1.

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Array of n values in 1..n. Find the missing one, in place.
  • Find every value that appears twice.
  • First missing positive. Negatives and zeros are not seats.

You say this first

Write each element directly to its final index by walking cycles of the permutation. Minimizes writes; useful when memory writes are costly. I'd dry-run a tiny case first, then say the invariant and the complexity (O(n²) general ranking; O(n) for 1..n destination mapping time, O(1) space).

Offer the next notch: Permutation-of-1..n variant: while A[i] is in 1..n and A[A[i]-1] !== A[i], swap A[i] with A[A[i]-1].. Tradeoff: General-purpose sorting; n² comparisons and a delicate implementation. When you see 'array of n integers, each in 1..n,' think cycle placement before hashing.

More notes if you want them

Cycle sort is the rare sort whose headline is writes, not comparisons. You will not implement it as a general library sort. You will use the cycle idea in interview problems: 'find the missing number,' 'find all duplicates in 1..n,' 'first missing positive.' Those problems are cycle sort wearing a disguise — each value v belongs at index v-1, and you rotate cycles until every seat is correct.

Use when: Write-limited memory; you need a write-optimal rearrangement.

Skip when: General-purpose sorting; n² comparisons and a delicate implementation.

Trap: Infinite swap loops when duplicates exist: stop if the destination already holds the same value.
