Merge Two Sorted Lists

CORE

The problem they give you

They will not say “Merge Two Sorted Lists.” They describe this:

Given: Two lists whose values are already sorted, e.g. 1→4→5 and 1→2→3→6.

Find: One sorted list made by rewiring the existing nodes, not allocating new ones. On ties, take the first list first.

Tiny example: 1→2→4 and 1→3→4 → 1→1→2→3→4→4.

Name of the tool

Walk two sorted lists with a dummy tail pointer and always attach the smaller head. The merge step of merge sort, in pointer form.

Why this tool

This is the linked-list analog of the merge in merge sort and the warmup for merge-k-lists.

Approach

  1. Create dummy and tail = dummy.
  2. While a and b are both non-null: if a.val <= b.val, tail.next = a, a = a.next; else tail.next = b, b = b.next.
  3. tail.next = a ??

Run it in JavaScript

Left is the snippet. Right is the console — one console.log at a time.

dummy tail; always attach the smaller head

const n = (val, next = null) => ({ val, next });
const vals = (h) => { const a = []; while (h) { a.push(h.val); h = h.next; } return a; };
let a = n(1, n(3, n(5)));
let b = n(2, n(4));
const dummy = n(0);
let tail = dummy;
while (a && b) {
  if (a.val <= b.val) { tail.next = a; a = a.next; }
  else { tail.next = b; b = b.next; }
  tail = tail.next;
  console.log("took", tail.val);
}
tail.next = a || b;
console.log("merged", vals(dummy.next));

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Merge two sorted lists by pointer rewiring.
  • One list runs out first. What happens to the leftover tail?
  • Use this as the combine step to sort one list.

You say this first

Walk two sorted lists with a dummy tail pointer and always attach the smaller head. The merge step of merge sort, in pointer form. I'd dry-run a tiny case first, then say the invariant and the complexity (O(n + m) time, O(1) extra iterative space).

Offer the next notch: While a and b are both non-null: if a.val <= b.val, tail.next = a, a = a.next; else tail.next = b, b = b.next. Then tail = tail.next.. Tradeoff: Unsorted lists — sort first or use a heap if you have k of them. Use a dummy. Testing the first node with a null head is how people drop the first element.

More notes if you want them

This is the linked-list analog of the merge in merge sort and the warmup for merge-k-lists. It tests dummy-head technique, tail splicing, and leftover tails. If you rebuild values into a new list you will get dinged for extra allocations when the expected solution rewires existing nodes in O(1) extra space.

Use when: Combining two already-sorted lists.

Skip when: Unsorted lists — sort first or use a heap if you have k of them.

Trap: Advancing tail before attaching, or attaching but forgetting to advance the chosen list.
