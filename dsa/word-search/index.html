Word Search

CORE

The problem they give you

They will not say “Word Search.” They describe this:

Given: A letter grid and a word. You walk up/down/left/right. A cell may be used once on the path.

Find: Does the word appear as a path? Yes or no.

Tiny example: Grid AB / CD. Word ABD: A–B–D, yes. Word ABC: C sits diagonal from B, so no.

Name of the tool

DFS from each cell, walking four directions to match the next character, marking the path so you do not reuse a cell. Backtrack the mark.

Why this tool

Word search (and its II variant with a trie) is the grid-DFS interview.

Approach

  1. For each cell, call dfs(r, c, 0).
  2. dfs: if out of bounds or board[r][c] !== word[k], return false.
  3. Save board[r][c], set it to a sentinel, try four directions with k+1.

Run it in JavaScript

Left is the snippet. Right is the console — one console.log at a time.

walk neighbors, mark the cell used

const g = [
  ["A", "B"],
  ["C", "D"],
];
const word = "ABD";
const seen = new Set();

function dfs(r, c, i) {
  if (i === word.length) return true;
  const key = r + "," + c;
  if (r < 0 || r > 1 || c < 0 || c > 1 || seen.has(key) || g[r][c] !== word[i]) {
    return false;
  }
  seen.add(key);
  console.log("use", g[r][c], "at", r, c);
  const ok =
    dfs(r + 1, c, i + 1) ||
    dfs(r - 1, c, i + 1) ||
    dfs(r, c + 1, i + 1) ||
    dfs(r, c - 1, i + 1);
  if (!ok) {
    seen.delete(key);
    console.log("back", g[r][c]);
  }
  return ok;
}

console.log("found", dfs(0, 0, 0));

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Does this one word sit on the board?
  • A whole dictionary of words. Find all that sit on the board.
  • You may not reuse a cell. Mark and unmark as you walk.

You say this first

DFS from each cell, walking four directions to match the next character, marking the path so you do not reuse a cell. Backtrack the mark. I'd dry-run a tiny case first, then say the invariant and the complexity (O(mn · 4^L) for one word of length L time, O(L) stack; O(1) extra if you mark in place space).

Offer the next notch: dfs: if out of bounds or board[r][c] !== word[k], return false. If k === word.length-1, return true.. Tradeoff: The word may use cells twice — then do not mark, or the problem is a different one. Write mark/unmark in the same breath. If they ask about many words, pivot to a trie.

More notes if you want them

Word search (and its II variant with a trie) is the grid-DFS interview. It combines recursion, in-place marking, and pruning when the prefix dies. If you forget to unmark, every path poisons the board. If you copy the board, you pass but signal the wrong instinct. Word Search II upgrades the same walk with a trie so you search all words in one traversal.

Use when: Find a word (or all words) as a path in a grid, no cell reuse.

Skip when: The word may use cells twice — then do not mark, or the problem is a different one.

Trap: Forgetting to restore the cell on both success and failure (on success you must still restore if you continue searching other words, or if the caller retries).
