Ternary Search

ADV

Definition

Trisect a unimodal function and discard a third each time. Use it for finding a min or max on a mountain-shaped real or discrete domain.

Why it exists

Ternary search shows up in competitive programming and in the occasional interview that wants a unimodal optimization, not a boolean cutoff.

Approach

  1. Confirm unimodality — draw f or argue from the problem (e.g.
  2. While hi - lo > 2 (discrete), set m1 = lo + floor((hi-lo)/3), m2 = hi - floor((hi-lo)/3).
  3. If seeking a minimum: if f(m1) > f(m2) then lo = m1; else hi = m2.
Time O(log n) evaluations of f (log base 3/2, same class as binary)Space O(1)

Run it in JavaScript

Left is the snippet. Right is the console — one console.log at a time.

max of a bitonic array

const a = [1, 3, 8, 12, 9, 4, 2];
let lo = 0, hi = a.length - 1;

while (hi - lo > 2) {
  const t = Math.floor((hi - lo) / 3);
  const m1 = lo + t, m2 = hi - t;
  console.log({ m1, v1: a[m1], m2, v2: a[m2] });
  if (a[m1] < a[m2]) lo = m1;
  else hi = m2;
}
let p = lo;
for (let i = lo; i <= hi; i++) if (a[i] > a[p]) p = i;
console.log("peak", p, a[p]);

You say this first

Trisect a unimodal function and discard a third each time. Use it for finding a min or max on a mountain-shaped real or discrete domain. I'd dry-run a tiny case first, then say the invariant and the complexity (O(log n) evaluations of f (log base 3/2, same class as binary) time, O(1) space).

Offer the next notch: While hi - lo > 2 (discrete), set m1 = lo + floor((hi-lo)/3), m2 = hi - floor((hi-lo)/3).. Tradeoff: Handles unimodal optimization that binary search cannot, at the cost of two evaluations per step and a fiddlier discrete ending. More notes if you want them

Ternary search shows up in competitive programming and in the occasional interview that wants a unimodal optimization, not a boolean cutoff. If you try binary search on a function that goes down then up, there is no single predicate P that stays false then true. Ternary search is the tool for 'find the integer k that minimizes cost(k) when cost decreases then increases.' Knowing when not to use it — most interview 'search' problems are binary — is as important as coding it.

Use when: Unimodal cost over an integer or real parameter (optimal meeting point on a line, ternary over a bitonic array).

Skip when: Monotonic predicates — use binary search on the answer. It is simpler and less error-prone.

Trap: Using ternary search on a monotonic boolean — it works but is the wrong abstraction and confuses the interviewer.
