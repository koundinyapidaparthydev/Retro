Counting Set Bits

The problem they give you

They will not say “Counting Set Bits.” They describe this:

Given: An integer n, or every integer from 0 to n.

Find: How many 1-bits each number has.

Tiny example: 13 is 1101 → 3 ones. For 0..5 the counts are [0,1,1,2,1,2].

Name of the tool

Kernighan clears one set bit per loop. Hardware popcount is O(1). The DP counting-bits problem uses dp[i] = dp[i>>1] + (i&1).

Approach

  1. Single n: c=0; while n: n&=n-1; c++.
  2. Table: for i=1..n: dp[i]=dp[i>>1]+(i&1).
  3. Prefer Integer.bitCount / __builtin_popcount when allowed.

Run it in JavaScript

Left is the snippet. Right is the console — one console.log at a time.

n & 1 then shift, or popcount table

function bits(n) {
  let c = 0;
  const steps = [];
  while (n) {
    steps.push((n & 1) + " from " + n.toString(2));
    c += n & 1;
    n >>>= 1;
  }
  console.log(steps.join(" | "));
  return c;
}

console.log("pop 13", bits(13));
console.log("pop 7", bits(7));
console.log("pop 8", bits(8));

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Number of 1 bits in n.
  • Hamming distance between two integers.
  • The 1-bit count for every number from 0 to n.

You say this first

Kernighan clears one set bit per loop. Hardware popcount is O(1). The DP counting-bits problem uses dp[i] = dp[i>>1] + (i&1). I'd dry-run a tiny case first, then say the invariant and the complexity (O(popcount) Kernighan; O(1) hardware; O(n) for the 0..n table time, O(1) or O(n) for the table space).

Offer the next notch: Table: for i=1..n: dp[i]=dp[i>>1]+(i&1).. Tradeoff: You only need 'is n a power of two' — n>0 && (n&(n-1))===0, no count. Hamming Distance is popcount(x^y). Counting Bits is the DP, not n calls to popcount unless n is tiny.

More notes if you want them

Hamming weight shows up as 'number of 1 bits,' as a loop bound (iterate only set bits), and as Counting Bits (LeetCode 338) — a DP that interviewers like because it is not a nested popcount. You should know the naive 32-step scan, the Kernighan n&(n-1) loop, and the language's built-in (bitCount, popcount, __builtin_popcount).

Use when: Hamming weight, Hamming distance (popcount of XOR), bulk tables of popcounts.

Skip when: You only need 'is n a power of two' — n>0 && (n&(n-1))===0, no count.

Trap: Infinite loop if you write n = n-1 without the AND (negatives in JS 32-bit).
