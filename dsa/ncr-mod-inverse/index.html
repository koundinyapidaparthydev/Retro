nCr and Modular Inverse

NEXT

The problem they give you

They will not say “nCr and Modular Inverse.” They describe this:

Given: Many queries “n choose r”, n up to 10^6, answers modulo a prime.

Find: C(n, r) mod p without overflowing or using integer division.

Tiny example: C(5, 2) = 10. C(5, 2) mod 7 = 3. C(n, r) = 0 when r > n.

Name of the tool

nCr = n! / (r! (n-r)!). Mod a prime, divide by multiplying inv factorials. Precompute fact[i] and invFact[i] in O(N + log MOD).

Why this tool

Combinatorics interviews (unique paths, catalan, 'ways to choose k') become 'compute nCr mod p' the moment n is 10^6.

Approach

  1. Build fact and invFact up to the max n you need.
  2. C(n,r) as above, with n<r → 0 and negative → 0.
  3. For one-off C(n,r) with r small: ans=1; for i=1..r: ans = ans * (n-r+i) / i (exact in integers, or * inv(i) mod p).

Run it in JavaScript

Left is the snippet. Right is the console — one console.log at a time.

n! * inv(k!) * inv((n-k)!) mod p

const MOD = 13;

function modPow(a, e) {
  let r = 1;
  for (a %= MOD; e; e >>= 1, a = (a * a) % MOD) if (e & 1) r = (r * a) % MOD;
  return r;
}

const fact = [1];
for (let i = 1; i <= 8; i++) fact[i] = (fact[i - 1] * i) % MOD;
const inv = (x) => modPow(x, MOD - 2);

function nCr(n, k) {
  const v = (((fact[n] * inv(fact[k])) % MOD) * inv(fact[n - k])) % MOD;
  console.log("C(" + n + "," + k + ")", v);
  return v;
}

nCr(8, 3);
nCr(6, 2);
console.log("inv(2)", inv(2), "because 2*7=14≡1");

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • n choose r modulo 10^9+7, many queries.
  • Number of paths on an empty grid.
  • C(2n, n) / (n+1) modulo a prime.

You say this first

nCr = n! / (r! (n-r)!). Mod a prime, divide by multiplying inv factorials. Precompute fact[i] and invFact[i] in O(N + log MOD). I'd dry-run a tiny case first, then say the invariant and the complexity (O(N + log MOD) preprocess; O(1) per nCr time, O(N) space).

Offer the next notch: C(n,r) as above, with n<r → 0 and negative → 0.. Tradeoff: MOD is not prime and r! shares factors with MOD — Lucas / Chinese Remainder / no inverse. Say so. Unique Paths is C(n+m-2, n-1). If they add obstacles, that is DP, not one nCr.

More notes if you want them

Combinatorics interviews (unique paths, catalan, 'ways to choose k') become 'compute nCr mod p' the moment n is 10^6. If you multiply the formula naively you overflow and you cannot divide mod p with /. The factorial + inverse-factorial table is the standard package. When n is 10^18 and r is 10^6, use a multiplicative loop of r terms. When p is small, use Lucas.

Use when: Many nCr queries, Catalan, paths on a grid, 'choose k positions.'

Skip when: MOD is not prime and r! shares factors with MOD — Lucas / Chinese Remainder / no inverse. Say so.

Trap: Integer divide in the multiplicative formula without guaranteeing divisibility at each step (multiply then divide by i in order so it stays integral).
