The problem they give you

They will not say “XOR Tricks.” They describe this:

Given: An array where every value appears twice except one (or two), or 0..n with one missing.

Find: The leftover unique value(s), in linear time and constant extra space.

Tiny example: [4,1,2,1,2] → 4. [0,1,3] missing in 0..3 → 2.

Name of the tool

XOR is associative, commutative, and its own inverse. x^x=0, x^0=x. That is why XOR of a range finds the unique single number and why you can swap without a temp.

Why this tool

Single Number (every element twice except one) is the XOR interview.

Approach

  1. Single unique: acc=0; for x of a: acc^=x; return acc.
  2. Missing: acc = n; for i,x: acc ^= i^x.
  3. Two uniques: xor all, mask = xor & -xor, split XORs.

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Every number appears twice except one — find it without a hash set.
  • Two numbers appear once; the rest twice. Find both.
  • Find the missing number in 0..n.

You say this first

XOR is associative, commutative, and its own inverse. x^x=0, x^0=x. That is why XOR of a range finds the unique single number and why you can swap without a temp. I'd dry-run a tiny case first, then say the invariant and the complexity (O(n) time, O(1) space).

Offer the next notch: Missing: acc = n; for i,x: acc ^= i^x.. Tradeoff: You need the values that appeared an odd time when there are many — a map, or a bit-count array for 'all appear 3× except one.' Single Number II (triples): count bits mod 3, or a finite-state machine on bits. Mention both.

More notes if you want them

Single Number (every element twice except one) is the XOR interview. Single Number II/III, missing number, and 'find the extra character' are the family. If you reach for a hash set you pass, then they say O(1) space. XOR is the tool. You should also know you cannot recover two missing numbers with one XOR without a further partition on a differing bit.

Use when: Even-count cancellations, missing/extra in a permutation, partition by a bit.

Skip when: You need the values that appeared an odd time when there are many — a map, or a bit-count array for 'all appear 3× except one.'

Trap: Assuming XOR finds a duplicate (it finds a leftover parity, not a value that appeared twice).
