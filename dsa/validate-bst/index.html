Validate BST

CORE

The problem they give you

They will not say “Validate BST.” They describe this:

Given: A binary tree of numbers.

Find: Is every node in the left subtree < the node and every node on the right > the node — not just the two children?

Tiny example: 10 with left 5 and right 15, and 15 has left 6 → invalid (6 sits on the right of 10). 2 with left 1 and right 3 → valid.

Name of the tool

Every node must lie in (low, high) inherited from ancestors, or inorder must be strictly increasing. Checking only 'left < node < right' is not enough.

Why this tool

This is the classic trap.

Approach

  1. dfs(node, low, high): if !node return true.
  2. Or iterative inorder: if prev !== null && node.val <= prev.val return false; prev = node.val.

Validate BST

dfs(node, low, high): if !node return true. If node.val <= low or node.val >= high return false. Return dfs(left, low, node.val) && dfs(right, node.val, high).

Run it in JavaScript

Left is the snippet. Right is the console — one console.log at a time.

thread (lo, hi), not just kids

const n = (val, left = null, right = null) => ({ val, left, right });
const root = n(10, n(5), n(15, n(6), n(20)));

const ok = (node, lo = -Infinity, hi = Infinity) => {
  if (!node) return true;
  console.log(node.val, "in", [lo, hi]);
  if (node.val <= lo || node.val >= hi) return false;
  return ok(node.left, lo, node.val) && ok(node.right, node.val, hi);
};

console.log("valid?", ok(root));

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Is this a valid binary search tree?
  • Why is 'left child < node < right child' not enough?
  • Two nodes are swapped. Recover the tree.

You say this first

Every node must lie in (low, high) inherited from ancestors, or inorder must be strictly increasing. Checking only 'left < node < right' is not enough. I'd dry-run a tiny case first, then say the invariant and the complexity (O(n) time, O(h) space).

Offer the next notch: Or iterative inorder: if prev !== null && node.val <= prev.val return false; prev = node.val.. Tradeoff: The tree is a general binary tree and they asked something else (e.g. max path) — do not validate unless asked. Draw the 10 / 5 / 15 / 6 / 20 counterexample if they wonder why a local check fails.

More notes if you want them

This is the classic trap. A node can be greater than its parent and still violate a grandparent bound. Interviewers put a 5 under a 10 that sits on the left of a 6 and watch you return true. The fix is a range, or an inorder walk that remembers the previous value.

Use when: Verify the BST property after inserts, or as a gate before running a BST algorithm.

Skip when: The tree is a general binary tree and they asked something else (e.g. max path) — do not validate unless asked.

Trap: Only comparing a node to its children.
