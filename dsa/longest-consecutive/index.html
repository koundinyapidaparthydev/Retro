Longest Consecutive Sequence

CORE

The problem they give you

They will not say “Longest Consecutive Sequence.” They describe this:

Given: An unsorted list of integers. Order in the list does not matter. Duplicates do not extend a run.

Find: The length of the longest run of values that differ by 1 (like 1, 2, 3, 4). Faster than sorting if you can.

Tiny example: [100, 4, 200, 1, 3, 2] → 4, because 1, 2, 3, 4 all appear.

Name of the tool

Put all numbers in a set. Only start a streak from x when x−1 is missing, then walk x+1, x+2, … Each number is touched a constant number of times: O(n).

Why this tool

The O(n) constraint is the problem.

Approach

  1. const s = new Set(nums).
  2. For each x in s: if s.has(x-1) continue.
  3. Return ans (0 on empty).

Run it in JavaScript

Left is the snippet. Right is the console — one console.log at a time.

only start a run at the left edge

const nums = [100, 4, 200, 1, 3, 2];
const set = new Set(nums);
let best = 0;

for (const n of set) {
  if (set.has(n - 1)) continue;
  let len = 1;
  while (set.has(n + len)) len++;
  best = Math.max(best, len);
  console.log("start", n, "len", len);
}
console.log("best", best);

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Longest consecutive value run, ignoring array order.
  • You may not use extra memory. What is the honest bound?
  • Why is walking forward from every number too slow?

You say this first

Put all numbers in a set. Only start a streak from x when x−1 is missing, then walk x+1, x+2, … Each number is touched a constant number of times: O(n). I'd dry-run a tiny case first, then say the invariant and the complexity (O(n) expected time, O(n) space).

Offer the next notch: For each x in s: if s.has(x-1) continue. len = 1; while s.has(x+len) len++. ans = max(ans, len).. Tradeoff: You need the longest consecutive run in array order (that is a different, easier scan). Lead with sort in O(n log n), then 'I can do O(n) expected with a set if that is required.'

More notes if you want them

The O(n) constraint is the problem. Sorting is the honest O(n log n) solution and you should say so. The set-plus-start-of-run trick is what they want. It trains you to turn 'am I at the left edge of a run?' into a hash probe, which is a useful instinct for union-of-intervals style questions.

Use when: Longest run of consecutive values, order in the array ignored.

Skip when: You need the longest consecutive run in array order (that is a different, easier scan).

Trap: Walking from every x without the left-edge test.
