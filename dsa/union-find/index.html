Union-Find (Disjoint Set Union)

CORE

The problem they give you

They will not say “Union-Find (Disjoint Set Union).” They describe this:

Given: A stream of “these two people are in the same group” facts. Groups merge, they never split.

Find: After the facts, how many groups are left? Or: are Alice and Bob already in one group?

Tiny example: Merge 1-2, merge 3-4, merge 2-3. One group of four. 5 is still alone. Answer 2 groups.

Name of the tool

Circles of friends. union(a,b) means they become one circle. find(a) tells you which circle a is in.

Why this tool

Union-Find is a must-have.

Approach

  1. parent[i] = i, rank[i] = 0.
  2. find(x): if parent[x] !== x, parent[x] = find(parent[x]); return parent[x].
  3. union(a,b): ra=find(a), rb=find(b); if ra===rb return false.

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Number of friend circles / provinces.
  • Merge email accounts that share an address.
  • Which extra friendship would close a loop?

You say this first

Maintain a partition of elements under Union and Find. Path compression plus union by rank makes almost O(1) operations and powers Kruskal, components, and equality equations. I'd dry-run a tiny case first, then say the invariant and the complexity (α(n) amortized per op with both optimizations time, O(n) space).

Offer the next notch: find(x): if parent[x] !== x, parent[x] = find(parent[x]); return parent[x].. Tradeoff: Directed reachability — UF will happily merge against the arrow. Write find with compression even if you skip rank — still fine for n ≤ 10^5 in interviews. Rank is a plus.

More notes if you want them

Union-Find is a must-have. Number of provinces, accounts merge, redundant connection, equations possible, and Kruskal all collapse to it. Interviewers expect you to write parent[], find with path compression, and union by rank/size without looking it up. The mental model is 'named forests of trees,' not a graph search.

Use when: Dynamic connectivity, MST, grouping equals, merging accounts, redundant edges.

Skip when: Directed reachability — UF will happily merge against the arrow.

Trap: union without find — hanging mid-nodes and breaking representatives.
