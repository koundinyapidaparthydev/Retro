Binary Search

CORE

The problem they give you

They will not say “Binary Search.” They describe this:

Given: A sorted array. You may jump to any index in O(1).

Find: Does this number exist? If yes, at which index? Faster than checking every cell.

Tiny example: [1, 3, 5, 7, 9, 11, 13], find 9 → index 4 after three mid checks, not seven scans.

Name of the tool

If the list is sorted, keep asking “is the middle too small or too big?” and throw away half each time.

Why this tool

Binary search is the most common 'can you actually code' interview question that looks trivial and then eats twenty minutes.

Approach

  1. Confirm the array is sorted (or that your predicate is monotonic).
  2. Set lo = 0, hi = n - 1 (closed range) or hi = n (half-open).
  3. While the window is non-empty, compute mid = lo + Math.floor((hi - lo) / 2).

Run it in JavaScript

Left is the snippet. Right is the console — one console.log at a time.

find 9 in a sorted array

const nums = [1, 3, 5, 7, 9, 11, 13];
const target = 9;
let lo = 0, hi = nums.length - 1;

while (lo <= hi) {
  const mid = lo + Math.floor((hi - lo) / 2);
  console.log({ lo, mid, hi, v: nums[mid] });
  if (nums[mid] === target) break;
  if (nums[mid] < target) lo = mid + 1;
  else hi = mid - 1;
}

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Find a target in a sorted array in O(log n).
  • Return the first index of the target if it repeats.
  • The array is sorted, then rotated. Still log n.

You say this first

I'd confirm the array — or the predicate — is monotonic. Then binary search: lo, hi, mid = lo + (hi-lo)//2, throw away the half that cannot hold the answer. I say the invariant out loud: if the target exists it is still in [lo, hi].

Offer first/last occurrence (biased shrink), overflow-safe mid, and binary search on the answer if they switch to a feasibility check. Mention the infinite-loop when both bounds move to mid.

More notes if you want them

Binary search is the most common 'can you actually code' interview question that looks trivial and then eats twenty minutes. Interviewers are not testing whether you remember the name. They are testing whether you can keep an invariant, pick the right mid, and not infinite-loop when the window shrinks to one element. Once you own the template, a huge family of problems — first/last occurrence, rotated arrays, capacity problems, 'minimum k such that P(k)' — become the same loop with a different predicate.

Use when: Random-access sorted data and you need a single lookup in O(log n).

Skip when: The data is unsorted and you cannot sort it (sorting is O(n log n) plus you lose original indices unless you pair them).

Trap: Infinite loop from lo = mid when mid === lo on a two-element window.
