Next Greater Element

CORE

The problem they give you

They will not say “Next Greater Element.” They describe this:

Given: An array of temperatures (or prices). For each day you may look only to the right.

Find: For every index, the first later value that is strictly larger — or -1 if none exists.

Tiny example: [2, 1, 2, 4, 3] → [4, 2, 4, -1, -1].

Name of the tool

Scan left to right while a decreasing stack of indices waits. When the current value is larger, it is the next greater for every popped index.

Why this tool

Next greater (and next smaller, previous greater) is the monotonic-stack interview in its pure form.

Approach

  1. ans[i] = -1 for all i.
  2. For i in 0..n-1: while stack is nonempty and A[stack.top] < A[i], ans[stack.pop()] = A[i].
  3. Push i.

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Next warmer day for each temperature. Return the wait in days.
  • The array is circular — wrap once.
  • Now previous greater on the left as well.

You say this first

Scan left to right while a decreasing stack of indices waits. When the current value is larger, it is the next greater for every popped index. I'd dry-run a tiny case first, then say the invariant and the complexity (O(n) time, O(n) space).

Offer the next notch: For i in 0..n-1: while stack is nonempty and A[stack.top] < A[i], ans[stack.pop()] = A[i].. Tradeoff: You need the next greater that is also a specific distance away — maybe a different structure. Say 'each index is pushed and popped once' as the complexity proof.

More notes if you want them

Next greater (and next smaller, previous greater) is the monotonic-stack interview in its pure form. Daily temperatures, stock span, largest rectangle, and sliding-window extrema all reuse this loop. If you write a nested scan 'for each i, walk right until bigger,' you get O(n²) and a shrug. The stack makes each index push and pop at most once.

Use when: Next/previous greater or smaller for every index.

Skip when: You need the next greater that is also a specific distance away — maybe a different structure.

Trap: Using ≤ vs < incorrectly and skipping equal elements or infinite-looping on equals.
