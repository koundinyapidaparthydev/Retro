Lowest Common Ancestor

CORE
GooglehotMetaoftenTree interview closer.

The problem they give you

They will not say “Lowest Common Ancestor.” They describe this:

Given: A tree and two nodes p and q that exist in it.

Find: The deepest node that is an ancestor of both. A node is an ancestor of itself.

Tiny example: Root 3, left 5 (children 6 and 2), right 1. p=6, q=2 → 5. p=5, q=1 → 3.

Name of the tool

The deepest node that has both targets in its subtree. Binary tree: postorder report. BST: walk from the root using key order. Deep trees: binary lifting.

Why this tool

LCA is a core tree interview and a primitive for path queries (distance(u,v) = depth[u]+depth[v]-2depth[lca]).

Approach

  1. General tree: the postorder both-non-null rule above.
  2. BST: while node: if p.val < node.val && q.val < node.val, node = node.left; else if both greater, go right; else return node.
  3. With parent pointers: walk p to the root marking a set, walk q until you hit the set.

Run it in JavaScript

Left is the snippet. Right is the console — one console.log at a time.

BST walk until the keys split

const n = (val, left = null, right = null) => ({ val, left, right });
const root = n(6, n(2, n(0), n(4)), n(8));
const p = 0, q = 4;
let node = root;

while (node) {
  console.log("at", node.val);
  if (p < node.val && q < node.val) node = node.left;
  else if (p > node.val && q > node.val) node = node.right;
  else break;
}
console.log("lca", node.val);

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Lowest common ancestor in a binary tree.
  • The tree is a BST. Walk from the root using key order.
  • Distance between p and q via that ancestor.

You say this first

The deepest node that has both targets in its subtree. Binary tree: postorder report. BST: walk from the root using key order. Deep trees: binary lifting. I'd dry-run a tiny case first, then say the invariant and the complexity (O(n) single query on a binary tree; O(h) on a BST; O(n log n) preprocess + O(log n) or O(1) per query with lifting/RMQ time, O(h) or O(n log n) preprocess space).

Offer the next notch: BST: while node: if p.val < node.val && q.val < node.val, node = node.left; else if both greater, go right; else return node.. Tradeoff: Graphs with multiple paths — LCA is for trees (or DAGs with a defined ancestor poset, which is rarer). Ask if it is a BST and if both nodes are guaranteed present.

More notes if you want them

LCA is a core tree interview and a primitive for path queries (distance(u,v) = depth[u]+depth[v]-2depth[lca]). The binary-tree version tests recursion that returns a node or null. The BST version tests whether you use the search property. Advanced follow-ups (many queries) want preprocessing: Euler tour + RMQ, or binary lifting.

Use when: Path intersection, distance in a tree, subtree queries that need the join node.

Skip when: Graphs with multiple paths — LCA is for trees (or DAGs with a defined ancestor poset, which is rarer).

Trap: Returning root always because you only checked 'are both in the tree.'
