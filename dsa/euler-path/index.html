Euler Path and Circuit (Hierholzer)

ADV

The problem they give you

They will not say “Euler Path and Circuit (Hierholzer).” They describe this:

Given: Tickets (or roads) you must use. Each ticket is one flight from city A to city B.

Find: A walk that uses every ticket exactly once. Not “visit every city once” — leftover tickets fail.

Tiny example: Tickets JFK→ATL, ATL→JFK, JFK→SFO. Walk JFK, ATL, JFK, SFO uses all three.

Name of the tool

A trail that uses every edge once. Hierholzer: DFS-consume edges and append nodes on exit (postorder). Reverse the list for the path. Check degree conditions first.

Why this tool

Reconstruct Itinerary (tickets = directed edges) is the interview.

Approach

  1. Check degree conditions; choose start.
  2. Hierholzer(u): while u has unused edges: take the next edge u→v, delete it (and the reverse if undirected), Hierholzer(v).
  3. Reverse path.

Run it in JavaScript

Left is the snippet. Right is the console — one console.log at a time.

Hierholzer: eat unused outs, reverse finish

const g = { A: ["B"], B: ["C"], C: ["A", "D"], D: [] };
const circuit = [];

const dfs = (u) => {
  const outs = g[u] ?? [];
  while (outs.length) {
    const v = outs.pop();
    console.log("take", u, "→", v);
    dfs(v);
  }
  circuit.push(u);
};

dfs("A");
console.log("path", circuit.reverse());

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Reconstruct the itinerary. Prefer the alphabetically earliest next city.
  • Pairs (a,b) must be chained: the next pair starts where the last ended.
  • Two leftover unused tickets — the walk was not complete.

You say this first

A trail that uses every edge once. Hierholzer: DFS-consume edges and append nodes on exit (postorder). Reverse the list for the path. Check degree conditions first. I'd dry-run a tiny case first, then say the invariant and the complexity (O(E + V) plus sorting if lex is required time, O(E) space).

Offer the next notch: Hierholzer(u): while u has unused edges: take the next edge u→v, delete it (and the reverse if undirected), Hierholzer(v). Then path.push(u).. Tradeoff: Hamilton path (every vertex once) — NP-hard, not this linear algorithm. Reconstruct Itinerary: Hierholzer on a map of min-heaps of destinations, start at JFK, reverse the postorder.

More notes if you want them

Reconstruct Itinerary (tickets = directed edges) is the interview. People DFS-search permutations of tickets and TLE. Hierholzer is linear in the number of edges. You must know the degree conditions (0 or 2 odd degrees undirected; at most one start/end imbalance directed) and to sort edges if the problem wants the lexicographically smallest path.

Use when: Use every edge exactly once (itineraries, Chinese Postman on Eulerian graphs, reconstruct sequence from pairs).

Skip when: Hamilton path (every vertex once) — NP-hard, not this linear algorithm.

Trap: Preorder push — wrong splicing.
