The problem they give you

They will not say “Brian Kernighan's Trick.” They describe this:

Given: An integer n.

Find: Drop or isolate the lowest 1-bit so you can count ones or walk only the bits that are on.

Tiny example: 0b10110 → drop lowest 1 → 0b10100; isolate it → 0b00010. 8 is a power of two; 12 is not.

Name of the tool

n & (n-1) drops the lowest set bit. n & -n isolates it. Together they iterate, count, and test powers of two without scanning all 32 bits.

Why this tool

This one identity shows up everywhere: power-of-two tests, Fenwick index moves, iterating a mask's bits, and popcount.

Approach

  1. Count: while n: n&=n-1; c++.
  2. Iterate bits: while n: bit = n & -n; process(bit); n -= bit; (or n &= n-1).
  3. Fenwick: for (i+=i&-i) and for (i-=i&-i).

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Is n a power of two?
  • Count the 1-bits without scanning all 32 positions.
  • Walk only the bits that are set.

You say this first

n & (n-1) drops the lowest set bit. n & -n isolates it. Together they iterate, count, and test powers of two without scanning all 32 bits. I'd dry-run a tiny case first, then say the invariant and the complexity (O(number of set bits) time, O(1) space).

Offer the next notch: Iterate bits: while n: bit = n & -n; process(bit); n -= bit; (or n &= n-1).. Tradeoff: You need every bit position 0..31 regardless of set — a simple shift loop is clearer. Write n&(n-1) and say 'drops lowest set bit' in one breath.

More notes if you want them

This one identity shows up everywhere: power-of-two tests, Fenwick index moves, iterating a mask's bits, and popcount. Interviewers use 'is power of two' and 'count ones' as the door, then Fenwick as the house. If you write a 32-iteration loop they will ask you to do better on sparse masks.

Use when: Sparse bit iteration, popcount, power-of-two, Fenwick tree index math.

Skip when: You need every bit position 0..31 regardless of set — a simple shift loop is clearer.

Trap: n & -n in languages without two's complement wrap (JS 32-bit works; BigInt needs -n too).
