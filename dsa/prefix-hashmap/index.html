Prefix Sum plus Hash Map

CORE

The problem they give you

They will not say “Prefix Sum plus Hash Map.” They describe this:

Given: An array that may contain negatives, and a target k. You want contiguous stretches.

Find: How many subarrays add to exactly k? A window that only shrinks from the left will miss answers here.

Tiny example: [1, 2, 3], k = 3 → two stretches: [1, 2] and [3].

Name of the tool

A subarray sum equals k iff two prefixes differ by k. Store prefix frequencies (or latest indices) in a map and look up prefix − k as you scan.

Why this tool

This is the pattern that defeats 'sliding window on arrays with negatives.' Subarray sum equals k, contiguous array (equal 0s and 1s), max size subarr…

Approach

  1. map = {0: 1}, prefix = 0, ans = 0.
  2. For each x: prefix += x; ans += map.get(prefix - k) ??
  3. For longest: map = {0: -1} of first index; if prefix-k was seen, ans = max(ans, i - firstIndex).

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Count contiguous stretches whose sum is k.
  • Longest stretch with equally many zeros and ones.
  • Same question, but the stretch’s XOR equals k.

You say this first

A subarray sum equals k iff two prefixes differ by k. Store prefix frequencies (or latest indices) in a map and look up prefix − k as you scan. I'd dry-run a tiny case first, then say the invariant and the complexity (O(n) expected time, O(n) space).

Offer the next notch: For each x: prefix += x; ans += map.get(prefix - k) ?? 0; map.set(prefix, (map.get(prefix)??0)+1).. Tradeoff: Positive-only shortest subarray sum ≥ S — variable window is simpler and O(1) extra. Say 'I would window this if all positives; they are not, so prefix map.' That sentence scores.

More notes if you want them

This is the pattern that defeats 'sliding window on arrays with negatives.' Subarray sum equals k, contiguous array (equal 0s and 1s), max size subarray with sum k, and path-sum III are the same idea. If you try a variable window on negatives, it is wrong. If you brute all i,j it is O(n²). Prefix + map is O(n).

Use when: Contiguous subarray aggregates that are prefix-subtractable: sum, XOR, modular sum.

Skip when: Positive-only shortest subarray sum ≥ S — variable window is simpler and O(1) extra.

Trap: Forgetting the {0:1} seed.
