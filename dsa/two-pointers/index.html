Two Pointers

CORE

The problem they give you

They will not say “Two Pointers.” They describe this:

Given: A sorted array of numbers, and a target sum.

Find: Are there two different positions whose values add to the target? Do it in one pass, not every pair.

Tiny example: [1, 2, 4, 7, 11], target 11 → 4 + 7. You do not try 1+2, 1+4, 1+7…

Name of the tool

Put one finger on the left and one on the right, then move them toward each other instead of using two nested loops.

Why this tool

Two pointers is the first pattern that turns 'I would brute force pairs' into a linear pass.

Approach

  1. Name the invariant: what is true about A[0..i] and A[j..n), or about the two sequences.
  2. At each step, look at A[i] and A[j] (or the two heads) and decide exactly one move that cannot throw away a remaining answer.
  3. Advance that pointer; record a hit if the pair/window is valid.

Run it in JavaScript

Left is the snippet. Right is the console — one console.log at a time.

pair sum in a sorted array

const nums = [1, 2, 4, 7, 11];
const target = 11;
let L = 0, R = nums.length - 1;

while (L < R) {
  const sum = nums[L] + nums[R];
  console.log(`${nums[L]} + ${nums[R]} = ${sum}`);
  if (sum === target) break;
  if (sum > target) R--;
  else L++;
}

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Two numbers in a sorted array that add to target.
  • Do it in O(n) time and O(1) extra space.
  • Same idea, but three numbers (3-sum).

You say this first

Sorted, so I can put a finger on each end. Too big — move right left. Too small — move left right. One pass, no nested pair loop.

Three sum is sort + this for each i. If they unsort the array I hash instead. Say the invariant: everything left of L is too small to try again.

More notes if you want them

Two pointers is the first pattern that turns 'I would brute force pairs' into a linear pass. Pair-sum in a sorted array, removing duplicates in place, container-with-most-water, merging two sorted lists, partitioning around a pivot — they are the same idea with different move rules. Interviewers listen for whether you can say why a pointer only ever moves one way, because that is the proof you do not miss a pair.

Use when: Sorted arrays: 2-sum, 3-sum (fix one, two-pointer the rest), closest pair sum.

Skip when: Unsorted pair queries where you cannot sort (need original positions and O(n) time) — use a hash map.

Trap: Moving both pointers at once and skipping the pair that would have worked.
