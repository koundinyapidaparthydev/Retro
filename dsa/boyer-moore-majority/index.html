The problem they give you

They will not say “Boyer–Moore Majority Vote.” They describe this:

Given: An array of n values. One value may appear more than n/2 times.

Find: Return that majority value using only a few extra variables, not a frequency table. If a majority is not promised, say so.

Tiny example: [2, 2, 1, 1, 1, 2, 2] → 2 (it appears 4 times out of 7).

Why this tool

Approach

  1. cand=None, c=0.
  2. Optional: count cand; if count>n/2 return cand else none.
  3. n/3: two pairs, decrement both on a third value, then verify.

Boyer–Moore Majority Vote

cand=None, c=0. for x: if c==0 cand=x. c += (x==cand ? 1 : -1).

Run it in JavaScript

Left is the snippet. Right is the console — one console.log at a time.

one candidate, running vote

const nums = [3, 3, 4, 2, 3];
let cand = null, votes = 0;

for (const n of nums) {
  if (votes === 0) cand = n;
  votes += n === cand ? 1 : -1;
  console.log(n, "→ cand", cand, "votes", votes);
}
console.log("majority", cand);

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Find the value that appears more than half the time.
  • A majority is not guaranteed. What do you return?
  • Now find every value that appears more than n/3 times.

You say this first

If a value appears more than n/2 times, a cancel-pairs scan finds it: keep a candidate and a count, decrement on disagreement, switch when count hits 0. Verify in a second pass if the majority is not guaranteed. I'd dry-run a tiny case first, then say the invariant and the complexity (O(n) time, O(1) space).

Offer the next notch: Optional: count cand; if count>n/2 return cand else none.. Tradeoff: You need exact frequencies of everyone — hashmap / sort. Ask if a majority is guaranteed. If not, verify.

More notes if you want them

Majority Element is often solved with a hashmap. Boyer–Moore is the O(1)-space follow-up. The algorithm is not obvious and interviewers like the 'pairs of different elements cancel, the majority survives' picture. Majority II (n/3) uses two candidates. Do not skip the verify pass unless the problem guarantees a majority exists.

Use when: > n/2 (or n/3) majority in linear time and O(1) extra memory.

Skip when: You need exact frequencies of everyone — hashmap / sort.

Trap: Returning the candidate without verify on a no-majority instance.
