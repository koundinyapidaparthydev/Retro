Tree DP

ADV

The problem they give you

They will not say “Tree DP.” They describe this:

Given: Houses (or cameras, or distances) sit on a tree. A node’s answer comes from its children’s answers. No cycles.

Find: Best score at the root — or the score if every node were the root.

Tiny example: Tree 3 with children 2 and 3. Rob-the-root vs skip-root-and-rob-children. Take the better pair.

Name of the tool

Postorder: a node's answer from its children's answers. House Robber III, diameter, and rerooting (compute for every root in two DFS) are the templates.

Why this tool

Once the graph is a tree, DP is natural because removing a node splits independent subtrees.

Approach

  1. dfs(u, parent): for each child !== parent, collect dfs(child).
  2. Reroot: dfs2(u, parent, downFromParent): compute u's answer as if rooted at u, then recurse to children with the adjusted 'from parent' payload.

Run it in JavaScript

Left is the snippet. Right is the console — one console.log at a time.

house-robber on a tree: take node or kids

const tree = { val: 3, kids: [
  { val: 2, kids: [{ val: 3, kids: [] }] },
  { val: 3, kids: [{ val: 1, kids: [] }] },
]};

function rob(node) {
  if (!node.kids.length) {
    console.log("leaf", node.val, "take", node.val, "skip", 0);
    return [node.val, 0];
  }
  let take = node.val, skip = 0;
  for (const kid of node.kids) {
    const [t, s] = rob(kid);
    take += s;
    skip += Math.max(t, s);
  }
  console.log("node", node.val, "take", take, "skip", skip);
  return [take, skip];
}

const [t, s] = rob(tree);
console.log("best", Math.max(t, s));

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Max stash on a tree; parent and child cannot both be robbed.
  • Min cameras so every node is watched.
  • Sum of distances from every node to all others, without n walks.

You say this first

Postorder: a node's answer from its children's answers. House Robber III, diameter, and rerooting (compute for every root in two DFS) are the templates. I'd dry-run a tiny case first, then say the invariant and the complexity (O(n) or O(n · |state per node|) time, O(n) space).

Offer the next notch: Reroot: dfs2(u, parent, downFromParent): compute u's answer as if rooted at u, then recurse to children with the adjusted 'from parent' payload.. Tradeoff: General graphs with cycles — tree DP does not apply; you need different states (bitmask, SCC-DAG, etc.). House Robber III: return [rob, skip]. Cameras: return states covered / needs / has camera.

More notes if you want them

Once the graph is a tree, DP is natural because removing a node splits independent subtrees. Interviewers use House Robber III, binary tree cameras, and 'sum of distances in tree' (reroot). If you memoize a DAG of (node, parent-used), you are already doing tree DP even if you call it DFS+memo.

Use when: Optimal placement / independent set / distances on a tree.

Skip when: General graphs with cycles — tree DP does not apply; you need different states (bitmask, SCC-DAG, etc.).

Trap: Recursing to parent and infinite-looping on undirected trees.
