Definition

Kth Smallest in a BST

stack empty, cur = root. while true: while cur, push cur, cur = cur.left. cur = pop. k--; if k === 0 return cur.val. cur = cur.right.

Run it in JavaScript

Left is the snippet. Right is the console — one console.log at a time.

inorder with a stack, stop at k

const n = (val, left = null, right = null) => ({ val, left, right });
const root = n(5, n(3, n(2), n(4)), n(7));
const k = 3;
const stack = [];
let node = root, seen = 0;

while (node || stack.length) {
  while (node) { stack.push(node); node = node.left; }
  node = stack.pop();
  seen++;
  console.log("visit", node.val, "count", seen);
  if (seen === k) break;
  node = node.right;
}

They ask it like this

  • "Write iterative inorder. If they ask to do many queries, add sizes."
  • "Walk a tiny example, then code."

You say this first

Inorder is sorted, so the k-th visit is the answer. Stop early. With subtree sizes you can walk down in O(h). I'd dry-run a tiny case first, then say the invariant and the complexity (O(h + k) inorder; O(h) with sizes time, O(h) or O(1) Morris space).

Offer the next notch: Size-augmented: while node: L = size(node.left). if k === L+1 return node. if k <= L node = node.left; else k -= L+1; node = node.right.. Tradeoff: A general binary tree — inorder is not sorted; you would need a heap or a flatten+sort. Write iterative inorder. If they ask to do many queries, add sizes.

More notes if you want them

This is the standard 'use the BST property' follow-up after validate/inorder. The naive flatten-to-array is O(n) memory. The expected interview code is iterative inorder that decrements k and returns when k hits 0. The augmentation follow-up (each node stores subtree size) is how order-statistic trees work.

Use when: Order-statistic queries on a BST.

Skip when: A general binary tree — inorder is not sorted; you would need a heap or a flatten+sort.

Trap: Recursing the whole tree and indexing [k-1] — works, wastes time and space, and they may forbid it.
