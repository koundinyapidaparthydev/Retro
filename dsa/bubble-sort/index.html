Bubble Sort

CORE

Definition

Repeatedly swap adjacent out-of-order pairs so the largest remaining element 'bubbles' to the end each pass.

Why it exists

Nobody ships bubble sort, but interviewers still use it as a warmup to see whether you can reason about adjacent swaps, loop invariants, and early exit.

Approach

  1. For i from 0 to n-2, treat the end of the unsorted region as n-1-i.
  2. For j from 0 to n-2-i, if A[j] > A[j+1], swap them and mark that a swap happened.
  3. If a pass does zero swaps, the array is sorted — return.
Time O(n²) average and worst; O(n) best with a swap flagSpace O(1)

Run it in JavaScript

Left is the snippet. Right is the console — one console.log at a time.

adjacent swaps, last i already home

const a = [4, 2, 5, 1];
for (let end = a.length - 1; end > 0; end--) {
  let swapped = false;
  for (let i = 0; i < end; i++) {
    if (a[i] > a[i + 1]) {
      [a[i], a[i + 1]] = [a[i + 1], a[i]];
      swapped = true;
    }
  }
  console.log("pass", a.slice());
  if (!swapped) break;
}

You say this first

Repeatedly swap adjacent out-of-order pairs so the largest remaining element 'bubbles' to the end each pass. I'd dry-run a tiny case first, then say the invariant and the complexity (O(n²) average and worst; O(n) best with a swap flag time, O(1) space).

Offer the next notch: For j from 0 to n-2-i, if A[j] > A[j+1], swap them and mark that a swap happened.. Tradeoff: Trivial and in-place versus quadratic comparisons and swaps. Write the swap flag and state the invariant. That is the signal you understand it, not just the nested loops.

More notes if you want them

Nobody ships bubble sort, but interviewers still use it as a warmup to see whether you can reason about adjacent swaps, loop invariants, and early exit. It is also the simplest place to prove that a swap-based sort is at best O(n²) if you only look at neighbors. Once you can explain why the last i elements are already finished after pass i, you are ready for insertion and selection.

Use when: Teaching adjacent swaps and loop invariants.

Skip when: Any production n beyond a few dozen elements.

Trap: Inner loop running to n-1 after elements have already bubbled to the end — wasted work, still correct.
