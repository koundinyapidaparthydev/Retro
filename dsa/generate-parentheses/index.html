Generate Parentheses

CORE

The problem they give you

They will not say “Generate Parentheses.” They describe this:

Given: You have n pairs of parentheses. A prefix must never have more closers than openers.

Find: Every valid string of length 2n. Do not build invalids and filter.

Tiny example: n=2 → ()(), (()). Not )((), not (().

Name of the tool

Build a string of n pairs by adding '(' if you still have opens left and ')' if closes would not exceed opens. Catalan-many valid strings, no invalid ones generated.

Why this tool

This is the cleanest 'generate all valid structures' interview.

Approach

  1. dfs(path, open, close) with open/close = number used so far.
  2. If path.length === 2n, record path and return.
  3. If open < n, append '(', dfs(open+1, close), pop.

Run it in JavaScript

Left is the snippet. Right is the console — one console.log at a time.

open if leftover, close if it stays valid

function gen(open, close, s) {
  if (open === 0 && close === 0) {
    console.log(s);
    return;
  }
  if (open > 0) gen(open - 1, close, s + "(");
  if (close > open) gen(open, close - 1, s + ")");
}

I'd dry-run a tiny case first, then say the invariant and the complexity (O(n · C_n) to output all strings time, O(n) recursion plus output space).

Offer the next notch: If path.length === 2n, record path and return.. Tradeoff: You only need to validate one string — that is a counter or a stack, not generation. Do not generate invalids. Show the two guards.

More notes if you want them

This is the cleanest 'generate all valid structures' interview. The naive generate-all-2n-bit-strings-and-filter is correct and exponential in a worse way (you build invalids). The right DFS never goes invalid: you track how many opens remain and how many closes you are still allowed. It also introduces Catalan numbers, which interviewers like as a follow-up count.

Use when: Enumerate valid parentheses strings, mountain arrays of ±1, or other Catalan structures.

Skip when: You only need to validate one string — that is a counter or a stack, not generation.

Trap: Allowing close > open in a prefix — those strings can never be finished validly, but you still waste time if you only filter at the end.
