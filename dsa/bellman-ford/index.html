Bellman-Ford

NEXT

Definition

Relax every edge V−1 times. Handles negative weights and reports a negative cycle if the V-th pass still improves a reachable distance.

Why it exists

Bellman-Ford is the answer when Dijkstra's assumption fails, and the engine of 'cheapest path with at most k edges' (stop after k relax rounds).

Approach

  1. dist[s]=0, others ∞.
  2. Repeat V-1 times: for each edge u→v weight w, if dist[u]+w < dist[v], dist[v]=dist[u]+w (and parent[v]=u).
  3. One more pass: if any relax succeeds on a node you care about, report a negative cycle.
Time O(V E)Space O(V)

Run it in JavaScript

Left is the snippet. Right is the console — one console.log at a time.

relax every edge |V|-1 times

const nodes = ["A", "B", "C"];
const edges = [["A", "B", 4], ["A", "C", 1], ["C", "B", -2]];
const dist = { A: 0, B: Infinity, C: Infinity };

for (let i = 0; i < nodes.length - 1; i++) {
  for (const [u, v, w] of edges) {
    if (dist[u] + w < dist[v]) {
      dist[v] = dist[u] + w;
      console.log("relax", u, "→", v, "=", dist[v]);
    }
  }
}
console.log("dist", dist);

You say this first

Relax every edge V−1 times. Handles negative weights and reports a negative cycle if the V-th pass still improves a reachable distance. I'd dry-run a tiny case first, then say the invariant and the complexity (O(V E) time, O(V) space).

Offer the next notch: Repeat V-1 times: for each edge u→v weight w, if dist[u]+w < dist[v], dist[v]=dist[u]+w (and parent[v]=u).. Tradeoff: Non-negative weights — Dijkstra is faster. Arbitrage: log-transform rates so a profitable cycle is a negative cycle, then Bellman-Ford.

More notes if you want them

Bellman-Ford is the answer when Dijkstra's assumption fails, and the engine of 'cheapest path with at most k edges' (stop after k relax rounds). Interviewers use it for negative-cycle detection (arbitrage) and to see if you know why V−1 rounds suffice: a simple shortest path has at most V−1 edges.

Use when: Negative weights, negative-cycle detection, shortest path with a bound on edge count.

Skip when: Non-negative weights — Dijkstra is faster.

Trap: Relaxing in place for the k-stop problem and accidentally allowing more than k hops in one pass.
