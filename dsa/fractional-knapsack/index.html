Fractional Knapsack

CORE

Definition

Take items in decreasing value/weight ratio; the last item may be split. Greedy is optimal here and illegal in 0/1 knapsack.

Why it exists

This is the contrast case that makes 0/1 knapsack make sense.

Approach

  1. Sort items by v/w desc.
  2. ans=0.
  3. Return ans as a float.
Time O(n log n)Space O(1) besides sort

Run it in JavaScript

Left is the snippet. Right is the console — one console.log at a time.

value / weight, take a fraction of the last

const items = [
  { w: 10, v: 60 },
  { w: 20, v: 100 },
  { w: 30, v: 120 },
];
items.sort((a, b) => b.v / b.w - a.v / a.w);
let cap = 50, worth = 0;

for (const { w, v } of items) {
  const take = Math.min(w, cap);
  worth += (v / w) * take;
  cap -= take;
  console.log("take", take, "/", w, "ratio", v / w, "left", cap);
}
console.log("worth", worth);

You say this first

Take items in decreasing value/weight ratio; the last item may be split. Greedy is optimal here and illegal in 0/1 knapsack. I'd dry-run a tiny case first, then say the invariant and the complexity (O(n log n) time, O(1) besides sort space).

Offer the next notch: ans=0. for item: if w <= cap, take all, cap -= w, ans += v; else ans += v * (cap/w), break.. Tradeoff: 0/1 or integer copies — DP. Ask 'may I break an item?' If no, knapsack DP. If yes, this.

More notes if you want them

This is the contrast case that makes 0/1 knapsack make sense. Interviews (and some LLD/estimation talks) use 'you may take a fraction of an item' — gold dust, liquids, remaining capacity. If you apply the same ratio greedy to 0/1, they will hand you a counterexample. Knowing when the greedy is legal is the skill.

Use when: Divisible items, maximize value under a weight cap.

Skip when: 0/1 or integer copies — DP.

Trap: Integer division on the last fraction.
