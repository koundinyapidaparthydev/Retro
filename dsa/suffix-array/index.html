Suffix Array

ADV

The problem they give you

They will not say “Suffix Array.” They describe this:

Given: A fixed text you will query many times, or one string looking for repeats.

Find: All suffixes in sorted order (as start indices). Then find a pattern or the longest repeated substring.

Tiny example: "banana" — longest substring that appears twice is "ana".

Name of the tool

The sorted list of all suffixes of s, usually stored as starting indices. With LCP (Kasai), you get longest repeated substring and many comparison queries in log time…

Why this tool

Suffix arrays are the practical suffix structure in interviews/contests that will not ask you to build a suffix tree.

Approach

  1. Build SA (naive sort is OK for n ≤ a few thousand in an interview; mention doubling).
  2. Optional Kasai LCP.
  3. Queries: binary search SA, or read max LCP.

Run it in JavaScript

Left is the snippet. Right is the console — one console.log at a time.

sort every suffix, then the string is searchable

const s = "banana";
const sa = [...s.keys()].sort((i, j) => (s.slice(i) < s.slice(j) ? -1 : 1));

for (const i of sa) {
  console.log(i, s.slice(i));
}

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Find every occurrence of a pattern in a fixed document.
  • Longest substring that appears at least twice.
  • How many distinct substrings does this string have?

You say this first

The sorted list of all suffixes of s, usually stored as starting indices. With LCP (Kasai), you get longest repeated substring and many comparison queries in log time after n log n build. I'd dry-run a tiny case first, then say the invariant and the complexity (O(n log n) typical build; O(|P| log n) search time, O(n) space).

Offer the next notch: Optional Kasai LCP.. Tradeoff: Single short search — KMP. For longest duplicate, prefer binary search + rolling hash unless they named suffix arrays.

More notes if you want them

Suffix arrays are the practical suffix structure in interviews/contests that will not ask you to build a suffix tree. Longest duplicate substring can be 'binary search + Rabin–Karp' or 'suffix array + max LCP.' If a strong interviewer asks how a search engine finds all occurrences of a pattern in a static text, this is a correct answer: binary search the suffix array.

Use when: Static text, many pattern queries; longest repeated substring; distinct substring count.

Skip when: Single short search — KMP.

Trap: Storing suffix strings instead of indices.
