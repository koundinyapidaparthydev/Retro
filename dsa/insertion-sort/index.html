DSA/Sorting

Insertion Sort

CORE

The problem they give you

They will not say “Insertion Sort.” They describe this:

Given: A short array, or one that is already almost in order. Values can be treated as arriving one by one.

Find: Keep a growing sorted prefix and slide each new value left into its hole. Return the sorted array.

Tiny example: [3, 1, 2] → insert 1 before 3 → [1, 3, 2] → slide 2 between them → [1, 2, 3].

Name of the tool

Grow a sorted prefix by inserting A[i] leftward into its place. Fast on small and nearly sorted arrays; the inner loop of production sorts.

Why this tool

Insertion sort is the quadratic sort you should actually remember.

Approach

  1. For i from 1 to n-1, set key = A[i] and j = i - 1.
  2. While j >= 0 and A[j] > key, set A[j+1] = A[j] and j--.
  3. Write key into A[j+1].

const a = [4, 2, 5, 1];
for (let i = 1; i < a.length; i++) {
  const x = a[i];
  let j = i - 1;
  while (j >= 0 && a[j] > x) { a[j + 1] = a[j]; j--; }
  a[j + 1] = x;
  console.log("insert", x, "→", a.slice());
}

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Sort this nearly-sorted list.
  • Each item is at most k seats from home. How does the time change?
  • Do the same on a singly linked list.

You say this first

Grow a sorted prefix by inserting A[i] leftward into its place. Fast on small and nearly sorted arrays; the inner loop of production sorts. I'd dry-run a tiny case first, then say the invariant and the complexity (O(n + I) ≈ O(n) best, O(n²) average/worst time, O(1) space).

Offer the next notch: While j >= 0 and A[j] > key, set A[j+1] = A[j] and j--.. Tradeoff: Excellent constants and adaptivity versus quadratic worst case. If the prompt says 'almost sorted' or 'k-sorted' (each element at most k from home), insertion sort is O(nk) and a heap of size k is O(n log k).

More notes if you want them

Insertion sort is the quadratic sort you should actually remember. Library sorts (Timsort, introsort) switch to it for small partitions because the constants crush merge and quick at n ≲ 32. Interviews ask you to sort a nearly-sorted stream, to insert into a sorted list, or to explain why adaptive sorts win. The inversion-count view also connects it to 'how far from sorted is this array?'

Use when: n small (the cutoff inside Timsort / introsort).

Skip when: Large reversed or random arrays — use merge/quick/heap.

Trap: Copying A[j] to A[j+1] without saving key, then losing A[i].
