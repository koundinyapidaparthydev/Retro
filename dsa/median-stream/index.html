The problem they give you

They will not say “Median of a Stream.” They describe this:

Given: Numbers arrive one at a time. After each arrival you may be asked for the median so far.

Find: The median after each query: the middle value if the count is odd, the average of the two middles if even. Insert must stay fast.

Tiny example: Stream 1, then 2, then 3 → medians 1, 1.5, 2.

Name of the tool

Two heaps: a max-heap of the lower half and a min-heap of the upper half. Rebalance so sizes differ by at most one; the median is one of the roots or their average.

Why this tool

This is the two-heap design interview.

Approach

  1. low = max-heap, high = min-heap.
  2. add(x): if low is empty or x <= low.peek, low.push(x); else high.push(x).
  3. if low.size > high.size + 1, high.push(low.pop()).

Run it in JavaScript

Left is the snippet. Right is the console — one console.log at a time.

max-heap low + min-heap high, sizes off by ≤ 1

const low = [];  // max-heap of the lower half
const high = []; // min-heap of the upper half
const push = (h, x, max) => {
  h.push(x);
  h.sort(max ? (a, b) => b - a : (a, b) => a - b);
};
const pop = (h) => h.shift();
function add(x) {
  if (!low.length || x <= low[0]) push(low, x, true);
  else push(high, x, false);
  if (low.length > high.length + 1) push(high, pop(low), false);
  if (high.length > low.length) push(low, pop(high), true);
  const med = low.length > high.length ? low[0] : (low[0] + high[0]) / 2;
  console.log("add", x, "low", low.slice(), "high", high.slice(), "med", med);
}
add(1); add(2); add(3); add(0);

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Running median of a stream.
  • Even count: average the two middles. Integer division is a trap.
  • Now a sliding window of size k — you must also delete the aging value.

You say this first

Two heaps: a max-heap of the lower half and a min-heap of the upper half. Rebalance so sizes differ by at most one; the median is one of the roots or their average. I'd dry-run a tiny case first, then say the invariant and the complexity (O(log n) add; O(1) median time, O(n) space).

Offer the next notch: add(x): if low is empty or x <= low.peek, low.push(x); else high.push(x).. Tradeoff: You need every percentile — a histogram or a tree with sizes is better. Draw the two piles and the split. Then implement rebalance as its own function.

More notes if you want them

This is the two-heap design interview. A sorted list is O(n) insert. A balanced BST of all elements also works (and a follow-up if they allow it). The two-heap solution is the one they expect you to invent: lower half's maximum and upper half's minimum sit at the split. It generalizes to two heaps plus a lazy index for sliding-window medians.

Use when: Running median of a stream.

Skip when: You need every percentile — a histogram or a tree with sizes is better.

Trap: Both heaps min-heaps because the language defaulted — invert one comparator.
