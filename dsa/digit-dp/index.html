Digit DP

ADV

The problem they give you

They will not say “Digit DP.” They describe this:

Given: A range [L, R] too big to scan. You care about a digit rule: digit sum, unique digits, allowed digits.

Find: How many integers in the range obey the rule. Count up to R, subtract count up to L−1.

Tiny example: How many numbers ≤ 25 have digits that add to 4? 4, 13, 22. Answer 3.

Name of the tool

Count numbers ≤ N whose digits satisfy a property. DFS on (position, tight, leftover-state) with memo. Tight says you are still prefix-matching N.

Why this tool

Digit DP is how you answer 'how many numbers in [L, R] have digit-sum k / no repeated digits / are beautiful' without iterating the range.

Approach

  1. count(num): digits = decimal digits of num.
  2. Answer = count(R) - count(L-1), careful when L=0.
  3. Always implement count(N) on paper for N=20 before trusting the flags.

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Count numbers in [L, R] whose digits sum to k.
  • How many numbers ≤ N use only digits from a given set?
  • Leading zeros do not count as used digits.

You say this first

Count numbers ≤ N whose digits satisfy a property. DFS on (position, tight, leftover-state) with memo. Tight says you are still prefix-matching N. I'd dry-run a tiny case first, then say the invariant and the complexity (O(length × |state| × 10) time, same for the memo space).

Offer the next notch: Answer = count(R) - count(L-1), careful when L=0.. Tradeoff: The range is tiny — brute force. Numbers At Most N Given Digit Set is a gentle version (sometimes combinatorics without full digit DP).

More notes if you want them

Digit DP is how you answer 'how many numbers in [L, R] have digit-sum k / no repeated digits / are beautiful' without iterating the range. It shows up in harder interviews and contests. The tight flag is the idea: until you choose a digit smaller than the bound's digit, you are constrained; after that, later digits are free 0–9.

Use when: Count (or sum) of integers in a numeric range with digit constraints.

Skip when: The range is tiny — brute force.

Trap: Forgetting Count(L-1) or L=0.
