Bitmask DP

ADV

The problem they give you

They will not say “Bitmask DP.” They describe this:

Given: n ≤ 20 people, cities, or tasks. A subset fits in an integer of n bits.

Find: Best way to handle every subset: assign jobs, or a tour that visits each city once and returns.

Tiny example: 3 cities, start 0. Distances make 0-1-2-0 cheaper than 0-2-1-0. Try both tours; n=3 is 2 leftover orders.

Name of the tool

When n ≤ 20, a subset is an integer mask. dp[mask] (and maybe a location) iterates over bits to add one element. TSP, assignment, and 'smallest sufficient team' live here.

Why this tool

Bitmask DP is the CP/interview move when subsets are the state and n is tiny.

Approach

  1. n = nums.length; dp = Array(1<<n).fill(INF); dp[0]=0;
  2. for mask in 0..(1<<n)-1: for i in 0..n-1: if mask has i, relax dp[mask] from dp[mask without i].
  3. TSP: add a last-city index; from mask,i go to j not in mask.

Run it in JavaScript

Left is the snippet. Right is the console — one console.log at a time.

TSP: visit each city once, 4 nodes

const d = [
  [0, 10, 15, 20],
  [10, 0, 35, 25],
  [15, 35, 0, 30],
  [20, 25, 30, 0],
];
const n = 4, FULL = (1 << n) - 1;
const dp = Array.from({ length: 1 << n }, () => Array(n).fill(Infinity));
dp[1][0] = 0;

for (let mask = 1; mask <= FULL; mask++) {
  for (let u = 0; u < n; u++) {
    if (!(mask & (1 << u)) || dp[mask][u] === Infinity) continue;
    for (let v = 0; v < n; v++) {
      if (mask & (1 << v)) continue;
      const nxt = mask | (1 << v);
      dp[nxt][v] = Math.min(dp[nxt][v], dp[mask][u] + d[u][v]);
    }
  }
}

for (let u = 1; u < n; u++) {
  console.log("end at", u, "tour", dp[FULL][u] + d[u][0]);
}
console.log("best", Math.min(...dp[FULL].map((c, u) => c + d[u][0])));

You say this first

I'd dry-run a tiny case first, then say the invariant and the complexity (O(n 2^n) or O(n² 2^n) for TSP time, O(2^n) or O(n 2^n) space).

Offer the next notch: for mask in 0..(1<<n)-1: for i in 0..n-1: if mask has i, relax dp[mask] from dp[mask without i].. Tradeoff: n = 40 — meet-in-the-middle or a different DP. Say the n limit out loud. Then define mask.

More notes if you want them

Bitmask DP is the CP/interview move when subsets are the state and n is tiny. Travelling salesman (n≤16), assignment problem, and 'max score after n operations' (n pairs) are the usual prompts. If you try n! backtracking you TLE; if you try n=30 you need meet-in-the-middle. Knowing the size limit is part of knowing the technique.

Use when: n ≤ 20 subset states; TSP-like tours; pairing / assignment.

Skip when: n = 40 — meet-in-the-middle or a different DP.

Trap: Off-by-one in bit tests; using signed 32-bit for n=32 (use 64 or n≤20).
