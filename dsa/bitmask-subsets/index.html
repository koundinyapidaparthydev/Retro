The problem they give you

They will not say “Bitmask Subsets.” They describe this:

Given: A set of n items, n small (about 15–20).

Find: Visit every subset — or every split of a subset — as an integer mask.

Tiny example: {a,b,c} → 8 masks; 0b101 is {a,c}.

Name of the tool

Enumerate all 2^n subsets as integers 0..(1<<n)-1. Iterate set bits, walk submasks, and build next-masks. The implementation layer under bitmask DP.

Why this tool

If n is 15, a mask loop is cleaner than recursion.

Approach

  1. for mask in 0..(1<<n)-1: handle the subset { i | mask has bit i }.
  2. for i in 0..n-1: if (mask>>i)&1, use element i.

every mask from 0 to 2^n - 1

const items = ["a", "b", "c"];
const n = items.length;

for (let mask = 0; mask < 1 << n; mask++) {
  const sub = items.filter((_, i) => mask & (1 << i));
  console.log(mask.toString(2).padStart(n, "0"), sub);
}

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • List every subset of n items.
  • Split a chosen set into two groups — visit every split.
  • From a used-mask, try adding one unused item.

You say this first

Enumerate all 2^n subsets as integers 0..(1<<n)-1. Iterate set bits, walk submasks, and build next-masks. The implementation layer under bitmask DP. I'd dry-run a tiny case first, then say the invariant and the complexity (O(n 2^n) to visit every element of every subset; O(3^n) all submasks of all masks time, O(1) besides output space).

Offer the next notch: for i in 0..n-1: if (mask>>i)&1, use element i.. Tradeoff: n > 22 or so for 2^n, n > 15 for 3^n — will not run. If you write a recursive subset DFS and n is 16, they may ask you to rewrite it as a mask loop.

More notes if you want them

If n is 15, a mask loop is cleaner than recursion. Interviews (and contests) expect you to write `for (mask = 0; mask < (1<<n); mask++)` and then, inside, loop i where `(mask>>i)&1`. Submask enumeration (`for (sub=mask; sub; sub=(sub-1)&mask)`) is the 3^n trick for 'split this set.' This topic is how those loops work, not the DP recurrences themselves.

Use when: n ≤ 20 subset enumeration; transitions of bitmask DP; split a set into two labeled groups.

Skip when: n > 22 or so for 2^n, n > 15 for 3^n — will not run.

Trap: 1<<n when n=31 sign-flips in 32-bit; use 1<<n for n≤30 or 1n<<n.
