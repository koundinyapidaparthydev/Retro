Interpolation Search

ADV

Definition

Guess the probe index by assuming values are uniform between lo and hi, like looking up a name in a phone book by its first letter.

Why it exists

Interpolation search is the 'how would you search a phone book' answer taken literally.

Approach

  1. Require a sorted array of numeric keys.
  2. While lo <= hi and t is between A[lo] and A[hi], compute pos by interpolation.
  3. If A[pos] === t return pos.
Time O(log log n) expected on uniform data; O(n) worst caseSpace O(1)

Run it in JavaScript

Left is the snippet. Right is the console — one console.log at a time.

probe where 18 should sit

const nums = [10, 12, 16, 18, 22, 24, 33, 35, 42, 47];
const t = 18;
let lo = 0, hi = nums.length - 1;

while (lo <= hi && t >= nums[lo] && t <= nums[hi]) {
  const span = nums[hi] - nums[lo];
  const pos = lo + Math.floor(((t - nums[lo]) * (hi - lo)) / span);
  console.log({ lo, pos, hi, v: nums[pos] });
  if (nums[pos] === t) break;
  if (nums[pos] < t) lo = pos + 1;
  else hi = pos - 1;
}

You say this first

Guess the probe index by assuming values are uniform between lo and hi, like looking up a name in a phone book by its first letter. I'd dry-run a tiny case first, then say the invariant and the complexity (O(log log n) expected on uniform data; O(n) worst case time, O(1) space).

Offer the next notch: While lo <= hi and t is between A[lo] and A[hi], compute pos by interpolation. Clamp pos into [lo, hi].. Tradeoff: Faster expected probes on uniform data versus a fragile worst case and extra arithmetic. More notes if you want them

Interpolation search is the 'how would you search a phone book' answer taken literally. Interviews almost never require you to implement it, but they do ask how binary search can be improved when values are uniformly distributed. The answer is: estimate the position with a linear interpolation instead of always picking mid. You should also know the failure mode — adversarial or skewed data makes it O(n).

Use when: Large, uniformly distributed, sorted numeric keys with random access.

Skip when: Skewed, exponential, or adversarial key distributions.

Trap: Division by zero when A[hi] === A[lo].
