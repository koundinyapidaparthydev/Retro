Trie (Prefix Tree)

CORE
GooglehotMetaoftenAutocomplete, word search.

The problem they give you

They will not say “Trie (Prefix Tree).” They describe this:

Given: A dictionary of words. Callers will ask: is this whole word in the set? Does any word start with this prefix?

Find: insert, search, and startsWith, each in time proportional to the query length — not to how many words you stored.

Tiny example: insert 'app', insert 'apple'. search('app') → true if you marked it a word. startsWith('appl') → true. search('appl') → false.

Name of the tool

A tree of characters where each root-to-node path is a prefix. Insert, search, and startsWith are O(length), independent of how many words are stored — until the alphabet fans out.

Why this tool

Tries are the data-structure interview for strings: autocomplete, Word Search II, replace words, longest common prefix, XOR maximum pair (bit trie).

Approach

  1. Node: children[26] or Map, isWord flag, optional count.
  2. insert(word): cur = root; for ch of word, create child if missing, cur = child; cur.isWord = true.
  3. search / startsWith: walk; fail on missing child; search also checks isWord.

Run it in JavaScript

Left is the snippet. Right is the console — one console.log at a time.

nested objects, $ marks a word

const root = {};

const insert = (word) => {
  let node = root;
  for (const ch of word) {
    node[ch] ??= {};
    node = node[ch];
  }
  node.$ = true;
  console.log("insert", word);
};

const has = (word) => {
  let node = root;
  for (const ch of word) {
    node = node[ch];
    if (!node) return false;
  }
  return !!node.$;
};

insert("app");
insert("apple");
console.log("app?", has("app"));
console.log("ap?", has("ap"));
console.log("apple?", has("apple"));

More notes if you want them

Tries are the data-structure interview for strings: autocomplete, Word Search II, replace words, longest common prefix, XOR maximum pair (bit trie). If you only know hash sets, you cannot answer 'find all words with this prefix' without scanning everything. Implementing insert/search/startsWith (LeetCode 208) is the expected baseline.

Use when: Prefix queries, autocomplete, dictionary search on a grid, bitwise XOR tries.

Skip when: Exact lookups only — a hash set is simpler and usually faster.

Trap: Using isWord incorrectly so prefixes of words are reported as words (or the reverse).
