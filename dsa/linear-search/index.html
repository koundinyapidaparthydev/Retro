Linear Search

CORE

The problem they give you

They will not say “Linear Search.” They describe this:

Given: An unsorted list, or a stream you can only read forward. A target value, or a yes/no test.

Find: The first index that matches, or a miss. You cannot jump to the middle.

Tiny example: [4, 9, 1, 7, 2], find 7 → index 3. Find 8 → not found.

Name of the tool

Start at the first item and check one by one until you find what you want — or run out of items.

Why this tool

Linear search is the algorithm you already do by eye: start at the front, check each item.

Approach

  1. Walk index i from 0 to n - 1.
  2. If A[i] equals the target (or satisfies the predicate), return i immediately.
  3. If the loop finishes, return a miss sentinel such as -1.

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Find the first even number; return -1 if none.
  • Return the last occurrence, not the first.
  • The data is a linked list — you have no random index.

You say this first

Scan every element in order until you find the target or exhaust the collection. The baseline every other search is measured against. I'd dry-run a tiny case first, then say the invariant and the complexity (O(n) time, O(1) space).

Offer the next notch: If A[i] equals the target (or satisfies the predicate), return i immediately.. Tradeoff: Zero preprocessing and zero extra memory versus no asymptotic speedup. State the assumption: 'If this is unsorted I scan; if it is sorted I binary search.' That sentence is half the question.

More notes if you want them

Linear search is the algorithm you already do by eye: start at the front, check each item. Interviews rarely ask you to code it alone, but they expect you to know when it is the right tool — unsorted data, one-shot lookups, or streams you cannot index. More importantly, it is the mental default you must beat. If a problem looks like 'find X in a list,' your first question is whether the input is sorted or structured enough to do better than O(n).

Use when: The collection is unsorted and you will not search it again.

Skip when: The array is sorted — binary search is the default.

Trap: Off-by-one on empty arrays: the loop should simply not run and return miss.
