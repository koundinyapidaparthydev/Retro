Matrix Chain Multiplication

ADV

The problem they give you

They will not say “Matrix Chain Multiplication.” They describe this:

Given: A chain of matrices. (AB)C and A(BC) give the same product but different multiply counts.

Find: Minimum multiply cost. You choose where the last multiply sits.

Tiny example: 10×30, 30×5, 5×60. (AB)C costs 10·30·5 + 10·5·60 = 4500. A(BC) costs 30·5·60 + 10·30·60 = 27000. Best 4500.

Name of the tool

Interval DP: dp[i][j] is the min cost to multiply matrices i..j. Try every split k and add the cost of the final multiply.

Why this tool

Matrix chain is the cleanest interval DP.

Approach

  1. for len=2..n: for i=0..n-len: j=i+len-1; dp[i][j]=∞; for k=i..j-1: dp[i][j]=min(..., dp[i][k]+dp[k+1][j]+cost(i,k,j)).
  2. Return dp[0][n-1].

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Min cost to parenthesize the chain.
  • Print one best parenthesization.
  • Three matrices by hand, then code.

You say this first

Interval DP: dp[i][j] is the min cost to multiply matrices i..j. Try every split k and add the cost of the final multiply. I'd dry-run a tiny case first, then say the invariant and the complexity (O(n³) time, O(n²) space).

Offer the next notch: Return dp[0][n-1].. Tradeoff: You may merge any pair, not only adjacent — that is Huffman / greedy, not matrix chain. Draw three matrices 10×30, 30×5, 5×60 and compute both parenthesizations by hand, then code.

More notes if you want them

Matrix chain is the cleanest interval DP. Burst balloons, palindrome partitioning, and min-cost tree from leaves are the same 'try every last cut' shape. If you can write the length-outer, split-inner loops here, you can write those interviews. People who nest the loops in the wrong order use unready subintervals.

Use when: Optimal parenthesization; last-cut interval problems.

Skip when: You may merge any pair, not only adjacent — that is Huffman / greedy, not matrix chain.

Trap: Filling by i,j increasing instead of by length — reading uncomputed middles.
