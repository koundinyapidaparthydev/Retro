Fast and Slow Pointers

CORE

The problem they give you

They will not say “Fast and Slow Pointers.” They describe this:

Given: A singly linked list. You may not count the length first, and you get only a few extra pointers.

Find: Does the list loop back on itself? If so, where does the loop start? Or: which node is in the middle?

Tiny example: 1→2→3→4→5, and 5 points back to 3. There is a cycle; it starts at 3. Middle of 1→2→3→4→5 is 3.

Name of the tool

Advance one pointer twice as fast as the other on a linked structure. They meet on a cycle; the slow pointer is at the middle when the fast hits the end.

Why this tool

The Floyd cycle algorithm and 'middle of the list' are the two linked-list interviews you will get.

Approach

  1. Detection: init slow = fast = head.
  2. Entrance: after a meet, set ptr = head.
  3. Middle: while fast && fast.next, advance both.

Run it in JavaScript

Floyd cycle in a next[] list

const next = [1, 2, 3, 4, 2];
let slow = 0, fast = 0;

do {
  slow = next[slow];
  fast = next[next[fast]];
  console.log({ slow, fast });
} while (slow !== fast);

console.log("cycle meet at", slow);

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Does this linked list contain a cycle?
  • Return the node where the cycle begins.
  • Find the middle node, or the nth from the end, in one pass.

You say this first

Advance one pointer twice as fast as the other on a linked structure. They meet on a cycle; the slow pointer is at the middle when the fast hits the end. I'd dry-run a tiny case first, then say the invariant and the complexity (O(n) time, O(1) space).

Offer the next notch: Entrance: after a meet, set ptr = head. While ptr !== slow, ptr = ptr.next, slow = slow.next. Return ptr.. Tradeoff: You may mark nodes or use O(n) memory and the problem is not about O(1) space. For happy number, the 'next' function is sum of squares of digits. Same algorithm, no list.

More notes if you want them

The Floyd cycle algorithm and 'middle of the list' are the two linked-list interviews you will get. Fast-slow (tortoise and hare) solves both without a length counter or extra memory. Interviewers like it because the code is short and the proof is not obvious: why they meet, why resetting one pointer to the head finds the cycle entrance, why slow is at the middle. If you only memorize the snippet, the follow-up will catch you.

Use when: Cycle detection / entrance in a linked list or a functional graph (each node has outdegree 1, e.g. happy number).

Skip when: You may mark nodes or use O(n) memory and the problem is not about O(1) space.

Trap: Not checking fast.next before fast.next.next — null pointer on even lists.
