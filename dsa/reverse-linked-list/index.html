Reverse a Linked List

CORE
AmazonhotMetaoftenMicrosoftoftenList fluency check.

The problem they give you

They will not say “Reverse a Linked List.” They describe this:

Given: A singly linked list of nodes, each pointing only forward.

Find: The same nodes, reversed, in place. Return the new head.

Tiny example: 1→2→3→4 → 4→3→2→1. Empty list and a single node stay themselves.

Name of the tool

Rewire next pointers so a singly linked list runs backward. Iterative three-pointer reverse is the interview default; recursion is the follow-up.

Why this tool

If you cannot reverse a list you will fail every linked-list interview that follows: palindrome list, reverse-k-group, add two numbers in reverse, reorder list.

Approach

  1. Set prev = null, curr = head.
  2. While curr is not null: nxt = curr.next; curr.next = prev; prev = curr; curr = nxt.
  3. Return prev.

Run it in JavaScript

Left is the snippet. Right is the console — one console.log at a time.

prev / curr / nxt — flip next, slide the window

const n = (val, next = null) => ({ val, next });
let curr = n(1, n(2, n(3, n(4))));
let prev = null;
while (curr) {
  const nxt = curr.next;
  curr.next = prev;
  prev = curr;
  curr = nxt;
  console.log("head so far", prev.val, "rest", curr && curr.val);
}
const walk = [];
for (let p = prev; p; p = p.next) walk.push(p.val);
console.log("list", walk);

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Reverse the list. Return the new head.
  • Reverse only the slice from position left to right.
  • Reverse every group of k nodes.

You say this first

Rewire next pointers so a singly linked list runs backward. Iterative three-pointer reverse is the interview default; recursion is the follow-up. I'd dry-run a tiny case first, then say the invariant and the complexity (O(n) time, O(1) iterative; O(n) recursive stack space).

Offer the next notch: While curr is not null: nxt = curr.next; curr.next = prev; prev = curr; curr = nxt.. Tradeoff: You may rebuild a new list from an array — correct but not what they want if they asked for O(1) extra space. Draw three boxes and rewrite the pointers out loud once before coding. Then type the four-line loop.

More notes if you want them

If you cannot reverse a list you will fail every linked-list interview that follows: palindrome list, reverse-k-group, add two numbers in reverse, reorder list. The iterative version is also the cleanest demonstration of pointer rewiring — you hold prev, curr, next, and you never lose the rest of the list. Interviewers watch whether you handle empty lists, single nodes, and whether you return the new head.

Use when: Any problem that needs the list in the opposite order or a reversed slice.

Skip when: You may rebuild a new list from an array — correct but not what they want if they asked for O(1) extra space.

Trap: Losing nxt, then walking curr = curr.next after you already flipped next to prev — you bounce back and loop forever.
