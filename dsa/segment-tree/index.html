Segment Tree

ADV

The problem they give you

They will not say “Segment Tree.” They describe this:

Given: An array. You change single cells and ask range sums, mins, or gcds.

Find: Each update and each range answer in logarithmic time.

Tiny example: [1, 3, 5, 7], sum of [1, 2] = 8; set index 1 to 4; that sum becomes 9.

Name of the tool

A binary tree over array ranges. Each node stores an aggregate of [l,r]. Point update and range query are O(log n) by walking O(1) nodes per level.

Approach

  1. build(idx,l,r): if l==r tree[idx]=A[l]; else build children, tree[idx]=merge(left,right).
  2. query(idx,l,r,L,R): if no overlap return identity (0 for sum, +∞ for min); if fully covered return tree[idx]; else merge the two recursive queries.
  3. update(idx,l,r,pos,val): descend to the leaf, set, merge on the way up.

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Range sum or min after point updates.
  • Count of smaller numbers after self.
  • How many inversions?

You say this first

A binary tree over array ranges. Each node stores an aggregate of [l,r]. Point update and range query are O(log n) by walking O(1) nodes per level. I'd dry-run a tiny case first, then say the invariant and the complexity (O(n) build; O(log n) update/query time, O(n) space).

Offer the next notch: query(idx,l,r,L,R): if no overlap return identity (0 for sum, +∞ for min); if fully covered return tree[idx]; else merge the two recursive queries.. Tradeoff: Static range sum — prefix. Static range min — sparse table O(1). Ask what the merge is and whether updates are points or ranges.

More notes if you want them

Segment trees are the default 'I have range queries and updates' answer in contests and in harder interviews (Range Sum Query Mutable, range min, count of inversions with values compressed). If the array is static, a prefix or a sparse table is simpler. If you only add at prefixes, a Fenwick is less code. The segment tree is the one that generalizes to any mergeable monoid (sum, min, gcd, pair of top-two).

Use when: Range queries + point updates on an associative merge; more general than Fenwick.

Skip when: Static range sum — prefix. Static range min — sparse table O(1).

Trap: Identity of merge wrong (0 for min).
