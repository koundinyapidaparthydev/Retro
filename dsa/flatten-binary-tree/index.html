The problem they give you

They will not say “Flatten Binary Tree to Linked List.” They describe this:

Given: A binary tree. You must mutate it, not allocate a new list of nodes.

Find: A chain that uses only right pointers, in the original node-first order. Every left pointer is null.

Tiny example: 1 with left 2 (3, 4) and right 5 → 1→2→3→4→5, all lefts null.

Name of the tool

Rewrite the tree in place so it becomes a right-linked preorder list. Save the right child, attach the flattened left, then append the old right.

Why this tool

Listed separately because interviews often ask flatten on its own after invert.

Approach

  1. Recursive tail: see theory.
  2. Predecessor loop: while node: if left exists, find pred, pred.right = node.right, rotate left onto right, clear left.

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Flatten the tree to a right-linked list, in place.
  • A left-only chain — the nasty case. A right-only chain is already flat.
  • Do it with a few pointers and no recursion stack.

You say this first

Rewrite the tree in place so it becomes a right-linked preorder list. Save the right child, attach the flattened left, then append the old right. I'd dry-run a tiny case first, then say the invariant and the complexity (O(n) time, O(h) or O(1) space).

Offer the next notch: Predecessor loop: while node: if left exists, find pred, pred.right = node.right, rotate left onto right, clear left. Then node = node.right.. Tradeoff: You are allowed O(n) extra and they want simple code — collect then relink. Ask whether the list should be preorder (yes, in the standard problem).

More notes if you want them

Listed separately because interviews often ask flatten on its own after invert. The predecessor (Morris-style) solution is O(1) extra space and is a strong finish. Recursion that returns the tail of the flattened subtree is also clean and easier to get right than walking to the tail after the fact.

Use when: In-place preorder list rewrite.

Skip when: You are allowed O(n) extra and they want simple code — collect then relink.

Trap: Connecting tails incorrectly and dropping the right subtree.
