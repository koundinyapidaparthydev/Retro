First and Last Occurrence

NEXT

Definition

Two binary searches (lower and upper bound) that pin the leftmost and rightmost index of a target in a sorted array with duplicates.

Why it exists

Approach

  1. Write a lowerBound(t): while lo < hi, mid = floor((lo+hi)/2); if A[mid] < t then lo = mid + 1 else hi = mid.
  2. Write an upperBound(t): same loop but the test is A[mid] <= t then lo = mid + 1 else hi = mid.
  3. First index is lowerBound(t); accept it only if it is in range and A[i] === t.
Time O(log n)Space O(1)

Run it in JavaScript

Left is the snippet. Right is the console — one console.log at a time.

first and last 2

const nums = [1, 2, 2, 2, 5];
const t = 2;

function bound(wantLeft) {
  let lo = 0, hi = nums.length - 1, ans = -1;
  while (lo <= hi) {
    const mid = Math.floor((lo + hi) / 2);
    if (nums[mid] === t) {
      ans = mid;
      console.log(wantLeft ? "first" : "last", mid);
      if (wantLeft) hi = mid - 1;
      else lo = mid + 1;
    } else if (nums[mid] < t) lo = mid + 1;
    else hi = mid - 1;
  }
  return ans;
}

console.log({ first: bound(true), last: bound(false) });

More notes if you want them

The first follow-up after vanilla binary search is almost always 'the array has duplicates — find the first / last / count.' If your loop returns the first mid that equals the target, you have a random occurrence, not a bound. Interviewers use this to see whether you can bias the search left or right without breaking the invariant. The same template is lower_bound / upper_bound in C++ and the backbone of 'number of elements in [L, R].'

Use when: Sorted arrays with duplicates where you need a range, not a single hit.

Skip when: Unsorted data — bounds are meaningless without order.

Trap: Returning mid on equality and calling it 'first occurrence.'
