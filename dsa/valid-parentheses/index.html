Valid Parentheses

CORE

The problem they give you

They will not say “Valid Parentheses.” They describe this:

Given: A string of brackets: ( ) [ ] { }.

Find: Is every opener closed by the right type, in the right order?

Tiny example: ([{}]) is good. ([)] is not — they cross. (() is not — one left open.

Name of the tool

Push opening brackets; a closer must match the stack top. The stack is the unmatched prefix. Empty at the end means valid.

Why this tool

Valid parentheses is the first stack problem most people see and still shows up as a warmup or as the core of min-remove-to-valid, longest valid paren…

Approach

  1. Map )→(, ]→[, }→{.
  2. For each char: if it is an opener, push.
  3. After the scan, return whether the stack is empty.

Run it in JavaScript

Left is the snippet. Right is the console — one console.log at a time.

push openers; closer must match the top

const s = "([{}])";
const pair = { ")": "(", "]": "[", "}": "{" };
const st = [];
for (const ch of s) {
  if (!pair[ch]) { st.push(ch); console.log("push", ch, st.slice()); }
  else {
    const ok = st.pop() === pair[ch];
    console.log("pop for", ch, ok ? "match" : "fail", st.slice());
    if (!ok) break;
  }
}
console.log("valid", st.length === 0);

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Is this bracket string valid?
  • Longest valid parentheses substring.

You say this first

Push opening brackets; a closer must match the stack top. The stack is the unmatched prefix. Empty at the end means valid. I'd dry-run a tiny case first, then say the invariant and the complexity (O(n) time, O(n) space).

Offer the next notch: For each char: if it is an opener, push. If it is a closer, return false if the stack is empty or the top is not the matching opener; else pop.. Tradeoff: Only one bracket type and you only need a boolean — a counter is enough. Check empty before pop. That single guard is the usual crash.

More notes if you want them

Valid parentheses is the first stack problem most people see and still shows up as a warmup or as the core of min-remove-to-valid, longest valid parentheses, and score-of-parentheses. Interviewers want the map of close→open, early false on mismatch or leftover, and an empty-stack check before popping.

Use when: Check nesting of multiple bracket types.

Skip when: Only one bracket type and you only need a boolean — a counter is enough.

Trap: Treating counts of each type as sufficient (misses crossed pairs).
