The problem they give you

They will not say “Merge K Sorted Lists.” They describe this:

Given: k sorted linked lists. N nodes in total.

Find: One sorted list of all N nodes. Faster than folding them one list at a time (that costs O(Nk)).

Tiny example: [1→4→5], [1→3→4], [2→6] → 1→1→2→3→4→4→5→6.

Name of the tool

Merge k sorted linked lists using a min-heap of current heads, or by pairwise / tournament merging. O(N log k) instead of O(Nk).

Why this tool

This is the standard heap-plus-lists interview and the 'k-way merge' you will reuse for sorted arrays, files, and external sort.

Approach

  1. Push the head of every non-empty list into a min-heap keyed by val.
  2. Dummy/tail as in two-list merge.
  3. Return dummy.next.

Run it in JavaScript

Left is the snippet. Right is the console — one console.log at a time.

min-heap of current heads, then push the successor

const n = (val, next = null) => ({ val, next });
const vals = (h) => { const a = []; while (h) { a.push(h.val); h = h.next; } return a; };
const lists = [n(1, n(4)), n(2, n(3)), n(5)];
const heap = lists.filter(Boolean);
const dummy = n(0);
let tail = dummy;
while (heap.length) {
  heap.sort((x, y) => x.val - y.val);
  const node = heap.shift();
  tail.next = node;
  tail = node;
  if (node.next) heap.push(node.next);
  console.log("pop", node.val, "heads", heap.map((h) => h.val));
}
console.log("merged", vals(dummy.next));

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Merge k sorted lists.
  • N vs k: can you get O(N log k)?
  • Same idea for k sorted arrays: store (value, arrayId, index).

You say this first

Merge k sorted linked lists using a min-heap of current heads, or by pairwise / tournament merging. O(N log k) instead of O(Nk). I'd dry-run a tiny case first, then say the invariant and the complexity (O(N log k) time, O(k) for the heap (or O(log k) recursion for tournament merge) space).

Offer the next notch: Dummy/tail as in two-list merge. While the heap is non-empty, pop the min node, attach it to tail, and if node.next exists push node.next.. Tradeoff: Heap is simple and streaming-friendly; pairwise merge has better constants sometimes and no comparator objects. State N vs k. If you say O(N log N) they will ask you to do better.

More notes if you want them

This is the standard heap-plus-lists interview and the 'k-way merge' you will reuse for sorted arrays, files, and external sort. The naive 'merge list 1 into an accumulator, then list 2, …' is O(Nk). Interviewers want the log k improvement and a clear explanation of what the heap stores.

Use when: k sorted lists, files, or streams into one sorted output.

Skip when: k = 2 — just merge two lists.

Trap: Pushing all nodes of all lists into the heap at once — works but is O(N) memory and misses the k-head idea.
