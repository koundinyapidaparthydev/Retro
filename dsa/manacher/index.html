The problem they give you

They will not say “Manacher's Algorithm.” They describe this:

Given: A string.

Find: The longest contiguous palindrome — or the count of palindromic substrings.

Tiny example: "babad" → "bab" or "aba". "cbbd" → "bb".

Name of the tool

Longest palindromic substring in O(n). Mirror radii inside a current palindrome window, then expand only when the mirror does not pin the answer.

Why this tool

Manacher is the 'do LPS in linear time' flex.

Approach

  1. Build the separated string t.
  2. p array, c=0, r=0.
  3. Map the max radius back to s.

Run it in JavaScript

Left is the snippet. Right is the console — one console.log at a time.

odd palindromes: expand, then copy inside the box

const s = "abaaba";
const p = Array(s.length).fill(0);
let c = 0, r = 0;

for (let i = 0; i < s.length; i++) {
  const mirror = 2 * c - i;
  if (i < r) p[i] = Math.min(r - i, p[mirror]);
  while (s[i - p[i] - 1] && s[i - p[i] - 1] === s[i + p[i] + 1]) p[i]++;
  if (i + p[i] > r) {
    c = i;
    r = i + p[i];
  }
  console.log("center", i, s[i], "rad", p[i], "box", [c, r]);
}

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Longest palindromic substring.
  • How many palindromic substrings are there?
  • n is huge — faster than expanding around every center.

You say this first

Longest palindromic substring in O(n). Mirror radii inside a current palindrome window, then expand only when the mirror does not pin the answer. I'd dry-run a tiny case first, then say the invariant and the complexity (O(n) time, O(n) space).

Offer the next notch: p array, c=0, r=0. for i in 1..t.length-2: mirror=2c-i; if i<r p[i]=min(r-i, p[mirror]). while t[i-p[i]-1]==t[i+p[i]+1] p[i]++. if i+p[i]>r: c=i, r=i+p[i].. Tradeoff: n is small — expand-around-center is clearer. Offer expand-around-center first. Mention Manacher if they ask for linear.

More notes if you want them

Manacher is the 'do LPS in linear time' flex. Expand-around-center is O(n²) and enough for most interviews. If they forbid quadratic, or you are in a contest with n=10^6, this is the algorithm. The odd/even unification via separators (insert '#' between letters) is half the implementation.

Use when: Longest palindromic substring in linear time; count palindromic substrings in linear time.

Skip when: n is small — expand-around-center is clearer.

Trap: Off-by-one mapping from t's center/radius back to s.
