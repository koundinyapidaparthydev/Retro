Kruskal's MST

NEXT

Definition

Sort edges by weight, add an edge when it joins two components (Union-Find). The first V−1 accepted edges are a minimum spanning tree.

Why it exists

Kruskal is greedy + Union-Find.

Approach

  1. Sort edges by weight.
  2. For each edge u,v,w: if find(u)!=find(v), union, ans += w, taken++.
  3. If taken === V-1 return ans else impossible.
Time O(E log E)Space O(V)

Run it in JavaScript

Left is the snippet. Right is the console — one console.log at a time.

sort edges, union if they do not meet

const edges = [["A", "B", 1], ["B", "C", 2], ["A", "C", 4], ["C", "D", 1]];
edges.sort((a, b) => a[2] - b[2]);
const parent = { A: "A", B: "B", C: "C", D: "D" };
const find = (x) => (parent[x] === x ? x : (parent[x] = find(parent[x])));

for (const [u, v, w] of edges) {
  const a = find(u), b = find(v);
  if (a === b) { console.log("skip", u, v); continue; }
  parent[a] = b;
  console.log("take", u, v, w);
}

You say this first

Sort edges by weight, add an edge when it joins two components (Union-Find). The first V−1 accepted edges are a minimum spanning tree. I'd dry-run a tiny case first, then say the invariant and the complexity (O(E log E) time, O(V) space).

Offer the next notch: For each edge u,v,w: if find(u)!=find(v), union, ans += w, taken++.. Tradeoff: Directed graphs — MST is undirected; arborescences are a different algorithm (Edmonds). Min Cost to Connect All Points: generate all pairs as edges, then Kruskal. Mention Prim as an alternative.

More notes if you want them

Kruskal is greedy + Union-Find. Interviewers use 'min cost to connect all points' (complete graph of distances) and 'optimize water distribution' (a virtual well node). If you forget to skip edges inside a component, you build a cycle, not a tree. The cut proof is the same family as Prim.

Use when: Undirected MST / MSF, especially when you already have an edge list.

Skip when: Directed graphs — MST is undirected; arborescences are a different algorithm (Edmonds).

Trap: Not sorting.
