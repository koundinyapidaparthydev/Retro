Height and Diameter

CORE

The problem they give you

They will not say “Height and Diameter.” They describe this:

Given: A binary tree.

Find: The height (longest root-to-leaf). Also the longest path between any two nodes — it may not go through the root.

Tiny example: 1 with left 2 and right 3; 2 has left 4. Height 2 edges. Longest path 4–2–1–3 has length 3.

Name of the tool

Height is the longest root-to-leaf edge count (or node count — agree on the convention). Diameter is the longest path between any two nodes, computable in one DFS.

Why this tool

Height is the warmup; diameter is the real question.

Approach

  1. dfs(node): if null return -1 (edge height).
  2. For balanced: if |lh-rh| > 1 or either side returned 'unbalanced,' propagate unbalanced.
  3. On an undirected tree: BFS to farthest, BFS again.

Height and Diameter

dfs(node): if null return -1 (edge height). lh = dfs(left); rh = dfs(right). diameter = max(diameter, lh+rh+2). return 1+max(lh,rh).

Run it in JavaScript

Left is the snippet. Right is the console — one console.log at a time.

one postorder, height and diameter

const n = (val, left = null, right = null) => ({ val, left, right });
const root = n(1, n(2, n(4), n(5)), n(3));
let diameter = 0;

const height = (node) => {
  if (!node) return -1;
  const L = height(node.left);
  const R = height(node.right);
  diameter = Math.max(diameter, L + R + 2);
  console.log(node.val, { L, R, diameter });
  return 1 + Math.max(L, R);
};

height(root);

Whiteboard prompts

  • Maximum depth of the tree.
  • Longest path between any two nodes, in one walk.
  • Is the tree height-balanced? Return early on the first bad node.

You say this first

Height is the longest root-to-leaf edge count (or node count — agree on the convention). Diameter is the longest path between any two nodes, computable in one DFS. I'd dry-run a tiny case first, then say the invariant and the complexity (O(n) time, O(h) space).

Offer the next notch: For balanced: if |lh-rh| > 1 or either side returned 'unbalanced,' propagate unbalanced.. Tradeoff: Graphs with cycles — diameter of a general graph is APSP, not this. Ask whether height is in nodes or edges. Then write the null base case to match.

More notes if you want them

Height is the warmup; diameter is the real question. The naive 'diameter = max height(left)+height(right) at every node, each height is a separate DFS' is O(n²). The expected solution returns height from a single postorder and updates a global (or boxed) diameter along the way. Balanced-tree checks are the same postorder returning height or -1 on imbalance.

Use when: Any 'longest path in a tree,' balanced check, or subtree height.

Skip when: Graphs with cycles — diameter of a general graph is APSP, not this.

Trap: Returning only the through-root path.
