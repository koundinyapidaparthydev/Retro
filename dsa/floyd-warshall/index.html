The problem they give you

They will not say “Floyd-Warshall.” They describe this:

Given: A small map (dozens of cities). You need a fare between every pair, not one trip.

Find: Cheapest i→j for all i,j. A hop through another city can beat a direct flight.

Tiny example: A-B=3, B-C=1, A-C=10. After allowing B as a stop, A to C is 4.

Name of the tool

Triple loop: try each intermediate k, then i, j. dp[i][j] = min(dp[i][j], dp[i][k]+dp[k][j]). All-pairs shortest paths including negatives (no negative cycles).

Why this tool

When V is small (≤ 400) and you need every pair, Floyd is the algorithm you can write in six lines.

Approach

  1. Fill dp with ∞, 0 on diagonal, edges.
  2. for k in 0..n-1: for i: for j: if dp[i][k]+dp[k][j] < dp[i][j] update.
  3. Watch ∞+x overflow; only add when both sides are finite.

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • For each city, how many others are within a distance threshold?
  • Can every city reach every other (ignore weights, only yes/no)?
  • A city with a negative loop back to itself — report it.

You say this first

Triple loop: try each intermediate k, then i, j. dp[i][j] = min(dp[i][j], dp[i][k]+dp[k][j]). All-pairs shortest paths including negatives (no negative cycles). I'd dry-run a tiny case first, then say the invariant and the complexity (O(V³) time, O(V²) space).

Offer the next notch: for k in 0..n-1: for i: for j: if dp[i][k]+dp[k][j] < dp[i][j] update.. Tradeoff: Single source, large sparse graph — Dijkstra / Bellman-Ford. Say 'k is the outermost loop' before you type. That is the usual bug they look for.

More notes if you want them

When V is small (≤ 400) and you need every pair, Floyd is the algorithm you can write in six lines. Find the City With the Smallest Number of Neighbors, course-like reachability with weights, and transitive closure (OR instead of min-plus) are the interviews. People who launch V Dijkstras on a dense graph write more and gain little.

Use when: All-pairs on small V, possibly negative weights, or transitive closure.

Skip when: Single source, large sparse graph — Dijkstra / Bellman-Ford.

Trap: k not outermost.
