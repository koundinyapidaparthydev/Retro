The problem they give you

They will not say “Interval DP.” They describe this:

Given: A segment (subarray, substring, stick). The last action splits it at some k. Smaller segments are already scored.

Find: Best score of the whole segment. Fill short segments before long ones.

Tiny example: Cut a stick of length 7 at 1 and 3 and 5. Cost of a cut is the current piece length. Min total depends on cut order.

Name of the tool

dp[l][r] depends on smaller intervals. Enumerate length, then l, then a split. Matrix chain, burst balloons, palindrome cuts, and stone games share this loop nest.

Why this tool

Interval DP is a pattern name you should say in interviews.

Approach

  1. Write dp[l][r] meaning.
  2. Triple loop: length, l, split k.
  3. Answer is dp[0][n-1] (or the padded variant).

Whiteboard prompts

  • Min cost to cut a stick.
  • Stone piles in a row: last merge of two adjacent heaps.
  • Palindrome cuts and balloon bursts are this shape.

You say this first

dp[l][r] depends on smaller intervals. Enumerate length, then l, then a split. Matrix chain, burst balloons, palindrome cuts, and stone games share this loop nest. I'd dry-run a tiny case first, then say the invariant and the complexity (O(n³) typical, sometimes O(n²) if the split is fixed or Knuth-optimized time, O(n²) space).

Offer the next notch: Triple loop: length, l, split k.. Tradeoff: Merges of arbitrary pairs — Huffman. Name the pattern, then specialize to the problem's last action.

More notes if you want them

Interval DP is a pattern name you should say in interviews. Once the state is 'this subarray / this substring,' and the last action splits it, you are here. The skill is proving that smaller intervals do not depend on larger ones, then filling by length. Wrong loop order is the silent bug.

Use when: Optimal score / cost on a subarray with a last-split structure.

Skip when: Merges of arbitrary pairs — Huffman.

Trap: Using uncomputed longer intervals.
