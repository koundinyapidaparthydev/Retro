Set, Unset, and Toggle Bits

CORE

The problem they give you

They will not say “Set, Unset, and Toggle Bits.” They describe this:

Given: An integer n and a bit index k (LSB is 0).

Find: Turn bit k on, off, or flip it, without touching the other bits.

Tiny example: n=5 (101), k=1 → set 7 (111), clear 5 (101), toggle 7 (111).

Name of the tool

OR with a shifted 1 to set, AND with its complement to clear, XOR to flip. Masks are how you treat an integer as a small set or a packed flag word.

Why this tool

Every later bit trick assumes you can turn a bit on, off, or over without touching neighbors.

Approach

  1. Decide 0-based k from the right (LSB is 0) unless the problem says otherwise.
  2. Build mask = 1 << k (watch the type).
  3. Apply |, &, ~, ^ as required.

Run it in JavaScript

Left is the snippet. Right is the console — one console.log at a time.

OR sets, AND-NOT clears, XOR flips

let n = 0b0101;
console.log("start", n.toString(2).padStart(4, "0"));

n |= 1 << 1;
console.log("set bit1", n.toString(2).padStart(4, "0"));

n &= ~(1 << 2);
console.log("clear bit2", n.toString(2).padStart(4, "0"));

n ^= 1 << 0;
console.log("toggle bit0", n.toString(2).padStart(4, "0"));

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Set, clear, or flip bit k.
  • Is bit k on?
  • Pack a handful of flags into one word.

You say this first

OR with a shifted 1 to set, AND with its complement to clear, XOR to flip. Masks are how you treat an integer as a small set or a packed flag word. I'd dry-run a tiny case first, then say the invariant and the complexity (O(1) time, O(1) space).

Offer the next notch: Build mask = 1 << k (watch the type).. Tradeoff: You need an actual set of large integers — a hash set, not a 32-bit word. Say 'LSB is bit 0' before shifting. Draw an 8-bit example.

More notes if you want them

Every later bit trick assumes you can turn a bit on, off, or over without touching neighbors. Interviews start here on 'single number' warmups and on status-flag questions. If you write `n += 1<<k` to set a bit you will corrupt already-set bits. The mask `1<<k` (or `1n<<k` for 64-bit in JS) is the primitive.

Use when: Flags, packed fields, small-set representations, interview 'manipulate bit k.'

Skip when: You need an actual set of large integers — a hash set, not a 32-bit word.

Trap: 1<<k when k≥32 in 32-bit land.
