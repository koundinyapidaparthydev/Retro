const nums = [4, 1, 4, 2, 4];
const freq = new Map();

for (const n of nums) {
  freq.set(n, (freq.get(n) ?? 0) + 1);
  console.log(n, "→", freq.get(n));
}
console.log("4 appears", freq.get(4));

You say this first

Count occurrences in a hashmap (or an array if the alphabet is tiny). The first pass that turns 'is there a duplicate / anagram / majority' into O(n). I'd dry-run a tiny case first, then say the invariant and the complexity (O(n) expected to build time, O(distinct keys) space).

Offer the next notch: For a fixed alphabet, const a = new Array(26).fill(0); a[ch.charCodeAt(0)-97]++.. Tradeoff: You need order of first occurrence and nothing else — a set plus a list, or an ordered map. If the alphabet is 26, use an array. Say why.

More notes if you want them

A huge fraction of 'easy' and 'medium' array/string problems are frequency maps in disguise: anagrams, top-k frequent, majority, isomorphic strings, hand of straights. If your instinct is sort-and-scan, you are often one map away from linear time. Interviewers also use this to see if you pick an array[256] vs a hashmap vs a sort.

Use when: Counts, anagrams, majority, 'can I build this from that multiset.'

Skip when: You need order of first occurrence and nothing else — a set plus a list, or an ordered map.

Trap: Comparing maps by reference, not by counts.
