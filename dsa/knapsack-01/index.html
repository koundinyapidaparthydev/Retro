0/1 Knapsack

CORE

The problem they give you

They will not say “0/1 Knapsack.” They describe this:

Given: Items with a weight and a value. A bag with a weight cap. Each item at most once.

Find: The best total value that still fits.

Tiny example: Weights [1,2,3], values [6,10,12], cap 5 → take 2 and 3 = 22, not all three.

Name of the tool

A backpack that can take each item at most once. For every item you ask: take it, or skip it, and remember the best leftover capacity.

Approach

  1. dp = array(W+1, 0).
  2. Return dp[W].

Run it in JavaScript

Left is the snippet. Right is the console — one console.log at a time.

each item once: take or leave

const w = [2, 3, 3], v = [3, 4, 5], cap = 6;
const dp = Array(cap + 1).fill(0);

for (let i = 0; i < w.length; i++) {
  for (let c = cap; c >= w[i]; c--) {
    dp[c] = Math.max(dp[c], dp[c - w[i]] + v[i]);
  }
  console.log("after item", i, "w" + w[i], "dp", [...dp]);
}
console.log("best", dp[cap]);

You say this first

0/1 knapsack: each item at most once. dp[c] is best value with capacity c. For each item I walk capacity backward so I do not reuse it in the same pass. Answer is dp[W].

Say 'backward loop' so they know it is not unbounded. Partition equal subset is this table with boolean OR. If they allow repeats, that is unbounded / coin change — forward loop.

More notes if you want them

0/1 knapsack is the DP that everything else is 'like.' Partition equal subset sum, last stone weight II, target sum, and many 'pick a subset with a budget' problems are this table. If you iterate capacity forward on a 1-D array, you accidentally allow unlimited copies — that is the other knapsack. Interviewers listen for that backward loop.

Use when: Subset of items, each at most once, maximize value under a weight cap (or hit an exact sum).

Skip when: Items may be taken many times — unbounded knapsack / coin change.

Trap: Forward 1-D loop (unbounded).
