Rotate Array

CORE

The problem they give you

They will not say “Rotate Array.” They describe this:

Given: An array of n numbers and an integer k. k may be larger than n.

Find: Move every value k steps to the right, wrapping the overflow to the front. Prefer little extra memory.

Tiny example: [1, 2, 3, 4, 5, 6, 7], k = 3 → [5, 6, 7, 1, 2, 3, 4].

Name of the tool

Rotate right by k with three reversals: reverse all, reverse the first k, reverse the rest. O(n) time, O(1) extra. Know the extra-array version too.

Why this tool

Rotate is a favorite in-place array interview.

Approach

  1. k %= n.
  2. reverse(l,r): while l<r swap A[l++], A[r--].

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Rotate the array right by k in place.
  • What if k is a billion?
  • Now rotate a square image 90° clockwise.

You say this first

Rotate right by k with three reversals: reverse all, reverse the first k, reverse the rest. O(n) time, O(1) extra. Know the extra-array version too. I'd dry-run a tiny case first, then say the invariant and the complexity (O(n) time, O(1) reversal or cycle; O(n) buffer space).

Offer the next notch: reverse(l,r): while l<r swap A[l++], A[r--].. Tradeoff: You may allocate — extra array is simpler and fine. Ask left vs right and whether k can exceed n (always k%=n, n=0 guard).

More notes if you want them

Rotate is a favorite in-place array interview. The reversal trick is the one they want after you mention the extra buffer. Cycle-following (put A[i] into (i+k)%n, chase) is also O(1) extra and a bit more fiddly. Related: rotate image (layer swaps or transpose+reverse) and spiral are the 2-D cluster.

Use when: In-place rotation of a 1-D array; building block for some in-place shuffles.

Skip when: You may allocate — extra array is simpler and fine.

Trap: Forgetting k %= n.
