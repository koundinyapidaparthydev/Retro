The problem they give you

They will not say “Monotonic Queue.” They describe this:

Given: A stream of numbers and a window width k. You need the window extreme after every arrival.

Find: The max (or min) of the last k values, in total linear time — not a heap per window.

Tiny example: [1, 3, -1, -3, 5], k=3 → window maxima 3, 3, 5.

Name of the tool

A deque kept decreasing (or increasing) so the front is the current window's max (or min). Push at the back with evictions; pop the front when it leaves the window.

Why this tool

Sliding window maximum is the textbook monotonic-queue problem.

Approach

  1. deque empty.
  2. While deque is nonempty and A[deque.back] <= A[i], pop back.
  3. Push i.

Run it in JavaScript

Left is the snippet. Right is the console — one console.log at a time.

decreasing deque; front is the window max

const a = [1, 3, -1, -3, 5];
const k = 3;
const dq = [];
for (let i = 0; i < a.length; i++) {
  while (dq.length && a[dq[dq.length - 1]] <= a[i]) dq.pop();
  dq.push(i);
  if (dq[0] <= i - k) dq.shift();
  if (i >= k - 1) console.log("window", a.slice(i - k + 1, i + 1), "max", a[dq[0]]);
}

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Max of the last k measurements, online.
  • Longest stretch whose max − min is at most limit.
  • DP of the form dp[i] = A[i] + max(dp[i-k..i-1]).

You say this first

A deque kept decreasing (or increasing) so the front is the current window's max (or min). Push at the back with evictions; pop the front when it leaves the window. I'd dry-run a tiny case first, then say the invariant and the complexity (O(n) — each index enters and leaves the deque once time, O(k) space).

Offer the next notch: While deque is nonempty and A[deque.back] <= A[i], pop back.. Tradeoff: You need the full sorted window — use a multiset / two heaps. Name it 'decreasing deque of indices.' Then write the three while/push lines.

More notes if you want them

Sliding window maximum is the textbook monotonic-queue problem. A heap of window values is O(n log n) and needs lazy deletion. The deque is O(n). You will also use this for DP optimizations (sliding-window maximum of dp[i-k..i-1]) that interviewers call 'monotonic queue optimization' on harder rounds.

Use when: Min or max of every window of size k.

Skip when: You need the full sorted window — use a multiset / two heaps.

Trap: Storing values and then not knowing when the front left the window.
