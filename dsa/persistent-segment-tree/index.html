Persistent Segment Tree

ADV

The problem they give you

They will not say “Persistent Segment Tree.” They describe this:

Given: An array and queries on historical prefixes — k-th smallest in A[L..R].

Find: Answer as if every past version of the structure were still around.

Tiny example: A=[2, 1, 3, 1], 2nd smallest in [2, 4] (values 1, 3, 1) → 1.

Name of the tool

Each update allocates O(log n) new nodes along the path and reuses the rest. You keep a root per version and query any historical snapshot in O(log n).

Why this tool

Approach

  1. Node {left, right, sum}.
  2. roots[0] = empty tree.
  3. kth(L,R,k): walk(roots[R], roots[L-1], domain, k) choosing the side by left-frequency difference.

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • k-th smallest value in subarray [L, R].
  • How many values in [L, R] are ≤ X?
  • Query an older snapshot after later updates.

You say this first

Each update allocates O(log n) new nodes along the path and reuses the rest. You keep a root per version and query any historical snapshot in O(log n). I'd dry-run a tiny case first, then say the invariant and the complexity (O(n log n) build of n versions; O(log n) query time, O(n log n) space).

Offer the next notch: roots[0] = empty tree. roots[i] = update(roots[i-1], A[i]).. Tradeoff: No versioning needed — ordinary segment tree / Fenwick. Kth in [L,R]: name persistent Fenwick/segment tree or merge-sort tree. Sketch versions as prefixes.

More notes if you want them

Persistence is how you answer 'kth smallest on subarray [L,R]' (a classic hard): build a persistent frequency tree, adding A[i] as version i, then walk version R vs version L-1 for the kth. Interviewers at strong companies and CP rounds expect the idea even if they accept a merge-sort tree. You should not start this from zero on a 30-minute easy screen.

Use when: Queries on historical versions; kth in subarray; persistent frequency maps.

Skip when: No versioning needed — ordinary segment tree / Fenwick.

Trap: Mutating an old node instead of copying — versions corrupt each other.
