Cycle Detection in Undirected Graphs

CORE

The problem they give you

They will not say “Cycle Detection in Undirected Graphs.” They describe this:

Given: Towns linked by two-way roads. You get the road list.

Find: Is there a loop — a walk that returns home without retracing the same road as its only option?

Tiny example: 1-2, 2-3, 3-1. Yes, a triangle. 1-2, 2-3, 3-4. No loop.

Name of the tool

DFS: a visited neighbor that is not your parent is a cycle. Union-Find: if two ends of an edge are already in the same component, that edge closes a cycle.

Why this tool

Undirected cycle detection is how you know a graph is a tree (connected + acyclic) and how Kruskal rejects edges.

Approach

  1. DFS: for each unseen u, dfs(u, parent=-1).
  2. UF: for each edge (u,v): if find(u)==find(v) return that edge; else union(u,v).

Cycle Detection in Undirected Graphs

DFS: for each unseen u, dfs(u, parent=-1). Inside, for each v, if !seen[v] dfs(v,u); else if v !== parent return true.

Run it in JavaScript

Left is the snippet. Right is the console — one console.log at a time.

DFS, skip parent, seen neighbor = cycle

const g = { A: ["B", "C"], B: ["A", "C"], C: ["A", "B"] };
const seen = new Set();
let cycle = false;

const dfs = (u, parent) => {
  seen.add(u);
  for (const v of g[u]) {
    if (v === parent) continue;
    if (seen.has(v)) {
      cycle = true;
      console.log("back edge", u, "→", v);
      return;
    }
    console.log("walk", u, "→", v);
    dfs(v, u);
  }
};

dfs("A", null);
console.log("cycle?", cycle);

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • These n towns and n roads — which extra road closes a loop?
  • Is this a tree (connected, no loop)?
  • A self-road 2-2. Is that a loop?

You say this first

DFS: a visited neighbor that is not your parent is a cycle. Union-Find: if two ends of an edge are already in the same component, that edge closes a cycle. I'd dry-run a tiny case first, then say the invariant and the complexity (O(V + E) DFS; O(E α(V)) Union-Find time, O(V) space).

Offer the next notch: UF: for each edge (u,v): if find(u)==find(v) return that edge; else union(u,v).. Tradeoff: Directed graphs — a back edge is defined differently; use directed cycle detection. If the input is an edge list of a nearly-tree, start with Union-Find.

More notes if you want them

Undirected cycle detection is how you know a graph is a tree (connected + acyclic) and how Kruskal rejects edges. Interviews will give you an n-node n-edge graph ('redundant connection') and expect Union-Find. DFS is equally valid if you handle the parent correctly — that parent bug is the usual fail.

Use when: Is the graph a forest / tree? Which edge creates a cycle?

Skip when: Directed graphs — a back edge is defined differently; use directed cycle detection.

Trap: No parent argument → every undirected edge looks like a cycle.
