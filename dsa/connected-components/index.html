Connected Components

CORE

The problem they give you

They will not say “Connected Components.” They describe this:

Given: An undirected friendship map (or a 0/1 matrix of “knows”).

Find: How many separate circles exist? Isolated people count as their own circle.

Tiny example: 1-2, 3-4, 5 alone. Three circles.

Name of the tool

In an undirected graph, a component is a maximal reachable set. DFS/BFS floods one; Union-Find merges them from the edge list. Count the floods or the leftover roots.

Why this tool

Components are the first graph-counting question: number of provinces, friend circles, connected components in a grid (islands).

Approach

  1. visited array.
  2. UF: union edges; ans = number of roots (parent[i]===i) among relevant nodes.

Connected Components

visited array. ans = 0. for u in nodes: if !visited[u], ans++, dfs/bfs flood.

Run it in JavaScript

Left is the snippet. Right is the console — one console.log at a time.

DFS from each unseen node

const g = { A: ["B"], B: ["A"], C: ["D"], D: ["C"], E: [] };
const seen = new Set();
let comps = 0;

const dfs = (u) => {
  seen.add(u);
  for (const v of g[u]) if (!seen.has(v)) dfs(v);
};

for (const u of Object.keys(g)) {
  if (seen.has(u)) continue;
  comps++;
  dfs(u);
  console.log("component", comps, "from", u);
}
console.log("count", comps);

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Number of provinces in an n×n “connected” matrix.
  • Label each person with a circle id, then answer “same circle?” queries.
  • Edges arrive over time. How many circles after each edge?

You say this first

In an undirected graph, a component is a maximal reachable set. DFS/BFS floods one; Union-Find merges them from the edge list. Count the floods or the leftover roots. I'd dry-run a tiny case first, then say the invariant and the complexity (O(V + E) time, O(V) space).

Offer the next notch: UF: union edges; ans = number of roots (parent[i]===i) among relevant nodes.. Tradeoff: You need strong connectivity — SCC algorithms. Number of Provinces is UF on an adjacency matrix or DFS on the matrix rows.

More notes if you want them

Components are the first graph-counting question: number of provinces, friend circles, connected components in a grid (islands). You should be able to do it three ways and pick based on the input format (matrix vs edge list). Directed graphs have weakly vs strongly connected components — do not mix the terms.

Use when: Count or label undirected components; preprocess queries 'are u and v connected?' (then UF or one flood + labels).

Skip when: You need strong connectivity — SCC algorithms.

Trap: Counting nodes instead of floods.
