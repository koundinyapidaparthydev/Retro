Nth Node from the End

CORE

The problem they give you

They will not say “Nth Node from the End.” They describe this:

Given: A singly linked list and an integer n. You may be asked to delete that node.

Find: The n-th node from the tail, in one pass. If n equals the length, that node is the head.

Tiny example: 1→2→3→4→5, n=2 → delete 4 → 1→2→3→5.

Name of the tool

Advance a lead pointer n steps, then walk lead and trail together. When lead hits null, trail is n from the end — one pass, ready to delete.

Why this tool

Delete the nth node from the end is a top-10 linked-list question.

Approach

  1. dummy.next = head; lead = trail = dummy.
  2. Advance lead n + 1 steps so the gap is n nodes (lead is one past the eventual victim's predecessor relationship).
  3. Walk both until lead is null.

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Delete the n-th node from the end.
  • n equals the length — the head goes away. What do you return?
  • n=1: remove the tail without a stored length.

You say this first

Advance a lead pointer n steps, then walk lead and trail together. When lead hits null, trail is n from the end — one pass, ready to delete. I'd dry-run a tiny case first, then say the invariant and the complexity (O(L) where L is the list length time, O(1) space).

Offer the next notch: Advance lead n + 1 steps so the gap is n nodes (lead is one past the eventual victim's predecessor relationship).. Tradeoff: You already have a doubly linked list with a tail pointer and n = 1 — just pop the tail. Use a dummy. The 'delete the head' case is how most solutions fail the tests.

More notes if you want them

Delete the nth node from the end is a top-10 linked-list question. The two-pass (count length, then walk L-n) is fine. The one-pass gap technique is what they want if they said 'one pass.' The dummy head is what saves you when n equals the length (delete the real head).

Use when: Read or delete the nth-from-end node in one pass.

Skip when: You already have a doubly linked list with a tail pointer and n = 1 — just pop the tail.

Trap: Off-by-one on the gap: advancing n instead of n+1 when you needed the predecessor.
