Edit Distance (Levenshtein)

CORE

The problem they give you

They will not say “Edit Distance (Levenshtein).” They describe this:

Given: Two words. You may insert a letter, delete a letter, or replace a letter. Each action costs 1.

Find: Fewest actions to turn word A into word B.

Tiny example: horse → ros. Replace h→r, delete o, delete e? One standard answer is 3 (horse → rorse → rose → ros).

Name of the tool

dp[i][j] is the min inserts/deletes/replaces to turn A[:i] into B[:j]. A match copies the diagonal; otherwise 1+min(insert, delete, replace).

Why this tool

Edit distance is the LCS table with three paid moves.

Approach

  1. Init borders to i and j.
  2. for i,j: if A[i-1]==B[j-1] dp=diag else 1+min(diag, up, left).
  3. Return dp[n][m].

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Min inserts, deletes, replaces.
  • Recover one alignment, not only the number.
  • Only delete and insert — no replace.

You say this first

dp[i][j] is the min inserts/deletes/replaces to turn A[:i] into B[:j]. A match copies the diagonal; otherwise 1+min(insert, delete, replace). I'd dry-run a tiny case first, then say the invariant and the complexity (O(n m) time, O(n m) or O(min(n,m)) space).

Offer the next notch: for i,j: if A[i-1]==B[j-1] dp=diag else 1+min(diag, up, left).. Tradeoff: Only deletions on one string — that is LCS. Name the three neighbors: replace, delete, insert. Point at the table.

More notes if you want them

Edit distance is the LCS table with three paid moves. It appears in spell-check talks and in interviews as 'min operations to convert word1 to word2.' If you only remember LCS, you will miss replace-as-one-op (two deletes/inserts would be worse). One-row rolling is a common space follow-up.

Use when: Min edits between two strings under insert/delete/replace.

Skip when: Only deletions on one string — that is LCS.

Trap: Forgetting the insert-all / delete-all borders.
