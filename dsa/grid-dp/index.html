Grid DP

CORE

The problem they give you

They will not say “Grid DP.” They describe this:

Given: A grid. You may only step right or down (or only down a falling column). Cells have costs or obstacles.

Find: Number of paths, or the cheapest path sum, to the far corner.

Tiny example: 3×2 empty grid, only right/down. 3 paths. Min-sum grid [[1,3],[1,5]] → 1+1+5 = 7 or 1+3+5 = 9. Best 7.

Name of the tool

dp[r][c] from the top/left (or other incoming directions). Unique paths, min path sum, dungeon game, and falling path are one family.

Why this tool

Grid DP is how you walk a matrix without DFS+memo on every interview.

Approach

  1. Init first row/col as prefix sums or prefix products of ways.
  2. for r: for c: dp[r][c] = cell + min(up, left) (or + of ways).
  3. Return dp[m-1][n-1].

Run it in JavaScript

Left is the snippet. Right is the console — one console.log at a time.

only right and down

const grid = [
  [1, 3, 1],
  [1, 5, 1],
  [4, 2, 1],
];
const h = grid.length, w = grid[0].length;
const dp = grid.map((row) => row.slice());

for (let r = 0; r < h; r++) {
  for (let c = 0; c < w; c++) {
    if (r === 0 && c === 0) continue;
    const up = r ? dp[r - 1][c] : Infinity;
    const left = c ? dp[r][c - 1] : Infinity;
    dp[r][c] += Math.min(up, left);
    console.log(r, c, "→", dp[r][c]);
  }
}

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Unique paths. Obstacles block a cell.
  • Minimum path sum, right and down only.
  • Two walkers pick cherries. They cannot double-count a cell.

You say this first

dp[r][c] from the top/left (or other incoming directions). Unique paths, min path sum, dungeon game, and falling path are one family. I'd dry-run a tiny case first, then say the invariant and the complexity (O(m n) time, O(m n) or O(n) space).

Offer the next notch: for r: for c: dp[r][c] = cell + min(up, left) (or + of ways).. Tradeoff: Four-direction min cost — Dijkstra / 0-1 BFS. Unique Paths II: treat obstacle as a hard 0 and do not add from it.

More notes if you want them

Grid DP is how you walk a matrix without DFS+memo on every interview. Unique Paths, Min Path Sum, and Cherry Pickup (harder, two people / two paths) are the ladder. You must handle obstacles (zero out a cell), borders, and the rolling 1-D optimization. Do not BFS a min-sum grid with positive weights unless you Dijkstra — DP on DAG (only right/down) is enough.

Use when: Acyclic grid moves (right/down, or down-only falling paths).

Skip when: Four-direction min cost — Dijkstra / 0-1 BFS.

Trap: Uninitialized first row when left is the only incoming.
