Peak Finding

NEXT

The problem they give you

They will not say “Peak Finding.” They describe this:

Given: An array of numbers. A peak is a cell ≥ its neighbors; the two ends have one neighbor each.

Find: Any peak index. You do not need the global max. Faster than scanning every cell.

Tiny example: [1, 2, 3, 1] → index 2 (value 3). [1, 2, 1, 3, 5, 6, 4] → index 2 or 5 are both fine.

Name of the tool

Binary-search a bitonic or unsorted array for an index that is greater than its neighbors. The comparison at mid tells you which side still has a peak.

Why this tool

Peak finding is the interviewer's favorite 'binary search without a sorted array' problem.

Approach

  1. Handle n = 1 (index 0) and check the two ends if you want an early return.
  2. While lo < hi, set mid = floor((lo+hi)/2).
  3. If A[mid] < A[mid+1], set lo = mid + 1 (a peak exists on the rising side).

Run it in JavaScript

Left is the snippet. Right is the console — one console.log at a time.

climb a bitonic array

const nums = [1, 3, 8, 12, 4, 2];
let lo = 0, hi = nums.length - 1;

while (lo < hi) {
  const mid = Math.floor((lo + hi) / 2);
  console.log({ mid, v: nums[mid], next: nums[mid + 1] });
  if (nums[mid] < nums[mid + 1]) lo = mid + 1;
  else hi = mid;
}
console.log("peak", lo, nums[lo]);

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Find any index that is higher than its neighbors.
  • The array rises then falls. Find the top.
  • Same question on a grid: a cell greater than its four neighbors.

You say this first

Binary-search a bitonic or unsorted array for an index that is greater than its neighbors. The comparison at mid tells you which side still has a peak. I'd dry-run a tiny case first, then say the invariant and the complexity (O(log n) in 1D, O(n log n) typical 2D time, O(1) iterative 1D space).

Offer the next notch: While lo < hi, set mid = floor((lo+hi)/2).. Tradeoff: You need the global maximum of an arbitrary unsorted array — that is still a linear scan. Draw a 5-element up-down array and narrate why the slope at mid discards a half. That picture is the interview.

More notes if you want them

Peak finding is the interviewer's favorite 'binary search without a sorted array' problem. It trains you to binary search a guarantee, not a sort. Any array of numbers has at least one peak if you treat ends as lower than their one neighbor. That existence proof is what lets you discard half the array: if mid is on an uphill slope, a peak exists to the right; downhill, to the left.

Use when: Bitonic arrays: find the maximum in O(log n).

Skip when: You need the global maximum of an arbitrary unsorted array — that is still a linear scan.

Trap: Comparing A[mid] to the target instead of to A[mid+1]. There is no target.
