The problem they give you

They will not say “Counting Sort.” They describe this:

Given: n integers whose keys all lie in a small known range, say 0..k. Some items carry extra data (a name with a score).

Find: The items in order by that integer key. Equal keys must keep their original order.

Tiny example: scores [2, 0, 2, 1] with names A, B, C, D → B, D, A, C. The two 2s stay A before C.

Name of the tool

Tally how many times each key in a small integer range appears, then write the output by walking the counts. Linear in n + range.

Why this tool

Counting sort is the first sort you meet that beats n log n — by refusing to compare.

Approach

  1. Find min and max (or take them as given).
  2. For each element, count[key - min]++.
  3. Prefix-sum count so count[i] = number of elements with key ≤ i + min.

tally, then write values back in order

const a = [2, 5, 3, 0, 2, 3];
const count = Array(6).fill(0);
for (const x of a) count[x]++;
console.log("count", count);
const out = [];
count.forEach((c, v) => { while (c--) out.push(v); });

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Sort these ages / grades / bytes. The range is tiny.
  • Items have payloads. Equal scores must keep arrival order.
  • Keys can be negative. How do you index the tallies?

You say this first

Tally how many times each key in a small integer range appears, then write the output by walking the counts. Linear in n + range. I'd dry-run a tiny case first, then say the invariant and the complexity (O(n + k) time, O(n + k) space).

Offer the next notch: For each element, count[key - min]++.. Tradeoff: Linear time versus a key-range assumption and extra memory. If they say 'sort this array of ages' or 'sort characters,' counting sort is the intended answer, not quicksort.

More notes if you want them

Counting sort is the first sort you meet that beats n log n — by refusing to compare. Interviews use it as the engine inside radix sort, as the way to sort by a grade or a byte, and as a test of whether you can produce a stable linear sort. If you only remember 'make a frequency array,' you will fail the follow-up that asks for original order of ties.

Use when: Integer keys in a range k that is O(n) or otherwise acceptable.

Skip when: Huge or sparse key ranges (k ≫ n) — you pay in memory and time.

Trap: Prefix-sum off-by-one so the last bucket overflows.
