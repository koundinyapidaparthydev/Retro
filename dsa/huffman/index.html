The problem they give you

They will not say “Huffman Coding.” They describe this:

Given: A set of symbols and how often each appears. You will encode each symbol as a bit string. No code may be a prefix of another.

Find: An encoding that minimizes total bits (frequency × code length). Same process: minimum cost to merge files when merging a and b costs a+b.

Tiny example: a:3, b:1, c:1 → codes a=0, b=10, c=11. Total bits 3·1+1·2+1·2 = 7. Merge cost (1+1)+(2+3) = 7.

Name of the tool

Greedy: repeatedly merge the two rarest symbols into a new parent whose frequency is the sum. A min-heap of trees builds an optimal prefix code.

Why this tool

Huffman is the heap-meets-greedy interview.

Approach

  1. Count frequencies.
  2. While heap.size > 1: a = pop(); b = pop(); parent = {freq: a.freq+b.freq, left: a, right: b}; push(parent).
  3. The remaining node is the root.

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Minimum cost to connect n ropes / files. Any pair may merge.
  • Build bit codes so common letters get shorter strings.
  • Do they want the actual 0/1 strings, or only the total cost?

You say this first

Greedy: repeatedly merge the two rarest symbols into a new parent whose frequency is the sum. A min-heap of trees builds an optimal prefix code. I'd dry-run a tiny case first, then say the invariant and the complexity (O(n log n) time, O(n) space).

Offer the next notch: While heap.size > 1: a = pop(); b = pop(); parent = {freq: a.freq+b.freq, left: a, right: b}; push(parent).. Tradeoff: Symbols must keep a linear order (optimal BST, matrix chain) — that is DP. If they say 'connect n ropes with min cost,' this is it. Heap, not DP.

More notes if you want them

Huffman is the heap-meets-greedy interview. You prove a prefix code is optimal by always combining the two smallest frequencies. It shows up as 'minimum cost to merge files / ropes' (the same algorithm) and as the classic compression story. If you sort once and then merge linearly, you get it wrong when new parents should interleave — that is why the heap stays.

Use when: Optimal prefix codes; minimum cost to merge files when any pair may merge.

Skip when: Symbols must keep a linear order (optimal BST, matrix chain) — that is DP.

Trap: Merging in sorted order without reinserting the parent — wrong when 1,1,100 becomes (1+1)+100 vs something else; actually that one is fine, but 1,3,3,4 is the usual counterexample for 'always sequential.'
