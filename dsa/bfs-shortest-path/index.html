BFS Shortest Path

CORE

The problem they give you

They will not say “BFS Shortest Path.” They describe this:

Given: A map where every corridor is one hop. You need the walk, not only the length.

Find: One shortest hop-path from start to target. If none, say so.

Tiny example: S-a-b-E and S-x-y-z-E. Return S,a,b,E (3 hops), not the longer walk.

Name of the tool

On unweighted edges, BFS distance is the shortest hop count. Store parents if you must reconstruct one such path.

Why this tool

This is BFS specialized to the path question so you practice reconstruction and multi-source.

Approach

  1. Standard BFS with dist and parent arrays.
  2. Reconstruct: from t, walk parent until s, reverse the list.
  3. Multi-source: initialize the queue with all sources at dist 0.

Run it in JavaScript

Left is the snippet. Right is the console — one console.log at a time.

unweighted hops from A

const g = { A: ["B", "C"], B: ["D"], C: ["D"], D: [] };
const dist = { A: 0 };
const q = ["A"];

while (q.length) {
  const u = q.shift();
  console.log("pop", u, "d", dist[u]);
  for (const v of g[u]) {
    if (dist[v] === undefined) {
      dist[v] = dist[u] + 1;
      q.push(v);
    }
  }
}
console.log("dist", dist);

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Restore the path through a maze, not just the hop count.
  • List every shortest word-ladder, not one.
  • Several doors start open. Distance to the nearest door for every room.

You say this first

On unweighted edges, BFS distance is the shortest hop count. Store parents if you must reconstruct one such path. I'd dry-run a tiny case first, then say the invariant and the complexity (O(V + E) time, O(V) space).

Offer the next notch: Reconstruct: from t, walk parent until s, reverse the list. If parent[t] never set, no path.. Tradeoff: Weighted edges. If they want all shortest paths, do not DFS from the source; BFS first for dist, then DFS/BFS only along edges that go dist+1.

More notes if you want them

This is BFS specialized to the path question so you practice reconstruction and multi-source. Interviewers ask for the path, not just the length, and people who only stored a visited set freeze. It is also the correctness proof you will reuse: Dijkstra is 'BFS with a better frontier' when weights vary.

Use when: Shortest hop path; reconstruct one or all shortest paths in unweighted graphs.

Skip when: Weighted edges.

Trap: Reconstructing with a DFS that ignores dist and returns a long path.
