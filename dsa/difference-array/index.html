The problem they give you

They will not say “Difference Array.” They describe this:

Given: An array starts as zeros (or given values). You get many updates: “add v to every cell from L through R.”

Find: After all updates, produce the final array. Do not walk each range on every update.

Tiny example: n = 5. Add 2 on [1, 3], then add 3 on [2, 4] → [0, 2, 5, 5, 3].

Name of the tool

The inverse of prefix sum. To add v on [l,r], do D[l]+=v and D[r+1]-=v. One prefix pass materializes the final array after many range updates.

Why this tool

When you have q range-adds and then need the whole array (or one prefix scan), a difference array is O(q+n) and beats q scans.

Approach

  1. D = zeros(n+1).
  2. cur=0; for i in 0..n-1: cur+=D[i]; A[i]+=cur (or A[i]=cur if you started from 0).
  3. Ignore D[n] after the last subtract.

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Apply many range increments, then print the array.
  • Bookings add seats on flights [from, to]. How many seats does each flight need?
  • Each car trip adds one passenger from start to end. Does the road ever exceed capacity?

You say this first

The inverse of prefix sum. To add v on [l,r], do D[l]+=v and D[r+1]-=v. One prefix pass materializes the final array after many range updates. I'd dry-run a tiny case first, then say the invariant and the complexity (O(n + q) time, O(n) space).

Offer the next notch: cur=0; for i in 0..n-1: cur+=D[i]; A[i]+=cur (or A[i]=cur if you started from 0).. Tradeoff: Interleaved arbitrary range-sum queries — segment tree with lazy, or Fenwick on D plus extra for range sum. Corporate Flight Bookings is this. Car Pooling is a sweep / difference on time.

More notes if you want them

When you have q range-adds and then need the whole array (or one prefix scan), a difference array is O(q+n) and beats q scans. Corporate-flight-bookings, car pooling, and 'apply range increments then query points' are the interviews. If you later need arbitrary range queries after mixed updates, step up to Fenwick.

Use when: Many range increments, then a single materialization or point reads after all updates.

Skip when: Interleaved arbitrary range-sum queries — segment tree with lazy, or Fenwick on D plus extra for range sum.

Trap: D[r]-=v instead of D[r+1] (off-by-one on inclusive r).
