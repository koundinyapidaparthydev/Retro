BFS with a Queue, DFS with a Stack

CORE

The problem they give you

They will not say “BFS with a Queue, DFS with a Stack.” They describe this:

Given: A graph or grid. You must walk every reachable cell. Recursion depth might be 10^5, so the call stack may explode.

Find: Visit order if you expand nearest-first (fewest hops) versus dive-deep-first. For the nearest-first walk, also the hop distance from the start.

Tiny example: Start A with edges A→B, A→C, B→D. Nearest-first visits A, B, C, then D; hop count to D is 2. Dive-deep may go A, B, D, then C.

Name of the tool

The same graph walk, different frontier: a queue expands level by level; a stack (or the call stack) dives deep. Know what each visits first.

Why this tool

Interviews often ask you to rewrite a recursive DFS as an explicit stack, or to explain why BFS finds shortest paths in unweighted graphs and DFS does not.

Approach

  1. BFS: queue ← source; mark source.
  2. Iterative DFS: stack ← source.
  3. Recursive DFS: mark u; for each v, if unseen dfs(v).

BFS with a Queue, DFS with a Stack

BFS: queue ← source; mark source. While queue: pop front u; process u; for each unseen neighbor v, mark v, set dist[v]=dist[u]+1, push back.

Run it in JavaScript

Left is the snippet. Right is the console — one console.log at a time.

same graph: queue is BFS, stack is DFS

const g = { A: ["B", "C"], B: ["D"], C: ["E"], D: [], E: [] };

const q = ["A"], seenQ = new Set(["A"]);
while (q.length) {
  const u = q.shift();
  for (const v of g[u]) if (!seenQ.has(v)) { seenQ.add(v); q.push(v); }
}
console.log("bfs", [...seenQ]);

const st = ["A"], seenS = new Set();
while (st.length) {
  const u = st.pop();
  if (seenS.has(u)) continue;
  seenS.add(u);
  for (const v of [...g[u]].reverse()) st.push(v);
}
console.log("dfs", [...seenS]);

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Minimum steps in a maze. Walls are #.
  • Rewrite the recursive flood-fill with an explicit stack.
  • Number of islands, then nearest 0 in a matrix (many starts at once).

You say this first

The same graph walk, different frontier: a queue expands level by level; a stack (or the call stack) dives deep. Know what each visits first. I'd dry-run a tiny case first, then say the invariant and the complexity (O(V + E) time, O(V) for the frontier and visited space).

Offer the next notch: Iterative DFS: stack ← source. While stack: pop u; if u seen continue; mark u; push neighbors (often in reverse so the first neighbor is processed first).. Tradeoff: Weighted shortest paths — BFS is wrong; use Dijkstra or 0-1 BFS. If the problem says 'minimum number of steps' on a grid or word ladder, reach for BFS before DFS + memo.

More notes if you want them

Interviews often ask you to rewrite a recursive DFS as an explicit stack, or to explain why BFS finds shortest paths in unweighted graphs and DFS does not. The data structure is the algorithm. If you use a stack and call it BFS, you will get a spanning tree, not distances.

Use when: BFS: shortest path on unweighted graphs, level-order, 'minimum moves.'

Skip when: Weighted shortest paths — BFS is wrong; use Dijkstra or 0-1 BFS.

Trap: Using a stack and claiming shortest paths.
