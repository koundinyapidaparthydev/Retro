The problem they give you

They will not say “N-Queens.” They describe this:

Given: An n×n board. Place n queens so none share a row, column, or diagonal.

Find: Every safe board (or just how many). One queen per row is fine to assume.

Tiny example: n=4 has 2 solutions. n=1 has 1. n=2 and n=3 have 0.

Name of the tool

Place n queens so none share a row, column, or diagonal. Backtrack row by row, pruning with column and diagonal occupancy sets.

Why this tool

N-Queens is the backtracking poster child: a constraint-satisfaction search with aggressive pruning.

Approach

  1. col[c], diag[r-c+n-1], anti[r+c] start false.
  2. dfs(r): if r === n, record the board (or increment count).
  3. For c in 0..n-1: if any of the three flags is true, skip.

Run it in JavaScript

Left is the snippet. Right is the console — one console.log at a time.

place 4 queens, one per row

const n = 4;
const col = [], diag = [], anti = [];

function dfs(r) {
  if (r === n) {
    console.log("board", col.slice());
    return;
  }
  for (let c = 0; c < n; c++) {
    if (col.includes(c) || diag.includes(r - c) || anti.includes(r + c)) continue;
    col.push(c); diag.push(r - c); anti.push(r + c);
    console.log("try row", r, "col", c);
    dfs(r + 1);
    col.pop(); diag.pop(); anti.pop();
  }
}

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Return the boards as rows of Q and .
  • Only the count, no strings.
  • n=4 by hand, then match your program.

You say this first

Place n queens so none share a row, column, or diagonal. Backtrack row by row, pruning with column and diagonal occupancy sets. I'd dry-run a tiny case first, then say the invariant and the complexity (O(n!) worst case with pruning much faster in practice time, O(n) for flags and the current board space).

Offer the next notch: dfs(r): if r === n, record the board (or increment count).. Tradeoff: You only need a closed formula — none exists that is simpler than search for general n. Explain the three constraints before coding. Draw a 4×4 and mark r-c and r+c.

More notes if you want them

N-Queens is the backtracking poster child: a constraint-satisfaction search with aggressive pruning. Interviews use it to see whether you model attacks cheaply (O(1) checks via col / diag / anti-diag sets) instead of scanning the board every time. The 'return any one solution' vs 'return all boards' vs 'return the count' variants change almost no code.

Use when: Place n non-attacking queens, or similar 'one per row + extra conflicts' problems (n-rooks is just permutation of columns).

Skip when: You only need a closed formula — none exists that is simpler than search for general n.

Trap: Forgetting to undo the flags — later rows see a permanently blocked column.
