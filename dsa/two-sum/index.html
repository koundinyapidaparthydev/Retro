Two Sum and Family

CORE

The problem they give you

They will not say “Two Sum and Family.” They describe this:

Given: An unsorted array and a target. You may use extra memory.

Find: Two indices whose values add to the target.

Tiny example: [2, 7, 11, 15], target 9 → [0, 1]. The array is not sorted, so you cannot use two fingers.

Name of the tool

For each x, ask the map whether target − x was already seen. One pass, O(n). The family includes 3-sum (sort + two pointers), 4-sum, and two-sum on BST/sorted arrays.

Why this tool

Two Sum is the first hashmap problem in most interview loops.

Approach

  1. map empty.
  2. Sorted two-pointer: i=0, j=n-1, move the side that fixes the sum.
  3. 3-sum: sort; for i, skip dup i; l=i+1, r=n-1; skip dup l/r on hits.

Run it in Java

Left is the snippet. Right is the output — one System.out.println at a time.

two indices with a HashMap

int[] nums = {2, 7, 11, 15};
int target = 9;
Map<Integer, Integer> seen = new HashMap<>();
for (int i = 0; i < nums.length; i++) {
  int need = target - nums[i];
  if (seen.containsKey(need)) {
    System.out.println("hit " + seen.get(need) + "," + i);
    break;
  }
  seen.put(nums[i], i);
  System.out.println("store " + nums[i] + " @" + i);
}

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Return the two indices that add to target.
  • What if the array is sorted? (then two pointers, no Map)

You say this first

For each x, ask the map whether target − x was already seen. One pass, O(n). The family includes 3-sum (sort + two pointers), 4-sum, and two-sum on BST/sorted arrays. I'd dry-run a tiny case first, then say the invariant and the complexity (O(n) expected two-sum; O(n²) 3-sum after sort time, O(n) map space).

Offer the next notch: Sorted two-pointer: i=0, j=n-1, move the side that fixes the sum.. Tradeoff: Sorted array and O(1) extra required — two pointers. Ask: indices or values? duplicates? mutability? Then pick map vs sort.

More notes if you want them

Two Sum is the first hashmap problem in most interview loops. The follow-ups never stop: return indices, handle duplicates, 3-sum, two-sum in a BST, two-sum in a sorted stream. The idea — complement lookup — is the same as 'have I seen prefix-k' and 'have I seen this anagram signature.' Get the one-pass vs two-pass distinction right.

Use when: Pair / triple sums, complements, 'two numbers add to k' in an unsorted array.

Skip when: Sorted array and O(1) extra required — two pointers.

Trap: Inserting before querying so x pairs with itself when it appears once.
