Path Sum

CORE

The problem they give you

They will not say “Path Sum.” They describe this:

Given: A binary tree of integers and a target sum.

Find: Does any root-to-leaf path add to the target? Follow-up: count every downward path (any start, any end) that adds to the target.

Tiny example: 5 with left 4 (left 11) and right 8. Target 20 → yes (5-4-11). Target 13 → yes (5-8).

Name of the tool

Root-to-leaf (or any downward path) whose values add to a target. DFS with a remaining sum, or prefix sums plus a hashmap for 'any path.'

Why this tool

Path Sum I is a warmup.

Approach

  1. I: return dfs(root, target) with the leaf check.
  2. II: backtrack path + remaining.
  3. III: map {0:1}.

Run it in JavaScript

Left is the snippet. Right is the console — one console.log at a time.

subtract as you walk, check a leaf

const n = (val, left = null, right = null) => ({ val, left, right });
const root = n(5, n(4, n(11, n(7), n(2))), n(8));
const target = 22;

const dfs = (node, remain) => {
  if (!node) return false;
  remain -= node.val;
  console.log("at", node.val, "remain", remain);
  if (!node.left && !node.right) return remain === 0;
  return dfs(node.left, remain) || dfs(node.right, remain);
};

console.log("hit?", dfs(root, target));

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Root-to-leaf path that sums to target?
  • List every such root-to-leaf path.
  • Count downward paths that sum to target — not only from the root.

You say this first

Root-to-leaf (or any downward path) whose values add to a target. DFS with a remaining sum, or prefix sums plus a hashmap for 'any path.' I'd dry-run a tiny case first, then say the invariant and the complexity (O(n) for I/III with hashmap; O(n²) worst to list all paths if you must output them time, O(h) plus the map space).

Offer the next notch: II: backtrack path + remaining.. Tradeoff: Paths that may go up and then down (true tree paths through LCA) — reduce via LCA + prefix on parent chains, or reroot DP. Clarify start and end constraints before coding. Draw a 3-node example for III.

More notes if you want them

Path Sum I is a warmup. Path Sum II collects the paths. Path Sum III (any downward path, not necessarily from the root) is the one that filters people: nested DFS is O(n²), prefix+hashmap is O(n). Interviewers use this to see if you transfer the subarray-sum-equals-k trick onto a tree.

Use when: Target sums along tree paths, with various start/end constraints.

Skip when: Paths that may go up and then down (true tree paths through LCA) — reduce via LCA + prefix on parent chains, or reroot DP.

Trap: Counting a non-leaf as a finish in Path Sum I.
