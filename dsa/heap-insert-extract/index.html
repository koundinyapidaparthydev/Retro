Heap Insert and Extract

CORE

Definition

push appends and sifts up. pop swaps the root with the last element, shrinks, and sifts down. peek is A[0]. All the priority-queue operations.

Why it exists

Every 'top k,' 'merge k,' 'median stream,' and Dijkstra implementation is these two operations.

Approach

  1. push: append, siftUp.
  2. pop: if empty, error.
  3. peek: A[0].
Time O(log n) push/pop; O(1) peekSpace O(n)

Run it in JavaScript

Left is the snippet. Right is the console — one console.log at a time.

push + siftUp; swap root with last + siftDown

const h = [];
function up(i) {
  while (i > 0) {
    const p = (i - 1) >> 1;
    if (h[p] <= h[i]) break;
    [h[p], h[i]] = [h[i], h[p]];
    i = p;
  }
}
function down(i) {
  for (;;) {
    let l = i * 2 + 1, r = l + 1, m = i;
    if (l < h.length && h[l] < h[m]) m = l;
    if (r < h.length && h[r] < h[m]) m = r;
    if (m === i) break;
    [h[i], h[m]] = [h[m], h[i]];
    i = m;
  }
}
function push(x) { h.push(x); up(h.length - 1); console.log("push", x, h.slice()); }
function pop() {
  const top = h[0];
  h[0] = h.pop();
  if (h.length) down(0);
  console.log("pop", top, h.slice());
  return top;
}
push(5); push(2); push(4); pop();

You say this first

push appends and sifts up. pop swaps the root with the last element, shrinks, and sifts down. peek is A[0]. All the priority-queue operations. I'd dry-run a tiny case first, then say the invariant and the complexity (O(log n) push/pop; O(1) peek time, O(n) space).

Offer the next notch: pop: if empty, error. If one element, pop it. Else swap 0 and last, pop last, siftDown(0), return the old root.. Tradeoff: You need min and max at once — use two heaps or a balanced BST. If the language has a heap, use it after stating the comparator. If not, write a small Heap class once and reuse it.

More notes if you want them

Every 'top k,' 'merge k,' 'median stream,' and Dijkstra implementation is these two operations. You should be able to write them without a library, and you should know that extract-min is O(log n), not O(1). Decrease-key is O(log n) only if you have an index handle; otherwise people insert a duplicate and lazily skip stale pops.

Use when: Repeated 'give me the current min/max and insert new keys.'

Skip when: You need min and max at once — use two heaps or a balanced BST.

Trap: Forgetting to shrink the array after extract — siftDown sees a ghost last element.
