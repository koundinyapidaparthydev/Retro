Merge Sort

CORE
GoogleoftenAmazonsometimesStable n log n + inversion count.

Definition

Split the list in half until pieces are tiny, sort those, then zipper two sorted halves together.

Why it exists

Merge sort is the sorting algorithm interviews actually want you to write when they say 'sort this' and then follow up with 'now sort a linked list' o…

Approach

  1. If the slice has 0 or 1 elements, it is sorted — return.
  2. Recursively sort A[lo..mid) and A[mid..hi).
  3. Allocate a temp buffer (or use a shared scratch array of length n).
Time Θ(n log n)Space O(n) array scratch; O(log n) recursion (O(1) extra for linked lists besides recursion)

split in half, merge the sorted runs

function merge(L, R) {
  const out = [];
  let i = 0, j = 0;
  while (i < L.length && j < R.length)
    out.push(L[i] <= R[j] ? L[i++] : R[j++]);
  return out.concat(L.slice(i), R.slice(j));
}
function sort(a) {
  if (a.length < 2) return a;
  const m = a.length >> 1;
  const out = merge(sort(a.slice(0, m)), sort(a.slice(m)));
  console.log("merge", out);
  return out;
}

You say this first

Divide the array in half, sort each half, merge two sorted runs in linear time. Stable, guaranteed n log n, the interview divide-and-conquer sort. I'd dry-run a tiny case first, then say the invariant and the complexity (Θ(n log n) time, O(n) array scratch; O(log n) recursion (O(1) extra for linked lists besides recursion) space).

Offer the next notch: Recursively sort A[lo..mid) and A[mid..hi).. Tradeoff: Predictable time and stability versus linear extra memory on arrays. Allocate one scratch array of size n at the top and pass it down. Allocating inside every call is a common slow / messy version.

More notes if you want them

Merge sort is the sorting algorithm interviews actually want you to write when they say 'sort this' and then follow up with 'now sort a linked list' or 'count inversions.' It is also the template for a family of divide-and-conquer problems: merge k lists, sort a stream with external memory, and any 'combine two sorted answers' recurrence. You must be fluent in both the recursive structure and the linear merge.

Use when: You need a stable guaranteed O(n log n) sort.

Skip when: Tight memory: heap sort or in-place quicksort use O(1)/O(log n) extra space.

Trap: Mid calculation and empty-half bugs when lo/hi are indices versus lengths.
