Heapify and the Heap Property

CORE
GooglesometimesUberoftenPriority queue internals.

The problem they give you

They will not say “Heapify and the Heap Property.” They describe this:

Given: An array of n numbers already in memory. Index i’s children sit at 2i+1 and 2i+2. You want every parent to beat both children.

Find: Rearrange the array in place so that parent-child rule holds. Building it should be linear, not n single inserts.

Tiny example: [3, 1, 6, 5, 2, 4] as a max-tree → [6, 5, 4, 1, 2, 3] is one valid layout. Root 6 is the max; 5 and 4 beat their children.

Name of the tool

A binary heap is an almost-complete binary tree stored in an array. Sift-down from the last parent builds it in O(n); sift-up after an append is O(log n).

Why this tool

If you treat a heap as 'I imported PriorityQueue,' you cannot answer 'why is build O(n)?' or implement heap sort.

Approach

  1. build: for i = floor(n/2)-1 down to 0, siftDown(i).
  2. siftDown(i): while true, pick the extreme child in range; if it should swap with i, swap and i = child; else break.
  3. Do not build by n times push unless the data arrives online.

Run it in JavaScript

siftDown from the last parent — build is O(n)

const a = [3, 9, 2, 1, 4, 5];
function down(i) {
  for (;;) {
    let l = i * 2 + 1, r = l + 1, m = i;
    if (l < a.length && a[l] > a[m]) m = l;
    if (r < a.length && a[r] > a[m]) m = r;
    if (m === i) break;
    [a[i], a[m]] = [a[m], a[i]];
    i = m;
  }
}
console.log("last parent", (a.length >> 1) - 1);
for (let i = (a.length >> 1) - 1; i >= 0; i--) {
  down(i);
  console.log("sift", i, a.slice());
}

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Turn this array into a parent-beats-children tree in linear time.
  • Why is n inserts the wrong build?
  • Write the sink loop. Where is the last parent index?

You say this first

A binary heap is an almost-complete binary tree stored in an array. Sift-down from the last parent builds it in O(n); sift-up after an append is O(log n). I'd dry-run a tiny case first, then say the invariant and the complexity (O(n) build; O(log n) sift time, O(1) extra for iterative sift space).

Offer the next notch: siftDown(i): while true, pick the extreme child in range; if it should swap with i, swap and i = child; else break.. Tradeoff: You need a full sort in the array besides heap sort — use a real sort. Write indices on a 7-element array and circle the last parent. Then write the downward loop.

More notes if you want them

If you treat a heap as 'I imported PriorityQueue,' you cannot answer 'why is build O(n)?' or implement heap sort. Interviewers want the array indexing, the sift-down loop, and the linear-time build. This is also the difference between n inserts (n log n) and heapify (n) when you already have all the elements.

Use when: You already have n elements and need a heap (heap sort, heap-based selection).

Skip when: You need a full sort in the array besides heap sort — use a real sort.

Trap: siftDown using the wrong child (min vs max heap mix-up).
