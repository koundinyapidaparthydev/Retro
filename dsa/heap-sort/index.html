Heap Sort

CORE

The problem they give you

They will not say “Heap Sort.” They describe this:

Given: An array you must sort in place. You get only a handful of extra variables, and the time must stay n log n even on a sorted or reversed input.

Find: The same numbers in non-decreasing order. After each extraction the next-largest value sits in the shrinking suffix.

Tiny example: [3, 1, 4, 2] → [1, 2, 3, 4]. First extraction parks 4 at the end; then 3, then 2.

Name of the tool

Build a max-heap in linear time, then repeatedly extract the maximum into the shrinking suffix. Guaranteed n log n, in-place, not stable.

Approach

  1. Build: for i from floor(n/2)-1 down to 0, sink(i, n).
  2. For end from n-1 down to 1: swap A[0] and A[end]; sink(0, end).
  3. sink(i, size): while a child exists, pick the larger child; if it is bigger than A[i], swap and continue from that child; else stop.

Run it in JavaScript

Left is the snippet. Right is the console — one console.log at a time.

max-heap, then swap root to the end

const a = [3, 9, 2, 1, 4];
function down(i, n) {
  for (;;) {
    let l = i * 2 + 1, r = l + 1, m = i;
    if (l < n && a[l] > a[m]) m = l;
    if (r < n && a[r] > a[m]) m = r;
    if (m === i) break;
    [a[i], a[m]] = [a[m], a[i]];
    i = m;
  }
}
for (let i = (a.length >> 1) - 1; i >= 0; i--) down(i, a.length);
console.log("heap", a.slice());
for (let n = a.length - 1; n > 0; n--) {
  [a[0], a[n]] = [a[n], a[0]];
  down(0, n);
  console.log("pop", a[n], a.slice(0, n));
}

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Sort in place with a hard n log n cap — no quadratic cliff.
  • You already have the parent-beats-children layout. How do you emit the sorted array?
  • Why is building that layout linear, not n inserts?

You say this first

Build a max-heap in linear time, then repeatedly extract the maximum into the shrinking suffix. Guaranteed n log n, in-place, not stable. I'd dry-run a tiny case first, then say the invariant and the complexity (O(n log n) worst case; O(n) to build the heap time, O(1) space).

Offer the next notch: For end from n-1 down to 1: swap A[0] and A[end]; sink(0, end).. Tradeoff: Hard n log n and in-place versus poor cache behavior and no stability. Write iterative sink. Recursive sink is fine if you mention O(1) extra is for the iterative version.

More notes if you want them

Heap sort is the answer to 'in-place sort with a hard O(n log n) bound.' It is how you show you understand heaps beyond 'I used a PriorityQueue.' Interviews will ask you to heapify an array in place, explain why build-heap is O(n) not O(n log n), and then extract n times. It is also the fallback inside introsort when quicksort goes too deep.

Use when: In-place guaranteed O(n log n) with no worst-case cliff.

Skip when: You need stability.

Trap: Building the heap by n inserts (O(n log n)) and calling it linear.
