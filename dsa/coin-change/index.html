Coin Change

CORE
AmazonoftenGoogleoftenUnbounded knapsack in disguise.

Definition

Minimum coins (or number of combinations) to make amount. Unbounded knapsack with a careful base and an impossible sentinel.

Why it exists

Coin Change is the unbounded-knapsack interview in cash form.

Approach

  1. const INF = amount+1; dp = Array(amount+1).fill(INF); dp[0]=0;
  2. for a in 1..amount: for c of coins: if c<=a dp[a]=min(dp[a], dp[a-c]+1);
  3. return dp[amount] >= INF ?
Time O(n · amount)Space O(amount)

Run it in JavaScript

Left is the snippet. Right is the console — one console.log at a time.

fewest coins for the amount

const coins = [1, 2, 5], amount = 6;
const INF = 99;
const dp = Array(amount + 1).fill(INF);
dp[0] = 0;

for (const coin of coins) {
  for (let a = coin; a <= amount; a++) {
    dp[a] = Math.min(dp[a], dp[a - coin] + 1);
  }
  console.log("after", coin, dp.slice(0, 7));
}
console.log("coins for 6", dp[6]);

You say this first

Minimum coins (or number of combinations) to make amount. Unbounded knapsack with a careful base and an impossible sentinel. I'd dry-run a tiny case first, then say the invariant and the complexity (O(n · amount) time, O(amount) space).

Offer the next notch: for a in 1..amount: for c of coins: if c<=a dp[a]=min(dp[a], dp[a-c]+1);. Tradeoff: Each coin object can be used once (limited inventory) — 0/1 or bounded. Give the {1,3,4} vs 6 greedy fail, then write DP.

More notes if you want them

Coin Change is the unbounded-knapsack interview in cash form. People greedy-take the largest denomination and fail on {1,3,4} amount 6. You must DP. The sister problem (number of ways) swaps min for + and changes loop order. Both are must-haves.

Use when: Make an amount with unlimited denominations: min count or number of ways.

Skip when: Each coin object can be used once (limited inventory) — 0/1 or bounded.

Trap: Initializing dp to 0 so impossible amounts look like 0 coins.
