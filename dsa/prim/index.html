Prim's MST

NEXT

Definition

Grow a tree from a start node, always adding the cheapest edge that leaves the tree. A min-heap of candidate edges (or nodes) implements the pick.

Why it exists

Prim is Dijkstra's cousin: same heap loop, different meaning (edge weight, not path sum).

Approach

  1. inTree = empty, heap = [(0, start)], ans = 0.
  2. While heap and tree incomplete: pop (w,u).
  3. If you never absorbed V nodes, the graph was disconnected.
Time O(E log V) heap; O(V²) arraySpace O(V + E)

Run it in JavaScript

Left is the snippet. Right is the console — one console.log at a time.

grow the cut from A

const g = {
  A: [["B", 1], ["C", 4]],
  B: [["A", 1], ["C", 2], ["D", 5]],
  C: [["A", 4], ["B", 2], ["D", 1]],
  D: [["B", 5], ["C", 1]],
};
const inMST = new Set(["A"]);

while (inMST.size < 4) {
  let best = null;
  for (const u of inMST) {
    for (const [v, w] of g[u]) {
      if (inMST.has(v)) continue;
      if (!best || w < best[2]) best = [u, v, w];
    }
  }
  const [u, v, w] = best;
  inMST.add(v);
  console.log("grow", u, "→", v, w);
}

You say this first

Grow a tree from a start node, always adding the cheapest edge that leaves the tree. A min-heap of candidate edges (or nodes) implements the pick. I'd dry-run a tiny case first, then say the invariant and the complexity (O(E log V) heap; O(V²) array time, O(V + E) space).

Offer the next notch: While heap and tree incomplete: pop (w,u). if u in tree continue. add u, ans += w. for each (v,wuv): if v not in tree, push (wuv, v).. Tradeoff: You already have a sorted edge list and a UF handy — Kruskal is less code. Say 'like Dijkstra but the key is the edge into the tree, not a path sum.'

More notes if you want them

Prim is Dijkstra's cousin: same heap loop, different meaning (edge weight, not path sum). It is nicer than Kruskal on dense adjacency matrices (O(V²) without a heap). Interviews accept either MST algorithm; you should know one well and the other by name and difference (edge-sort vs grow-tree).

Use when: MST from an adjacency list or matrix, especially dense graphs (array Prim).

Skip when: You already have a sorted edge list and a UF handy — Kruskal is less code.

Trap: Using path-sum keys (writing Dijkstra by accident).
