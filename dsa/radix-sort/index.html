The problem they give you

They will not say “Radix Sort.” They describe this:

Given: n integers, each up to 32 bits — or equal-length digit strings.

Find: The numbers in increasing order. Digit width is small, so you should beat a comparison sort.

Tiny example: [170, 45, 75, 90] → [45, 75, 90, 170].

Name of the tool

Stable-sort integers (or fixed-length strings) digit by digit. LSD walks least-significant digit first; MSD walks from the high digit and buckets recursively.

Why this tool

Radix sort is how you sort 32-bit integers in linear time in n and the number of digits, and how interviewers check that you understand why the digit…

Approach

  1. Choose a base b (256 for bytes is standard).
  2. For d = 0 to w-1 (LSD): extract digit = floor(key / b^d) % b.
  3. Stable counting-sort the current array by that digit into a buffer, then swap buffers.

Run it in JavaScript

Left is the snippet. Right is the console — one console.log at a time.

LSD: counting-sort each digit, 1s then 10s

let a = [170, 45, 75, 90, 2];
for (let exp = 1; exp <= 100; exp *= 10) {
  const buckets = Array.from({ length: 10 }, () => []);
  for (const x of a) buckets[Math.floor(x / exp) % 10].push(x);
  a = buckets.flat();
  console.log("exp", exp, a);
}

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Sort these 32-bit IDs faster than n log n comparisons.
  • Each digit pass must keep earlier digit order. What happens if a pass is unstable?
  • The integers are signed. Where do the negatives go?

You say this first

Stable-sort integers (or fixed-length strings) digit by digit. LSD walks least-significant digit first; MSD walks from the high digit and buckets recursively. I'd dry-run a tiny case first, then say the invariant and the complexity (O(w(n + b)) time, O(n + b) space).

Offer the next notch: For d = 0 to w-1 (LSD): extract digit = floor(key / b^d) % b.. Tradeoff: Linear in n for short keys versus extra memory and a digit-width factor. Say 'stable counting sort per digit, LSD first' in one sentence, then write counting sort as a helper.

More notes if you want them

Radix sort is how you sort 32-bit integers in linear time in n and the number of digits, and how interviewers check that you understand why the digit sort must be stable. It shows up when someone says 'can you sort faster than n log n?' and the keys are integers or strings. You should know LSD vs MSD and why LSD is the one you implement first.

Use when: Fixed-width integer keys, IPv4 addresses, credit-card-like numeric IDs.

Skip when: Already-comparable objects with no cheap digit view.

Trap: Unstable digit sort — the whole algorithm is wrong, not just ties.
