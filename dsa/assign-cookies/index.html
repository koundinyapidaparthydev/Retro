Assign Cookies

CORE

Definition

Sort children by greed and cookies by size. Walk two pointers: give the smallest cookie that satisfies the next child. That maximizes the number of content children.

Why it exists

This is the easy greedy pairing interview and the warmup for more serious assignment problems.

Approach

  1. Sort both arrays.
  2. Return i.
Time O(n log n)Space O(1) besides sort

Run it in JavaScript

Left is the snippet. Right is the console — one console.log at a time.

smallest cookie that satisfies the greediest leftover kid

const kids = [1, 2, 3], cookies = [1, 1];
kids.sort((a, b) => a - b);
cookies.sort((a, b) => a - b);
let i = 0, fed = 0;

for (const cookie of cookies) {
  if (i < kids.length && cookie >= kids[i]) {
    console.log("give", cookie, "to kid", kids[i]);
    i++;
    fed++;
  } else {
    console.log("cookie", cookie, "too small or leftover");
  }
}
console.log("fed", fed);

You say this first

Sort children by greed and cookies by size. Walk two pointers: give the smallest cookie that satisfies the next child. That maximizes the number of content children. I'd dry-run a tiny case first, then say the invariant and the complexity (O(n log n) time, O(1) besides sort space).

Offer the next notch: Return i.. Tradeoff: Maximize sum of values — may need a heap or DP. After this they may go to 'assign cookies with k types' or to meeting rooms. Stay calm; the sort+pointer is enough here.

More notes if you want them

This is the easy greedy pairing interview and the warmup for more serious assignment problems. The proof is exchange: wasting a large cookie on a low-greed child cannot help more children than using the smallest adequate cookie. If you assign largest-to-largest you also get an optimal count here, but the two-pointer smallest-fit is the usual write-up.

Use when: 1–1 assignment maximizing count under a 'resource ≥ demand' rule.

Skip when: Maximize sum of values — may need a heap or DP.

Trap: Matching without sorting.
