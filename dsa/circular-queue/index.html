The problem they give you

They will not say “Circular Queue.” They describe this:

Given: A fixed-length buffer of capacity k. Producers enqueue, consumers dequeue. You may not shift the whole array.

Find: Support enqueue, dequeue, front, rear, isEmpty, isFull — all O(1).

Tiny example: cap 3: enq 1, enq 2, enq 3, deq → 1, enq 4. Buffer holds 2, 3, 4. The next enqueue fails (full).

Name of the tool

A fixed array with head and tail indices modulo capacity. Enqueue/dequeue O(1) without shifting, used in buffers and BFS pools.

Why this tool

Design Circular Queue is a common LLD-flavored coding question.

Approach

  1. Pick capacity, allocate the array, head = tail = 0, size = 0.
  2. enQueue(x): if size == cap return false; A[tail] = x; tail = (tail+1)%cap; size++.
  3. deQueue(): if size == 0 return false; head = (head+1)%cap; size--.

Run it in JavaScript

Left is the snippet. Right is the console — one console.log at a time.

head/tail modulo cap, size tells full vs empty

const cap = 3, buf = Array(cap);
let head = 0, tail = 0, size = 0;
function enq(x) {
  if (size === cap) return console.log("full");
  buf[tail] = x;
  tail = (tail + 1) % cap;
  size++;
  console.log("enq", x, "buf", buf.slice(), { head, tail, size });
}
function deq() {
  const x = buf[head];
  head = (head + 1) % cap;
  size--;
  console.log("deq", x, { head, tail, size });
}
enq(1); enq(2); enq(3); deq(); enq(4);

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Design a ring buffer with a fixed array.
  • When head equals tail, is it empty or full? State the invariant.
  • Same structure, but insert and delete at both ends.

You say this first

A fixed array with head and tail indices modulo capacity. Enqueue/dequeue O(1) without shifting, used in buffers and BFS pools. I'd dry-run a tiny case first, then say the invariant and the complexity (O(1) all operations time, O(capacity) space).

Offer the next notch: enQueue(x): if size == cap return false; A[tail] = x; tail = (tail+1)%cap; size++.. Tradeoff: Unbounded growth — use a linked list or a growable deque. State the empty/full invariant in a comment before you write modulo code.

More notes if you want them

Design Circular Queue is a common LLD-flavored coding question. It tests modulo arithmetic, the full vs empty ambiguity (when head == tail), and whether you waste one slot or keep a size counter. Ring buffers in producers/consumers are this structure.

Use when: Fixed-size buffers, IO rings, bounded BFS (rarely), producer-consumer queues.

Skip when: Unbounded growth — use a linked list or a growable deque.

Trap: Using % without adding cap on decrement — negative modulo in some languages.
