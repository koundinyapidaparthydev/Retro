Divide and Conquer

CORE

The problem they give you

They will not say “Divide and Conquer.” They describe this:

Given: A problem that splits into two independent halves whose answers stitch cheaply.

Find: Solve the halves, combine. Quote the time from the split and the stitch, not from a guess.

Tiny example: Count out-of-order pairs in [3,1,4,2]. Left [3,1] has 1, right [4,2] has 1, merge adds 3>2 and 1 stays. Total 3.

Approach

split the array, merge the halves

function mergeSort(a) {
  if (a.length <= 1) return a;
  const mid = Math.floor(a.length / 2);
  console.log("split", a, "→", a.slice(0, mid), a.slice(mid));
  const L = mergeSort(a.slice(0, mid));
  const R = mergeSort(a.slice(mid));
  const out = [];
  let i = 0, j = 0;
  while (i < L.length && j < R.length) {
    out.push(L[i] <= R[j] ? L[i++] : R[j++]);
  }
  const merged = out.concat(L.slice(i), R.slice(j));
  console.log("merge", L, R, "→", merged);
  return merged;
}

Whiteboard prompts

You say this first

Split the instance, solve parts independently, combine. The Master Theorem turns T(n) = a T(n/b) + f(n) into the closed form you quote in interviews. I'd dry-run a tiny case first, then say the invariant and the complexity (Given by the recurrence; often Θ(n log n) or Θ(n^{log_b a}) time, O(depth) stack plus whatever combine allocates space).

Offer the next notch: Split into independent subinstances (halves, quadrants, first/second half of a list).. Tradeoff: Subproblems overlap — use DP / memo, or you recompute an exponential tree. For 'count inversions' or 'reverse pairs,' say merge sort and count during combine.

More notes if you want them

Divide and conquer is the strategy behind merge sort, binary search, quicksort, closest pair, and many 'solve on halves then merge' problems (count inversions, majority, skyline). Interviewers want you to name the split, the combine cost, and the resulting complexity — not just recurse and hope. It is different from DP: subproblems do not overlap, so you do not memoize, you combine.

Use when: The problem splits into independent similar pieces whose answers combine cheaply.

Skip when: Subproblems overlap — use DP / memo, or you recompute an exponential tree.

Trap: Unbalanced splits that make T(n) = T(n-1) + n = O(n²) (bad quicksort, bad list mid).
