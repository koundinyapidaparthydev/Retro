Binary Search on the Answer

NEXT

The problem they give you

They will not say “Binary Search on the Answer.” They describe this:

Given: You need the smallest (or largest) number k that makes a check succeed. If k works, every larger k also works — or the reverse.

Find: That boundary k. You may not try every possible k; the range can be up to a billion.

Tiny example: Piles [3, 6, 7, 11], 8 hours. Slowest eat speed that still finishes: 4. Speed 3 is too slow; 4 is just enough.

Name of the tool

Binary search the value of the answer itself when feasibility is monotonic: if k works, k+1 also works (or the reverse).

Why this tool

This is the pattern that turns 'greedy simulation' problems into log × check solutions.

Approach

  1. Identify the quantity you would binary search — usually 'minimum max' or 'maximum min.'
  2. Prove: if a candidate k is feasible, every k' > k is feasible (or the opposite).
  3. Set lo to the smallest possible answer, hi to a known feasible (or infeasible) extreme.

Run it in JavaScript

Left is the snippet. Right is the console — one console.log at a time.

min eat speed for 8 hours

const piles = [3, 6, 7, 11];
const hours = 8;

function ok(speed) {
  let h = 0;
  for (const p of piles) h += Math.ceil(p / speed);
  return h <= hours;
}

let lo = 1, hi = 11, ans = 11;
while (lo <= hi) {
  const mid = Math.floor((lo + hi) / 2);
  const good = ok(mid);
  console.log("speed", mid, good ? "fits" : "too slow");
  if (good) { ans = mid; hi = mid - 1; }
  else lo = mid + 1;
}
console.log("min speed", ans);

Whiteboard prompts

These are problem statements. The algorithm name is your answer, not the title of the question.

  • Minimum eating speed to finish all piles in h hours.
  • Split the array into m pieces; minimize the largest piece sum.
  • Place cows in stalls so the closest pair is as far apart as possible.

You say this first

Binary search the value of the answer itself when feasibility is monotonic: if k works, k+1 also works (or the reverse). I'd dry-run a tiny case first, then say the invariant and the complexity (O(T log R) where T is the feasibility check and R is the numeric range time, O(1) plus whatever P uses space).

Offer the next notch: Prove: if a candidate k is feasible, every k' > k is feasible (or the opposite). If you cannot prove this, stop.. Tradeoff: Simple loop plus a simulation versus a custom greedy or DP that might be O(n) but harder to invent. Write P first and test it on a fixed k. Then wrap the binary search. Interviewers can follow that.

More notes if you want them

This is the pattern that turns 'greedy simulation' problems into log × check solutions. Koko eating bananas, split array largest sum, capacity to ship packages, minimize max distance to gas stations — they all share one shape. Interviewers love it because you must prove monotonicity, pick a numeric range, and write a correct feasibility predicate. Candidates who only know array binary search freeze when there is no array to index.

Use when: Minimize the maximum load, time, or distance subject to a count constraint.

Skip when: P is not monotonic — a medium k fails while a smaller k succeeds. Then this search is incorrect, not just slow.

Trap: Using lo + 1 < hi and then returning the wrong of lo/hi.
